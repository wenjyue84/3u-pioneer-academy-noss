1. Overview 
An organization puts their internal documentation controls in place to limit risks, such as 
losses, poor performance on contracts, poor quality and non -compliance with 
regulations.  
 
1.1 Documentation Procedures 
Documentation procedures detail the documents that the organization requires to 
implement their control systems and assign responsibility personnel for tasks and 
actions. Small businesses usually require less documentation s or controls because 
each employee carries out several job functions and responsibilities. 
 
Effective documentation procedures need less efficient controls to come out with 
businesses competitive advantages. To be effective in documentation procedures it has 
to cover the followings. 
i) Documentation procedures usually specify that an employee manual must 
contain all relevant policy and procedure documentations. 
ii) The detail ed manual must include  and state clearly the person who is 
responsible for writing and updating the policies and procedures. 
iii) How the organization communicates them to the employees. 
Documentation procedures typically specify that employees receive a copy of the 
manual when they start work, acknowledged the receipt and agree to adhere to the 
policies and procedures. They will also receive updates as changes are done from time 
to time.

2.1 Data Storage 
When data is stored in a storage device, it is stored as blocks of data. These blocks are 
accessed in their entirety, maki ng them the atomic disk access operation. Disk blocks 
are structured in much the same way as linked lists; both contain a section for data, a 
pointer to the location of the next node or block, and both need not be stored alongside. 
Due to the fact that a n umber of records can only be sorted on one field, we can state 
that searching on a field that isn’t sorted requires a Linear Search which 
requires N/2 block accesses (on average), where  N is the number of blocks that the 
table spans. If that field is a non -key field (i.e. doesn’t contain unique entries) then the 
entire table space must be searched at N block accesses. 
Whereas with a sorted field, a binary search may be used, this has  log2N block 
accesses. Also since the data is sorted given a non -key field,  the rest of the table 
doesn’t need to be searched for duplicate values, once a higher value is found. Thus 
the performance increase is substantial.

2.5 Hybrid System 
For hybrid system, the facility policies and procedures should determine which parts of 
the record will be paper based and the other parts are stored in a data repository.  This 
policy should also determine whether or not additional documents should be added as 
paper based documents or scanned into the data repository. If documents are added to 
the electronic portion of the record, these should be added as appendix. 
In data recording process there are a number of tagging manner is normally practiced, 
namely vital, important, useful, non-essential, etc. 
 2.6 Arrangement Scheme 
There is no one arrangement scheme that is best for all records. Here are some basic 
suggestions on the major ones. 
 i) Chronological 
 The file is a rranged by date. Most useful for small files and short life 
span records for easy deleting when no longer needed. 
 ii) Numeric 
 The file is a rranged by number  and is the simplest form . It is a serial 
arrangement beginning with the lowest number and proceeding .  M ore 
complex systems can be used for large series. Best for case files of one 
type or another, permits and for ms where numbers have already been 
assigned. 
 iii) Alphabetical Order 
 The file is a rranged in alphabetical order from A  to Z. This is the basic 
arrangement for most subject files.  Alphabetical subject files are difficult 
to manage unless they are very fo cused, and the filing and identification 
of folders is consistent.   Best use for small files or very consistent ones 
where the folder titles are easily determined, such as a file of all outgoing 
correspondence arranged by addressee.

3. Acquire And Sort Data 
 
Data acquisition will capture data from an actual system and store the information in a format 
that can be easily retriev ed. Another requirement is that  data should be able to capture 
information programmatically or automatically, without any human intervention or guidance. 
In general there are seven elements or functions that must be in place for a structure in a 
data acquisition.  If only a number of th ese elements are part of the system, then the module 
could be defined as components of data. 
The seven elements are; 
- Data collection 
- Measurement  
- Timing and triggering 
- Real time clock 
- System control 
- Data communication and 
- Data archives 
 
Data is transferred via logic signal or analog forms based on the system application.  Data 
hardware is usually interfaces between the signal and a computer. It could be in the form of 
modules that can be connected to computer ports. 
 
Data sorting is a process of arranging data into meaningful order so that you can analyze it 
more effectively. For example, if you want to submit sales data by calendar month so that 
you can produce a graph of sales performance. You may explore to sort data as follows: 
-      Sort text data into alphabetical order 
- Sort numeric data into numerical order 
- Group sorted data to other levels 
 By area or locality 
 By month within a year 
Sorting the data also makes job easier for analysis. For example, you might want to sort 
sales data from most profitable sales to least profitable sales to show the relative position of 
your company's best selling products. 
You may discoverer more flexibility when sorting data within data. You can do this to many 
different levels. For example, you can sort by cities within a region.

4. Periodically Review Document 
Document review is a process of identifying both grammatical and functional errors.   This 
process is important to enhance the quality of the documents and very well fits its needs. At 
times, documents are often been ignored or forgotten without being reviewed. 
The current challenges for document review are; 
- No accountability of the documents 
- Reviewed comments are not acceptable by the author 
- Managers are not comfortable with track changes 
- No proper document checklists available

4.1 Review Process 
There are ways and mean in reviewing a document. The followings are 
suggested points and checklist for reference 
 i) Examine the requirements and scope of the document 
 ii) Check the release date, version and copyright trademark 
 iii) Estimate required timing for completion 
 iv) Print the document and do markings to identify changes 
 v) Integrate changes from other reviewers 
 vi) Submit the reviewed document to the author 
 vii) Discuss on reviewed comments or edit if necessary 
 
4.2 Review Checklist 
The followings are steps to be taken for reviewing the work checklist 
- Style and Format 
- Body text 
- Bullets 
- Consistency in numbering 
- Avoid blank space 
- Update Field 
- Update the document 
- Check references 
- Grammatical Errors 
- Run spell check 
- Check logical flow of contents 
- Check clarity and readability 
- Keep tenses consistent 
- Avoid passive statement 
- Remove abbreviations (e.g., i.e., viz) 
- Check common misuse wording (Its, It’s, don’t, can’t) 
- Check for gender specifications 
- Check for numerical format (ONE to TEN shoul d be in words and 
the rest are in numeric values)

6 Update Document Accordingly 
Once you have indexed the content you need, you will want to start thinking about your 
strategy for dealing with changes to those documents. Among others there are two 
approaches in updating documents that have only partially changed. 
- Atomic Updates 
This approach allows changing only one or more fields of a document without 
having to re-index the entire document. 
- Optimistic Concurrency Or Optimistic Locking 
It is a feature  of many databases, and allows conditional updating a document 
based on its version. This approach includes semantics and rules for how to deal 
with version matches or mismatches. 
 
Atomic Updates and Optimistic Concurrency may be used as independent strate gies for 
managing changes to documents, or they may be combin ed; you can use optimistic 
concurrency to conditionally apply an atomic update.
