# BASELINE — PPT-PPA 考卷生产线

**建立：** 2026-08-23 · **适用：** Character Intl. Academy 全部 PPT-PPA 考卷

这份文件定义「完成」的标准、角色分工、以及每份产出必须通过的检查。
任何一轮生产都以此为准绳；不符合的产出不算完成。

## 2 · 「完成」的定义（Definition of Done）

一个 **NOSS Level** 算完成，当且仅当：

| # | 条件 | 依据 |
|---|---|---|
| 1 | SET A 四件套齐 | Jennifer 2026-08-23 定义 |
| 2 | SET B 四件套齐 | 同上 |
| 3 | 两套场景不同、难度对等、覆盖同一组 CU | JPK 惯例（A/B 卷 |
| 4 | 全部通过 AUDITOR 检查表（第 4 节） | 本 baseline |
| 5 | 已转 PDF、页数声明实测回填 | D1 教训 |
| 6 | 已上传对应 Drive 文件夹并重新列目录核实 | 交付纪律 |

**四件套 =** `SOALAN`（考卷）· `SKEMA`（评分标准）· `ASSESSMENT ANSWER SHEET`（答卷）·
`EQUIPMENT VERIFICATION`（设备核查表）

## 4 · AUDITOR 检查表

每份产出逐条过，任一项 FAIL 即打回重做。

### 4.1 内容真实性（最高优先级）

- [ ] **CU 名称逐字对得上 NOSS 正文** —— 不是「意思对」，是逐字。
      **不要以 TOC 为准。** TOC 是索引行，会把课程名与单元名混写。
      判据优先级：`COMPETENCY UNIT TITLE` 字段 > CoCU 正文标题 > CPC 图表 / TEM / 配分表 > TOC。
      多处冲突时按出现次数与字段语义裁定，并记录裁定理由。

      > *前科（两次都错在同一个地方）：*
      > *① 初版把 N821 C07 写作 `Staff Administration Supervision`；*
      > *② 2026-08-23 我依 TOC「更正」为 `Office Administration Supervision` 并交付客户 —— **改反了**。*
      > *实测：`Staff` 8 次（含 CU TITLE 字段、CoCU 正文、CPC、TEM、配分表），`Office` 1 次且仅在 TOC。*
      > *原文并列写明 `NOSS TITLE: Office Administration` / `COMPETENCY UNIT TITLE: Staff Administration Supervision`。*
      > *2026-08-24 已修正重传。**本条此前的表述本身就是错的**，由 Round 2 审计员发现并纠正。*
- [ ] **每道题都能追溯到某条 Work Activity 或 Related Knowledge** —— 指得出是哪一条
- [ ] **SKEMA 每个评分点对应 NOSS 的 Assessment Criteria**
- [ ] **零编造**：公司名、地址、电话、人名、证号、金额、日期——
      虚构场景中的可以是设定，但**不得伪装成真实机构**；
      未知的真实信息一律写 `⟪TBD: 需要什么 | 谁提供 | 何时要⟫`

### 4.2 结构完整性（继承自 SET A 审计的缺陷类）

- [ ] **D1** 封面页数声明 = 实测页数（**转 docx 后才能填，md 阶段留占位并标记**）
- [ ] **D2** 封面声明的每个 CU（含选修）在 SKEMA 中都有对应题目与分数
      —— *反例：SET A 声明 E01 但 SKEMA 中 `Inventory` 出现 0 次*
- [ ] **D3** SOALAN 与 SKEMA 两份封面的 CU 写法完全一致（含代码）
- [ ] **D4** 马来文拼写（已知：`Terlibat` 不是 `Terlibut`）
- [ ] 结尾有 `JUMLAH MARKAH KESELURUHAN` 与 PPL-PPT 签名栏
- [ ] SKEMA 封面有 SULIT 警示

### 4.3 配分自洽

- [ ] 各 Bahagian 权重加总 = 100%
- [ ] 每个换算式 `(Markah ÷ 满分) × 权重` 的满分与实际题目数×每题满分一致
- [ ] 达成率百分比逐条验算

### 4.4 R1 —— 实作覆盖（悬而未决，须标注）

- [ ] 记录每个 CU 是「实作评估」还是「仅口试」
- [ ] **若有 CU 仅靠口试，在产出中显式标注**，不得静默沿用

> ⚠️ **R1 现状：** Jennifer 已通过的 FB-018-3 SET A 中，C02/C03/C06 仅口试。
> 是否满足 JPK 对 *Penilaian Amali* 的要求**未经确认**。
> **本 baseline 的立场：新产出默认为每个 CU 安排实作任务**；
> 确实无法实作的，标注理由，交 PPL 裁定。不默认沿用旧结构。

### 4.6 可完成性与 A/B 卷对等（2026-08-24 新增）

> **加入原因：** Round 2 产出的 N821 SET B 通过了全部既有检查（零编造、配分自洽、
> 附件一致），却是 **66 页 / 35 份表格**，而 SET A 是 **20 页 / 14 份表格**，
> 两者同为 3 小时。审计员没抓到，因为检查表只查内部一致性，**没有一条查「人做得完吗」**。
> 一份考生做不完的卷子，内部再自洽也是废卷。

- [ ] **考生能在规定时限内完成** —— 按每份表格的实际填写量估时，总和 ≤ 时限 × 0.85
- [ ] **与同 Level 既有 SET 的规模对等** —— 表格数、页数、任务数不得超出 ±25%
      *（A/B 卷是等价替换关系，不是难度递进）*
- [ ] **SKEMA 篇幅与 SOALAN 相称** —— 评分标准比考卷厚几倍，说明评分点碎到无法实操
- [ ] 若确实需要超出规模，必须**书面说明理由**并同步调整时限，不得沉默放大

### 4.5 格式

- [ ] 抬头三段：JPK/KSM 地址 → Pusat Bertauliah 名称 → 文件标题
- [ ] 编号格式 `[NOSS]/[年]/[SET]/[序]`
- [ ] 候选人信息栏、Arahan、Fasilitator 签名栏齐备
- [ ] 语言：指令用 BM，内容/任务可 EN（沿用 Jennifer 已批准样本的双语惯例）

## 5 · 每轮产出报告格式

每轮结束必须回答：

1. **本轮完成了哪几份**（文件名 + 路径，不是「做了一些」）
2. **AUDITOR 打回了什么**（打回是正常的，藏起来才不正常）
3. **发现的新问题**（NOSS 与假设不符、源材料缺失等）
4. **剩余缺口**（数字，对照第 3 节基线）
5. **站点已更新**（academy.wenjyue.com）

---

## 6 · 不可越过的红线

- **NOSS 没写的，不准写进考卷。** 宁可少一道题，不可编一道题。
- **AUDITOR 说 FAIL 就是 FAIL。** 不得因赶工跳过。
- **上传前必须重新列 Drive 目录核实。** 接口返回 200 不等于文件在那里。
- **页数声明未回填的，不算完成。**
- **不得替 Jennifer 决定她该决定的事**（E01 取舍、A/B 卷数量、提交范围）。
