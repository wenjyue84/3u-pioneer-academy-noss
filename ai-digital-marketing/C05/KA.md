b) LCP and CLS remediation (8 marks):

LCP = 4.8s (Poor) (2m): Means the largest visible element (typically hero image or banner) takes 4.8 seconds to render — significantly above the 2.5s threshold, causing high bounce rate. Likely causes (2m): oversized uncompressed hero image (1m); slow shared hosting server response time / no CDN (1m). Remediation (1m): compress hero image to WebP format under 200KB and serve via a CDN (e.g. Cloudflare free tier).

CLS = 0.28 (Poor) (1m): Means page elements shift unexpectedly during load — above the 0.1 threshold, degrading user experience. Likely causes (2m): images loaded without defined width/height attributes causing layout reflow (1m); web fonts loading late and shifting text blocks (1m). Remediation (1m): add explicit width and height to all img tags; preload critical web fonts using `<link rel="preload">`.

**Q21.** [SENARIO / SCENARIO] A client's Google PageSpeed Insights report shows LCP = 5.2 seconds. Identify TWO (2) likely causes and describe ONE (1) specific action to bring LCP to "Good" (under 2.5s). [CoCU C05.1.3]

*Jawapan Contoh / Sample Answer:* Two likely causes: (1) The hero banner image is a large uncompressed JPEG file (e.g. 3MB+), which forces the browser to download and decode a massive file before painting the largest element. (2) The website is on slow shared hosting with no Content Delivery Network (CDN), so all assets are served from a single geographically distant server. One corrective action: convert the hero image to WebP format and compress it to under 150KB using Squoosh or TinyPNG, then serve it via Cloudflare's free CDN tier to reduce latency for Malaysian visitors across all regions.

**Q22.** [SENARIO / SCENARIO] A Kuala Lumpur bakery's Google Maps listing shows the wrong address (an old shop location). Customers are going to the wrong place. Describe the complete process to correct this and prevent it recurring. [CoCU C05.3.2]

*Jawapan Contoh / Sample Answer:* Log into Google Business Profile Manager at business.google.com using the verified owner account. Navigate to "Edit Profile" and update the address to the current premises. Save changes — Google may trigger a re-verification via postcard or phone for significant address changes; complete verification immediately. Simultaneously update the address on Facebook Business Page, website contact page, and all online directories to maintain NAP consistency. Create a master NAP reference document with the exact formatted address and share it with all staff and the digital marketing team. Set a monthly reminder to audit NAP across platforms. Going forward, any premise or phone number change must be updated across ALL platforms on the same day to prevent ranking drop.

**Q23.** [SENARIO / SCENARIO] A client wants to add multilingual support (EN, BM, ZH) to their existing Framer AI website. What are the key steps and considerations? [CoCU C05.2.2]

*Jawapan Contoh / Sample Answer:* First, plan content: prepare all page copy in all three languages before building — AI translation tools (ChatGPT, DeepL) can draft initial translations, but a native speaker should review BM and ZH for tone and accuracy. In Framer AI, use the built-in localisation/language switcher feature to create language variants of each page. Implement hreflang tags to tell Google which language version to serve to which audience — this prevents duplicate content penalties and improves multilingual SEO. Ensure the ZH version uses Simplified Chinese characters for Peninsular Malaysia's predominantly Mandarin-speaking Chinese community. Test all language switcher links on mobile devices before publishing. For GBP, set the primary language to Bahasa Malaysia (default for Malaysian listings) and add the English and Chinese descriptions in the "Business description" and supplementary fields.

**Q24.** [SENARIO / SCENARIO] A client asks whether they should focus on their website or their Google Business Profile first. They have limited time and budget. Advise them with a clear rationale. [CoCU C05.3.1]

*Jawapan Contoh / Sample Answer:* Recommend Google Business Profile (GBP) first. For most Malaysian SMEs with a physical location, GBP is the single highest-ROI digital asset — it appears in Google Maps and "near me" searches immediately after verification, at zero cost. A fully optimised GBP with correct NAP, photos, categories, and active reviews can drive significant walk-in and call traffic within weeks. In contrast, a new website typically takes 3–6 months of SEO effort before appearing in organic search results. The practical sequence: (1) Claim and fully optimise GBP this week. (2) Build a simple, mobile-optimised landing page or AI-generated website within the first month. (3) Link the GBP to the website once it is live. This maximises early digital visibility with minimal investment.

**Q25.** [SENARIO / SCENARIO] During a digital presence audit, you discover a client's business is listed on Foursquare and Hotfrog with a phone number from 5 years ago that has since been discontinued. Describe the steps to resolve this. [CoCU C05.2.1]

### Bahagian C / Section C — Soalan Senario Lanjutan / Extended Scenario Questions (0 markah / marks)

*Soalan senario lanjutan untuk penilaian kefahaman mendalam tahap 3. Jawapan contoh menunjukkan kedalaman teknikal yang diperlukan. / Extended scenario questions for in-depth Level 3 competency assessment. Sample answers demonstrate required technical depth.*

**Q26.** [SENARIO / SCENARIO] Explain the difference between shared hosting and cloud hosting for a Malaysian SME website. In which scenarios would each be appropriate? [CoCU C05.1.1]

*Jawapan Contoh / Sample Answer:* Shared hosting places multiple websites on a single physical server sharing all resources (CPU, RAM, bandwidth). It is low-cost (RM5–30/month in Malaysia from providers like Exabytes or Shinjiru) and adequate for simple brochure websites with low traffic — ideal for a new sole proprietor or startup with under 500 monthly visitors and no e-commerce transactions. The primary risks are shared performance degradation during traffic spikes from other tenants, and limited scalability. Cloud hosting (e.g. AWS, Google Cloud, DigitalOcean, or Cloudflare Pages) distributes resources across multiple servers, scales on demand, and typically includes CDN by default — resulting in consistently lower latency for Malaysian visitors regardless of origin server location. It is appropriate once a business website handles e-commerce transactions, receives >1,000 daily visitors, or requires guaranteed uptime for revenue-critical operations. For the Core Web Vitals metric LCP, cloud hosting with CDN can improve Time to First Byte (TTFB) by 200–500ms compared to shared hosting, meaningfully improving page performance scores.

**Q27.** [SENARIO / SCENARIO] Explain how PDPA 2010 applies to a Malaysian business website that collects visitor email addresses via a contact form or newsletter subscription. What specific compliance elements must be present? [CoCU C05.1.2]

*Jawapan Contoh / Sample Answer:* PDPA 2010 (Personal Data Protection Act) governs how Malaysian businesses collect, process, and store personal data. For a website collecting email addresses via a contact form or subscription: (1) Privacy Notice — a clearly accessible Privacy Policy page must explain what data is collected, why, how it is stored, how long it is retained, and how users can request deletion or correction. (2) Consent — the form must include an explicit opt-in checkbox (not pre-ticked) where the user consents to data processing for the stated purpose. A pre-ticked box does not constitute valid consent under PDPA. (3) Purpose limitation — data collected for newsletter subscription cannot be used for a different purpose (e.g. sold to a third party) without separate consent. (4) Data security — the website must implement HTTPS (SSL certificate) to encrypt data in transit. Form submissions should be stored securely, not in plain-text emails if they contain sensitive information. (5) Data subject rights — users must have a way to unsubscribe, request access to their data, or request deletion. An unsubscribe link in every marketing email satisfies the marketing opt-out requirement. Non-compliance risks: fines up to RM500,000 and/or 3 years imprisonment under PDPA 2010 Section 130.

**Q28.** [SENARIO / SCENARIO] A client's landing page has a 78% bounce rate. Describe FIVE (5) possible causes and the corresponding CRO improvements. [CoCU C05.1.1]

*Jawapan Contoh / Sample Answer:* (1) Slow page load (LCP >4s) — visitors leave before the page finishes loading. Fix: compress images, enable CDN, minimise render-blocking scripts. (2) Message mismatch — the ad promised "50% discount" but the landing page shows no discount. Fix: ensure ad copy and landing page headline are aligned in message and offer. (3) Unclear or hidden CTA — the call-to-action button is below the fold, low-contrast, or uses vague text like "Submit." Fix: place a high-contrast CTA button above the fold with specific action text ("Book Free Consultation" / "Get My Discount"). (4) No social proof — no reviews, testimonials, or logos to build trust for a first-time visitor. Fix: add 3–5 authentic customer testimonials with photos or brand logos near the CTA. (5) Not mobile-optimised — 80%+ of Malaysian web traffic is mobile; a desktop-only layout causes immediate abandonment. Fix: use a mobile-first layout with tap-friendly CTA buttons of at least 44×44px, readable fonts (≥16px), and stacked (not side-by-side) content blocks.

**Q29.** [SENARIO / SCENARIO] Explain the concept of "domain authority" and why a newly registered `.my` domain may initially rank poorly on Google even with excellent content. [CoCU C05.1.1]

*Jawapan Contoh / Sample Answer:* Domain authority (DA) is a third-party metric (developed by Moz, also reflected in Ahrefs' Domain Rating) that predicts how likely a domain is to rank in search results, based primarily on the quantity and quality of external websites linking to it (backlinks). Google itself does not use the DA metric directly, but the underlying signals it reflects — inbound link quality, domain age, and historical authority — are genuine Google ranking factors. A newly registered `.my` domain has zero backlink history and no Google trust signals, so even high-quality content may not appear on Google's first page for 3–6 months (sometimes called the "Google Sandbox" effect). To accelerate authority building for a new Malaysian domain: (1) Submit the domain to Google Search Console and request indexing. (2) Create and submit an XML sitemap. (3) Earn mentions and links from local Malaysian business directories (e.g. Hotfrog MY, Foursquare, CTOS business listings). (4) Get featured in local Malaysian media or blogs. (5) Cross-link from the business's established social media profiles. These signals collectively shorten the time before Google starts ranking the new domain's pages.

**Q30.** [SENARIO / SCENARIO] Describe how AI scheduling tools integrate with a Google Business Profile posting strategy for a Malaysian retail business. [CoCU C05.2.2]

(2) Schedule posts to auto-publish at optimal times (Buffer AI recommends peak engagement windows). (3) Maintain a 2×/week posting cadence without requiring daily manual login. (4) Repurpose social media content — the scheduler can adapt an Instagram caption for GBP format automatically. For Malaysian retail: plan posts around local calendar events (Hari Raya, CNY, Deepavali, school holidays, Merdeka) using AI to generate festive-appropriate captions in EN/BM/ZH. The combined effect of regular GBP posts, consistent NAP, and active review responses significantly improves the "prominence" local ranking factor over 60–90 days.

**Q31.** [SENARIO / SCENARIO] Explain what hreflang tags are and how they should be implemented for a Malaysian trilingual website (EN, BM, ZH-Hans). [CoCU C05.2.2]

*Jawapan Contoh / Sample Answer:* Hreflang tags are HTML meta tags that tell Google which language and regional version of a page to serve to users based on their browser language settings and geographic location. Without hreflang, Google may serve the wrong language version to a visitor or treat the three language pages as duplicate content, penalising all three in search rankings. Correct implementation for a Malaysian trilingual site: In the `<head>` section of EACH language page, include three hreflang link tags pointing to all three versions: `<link rel="alternate" hreflang="en-my" href="https://example.com.my/en/" />` for English (Malaysia), `<link rel="alternate" hreflang="ms-my" href="https://example.com.my/bm/" />` for Bahasa Malaysia, and `<link rel="alternate" hreflang="zh-Hans-my" href="https://example.com.my/zh/" />` for Simplified Chinese (Malaysia). Also include a default fallback: `<link rel="alternate" hreflang="x-default" href="https://example.com.my/" />`. All three pages must link to each other — a one-directional hreflang is invalid. Verify implementation using Google Search Console's "International Targeting" report or the hreflang checker at hreflang.ninja.

**Q33.** [SENARIO / SCENARIO] Explain the difference between organic local search results and the Google Map Pack ("Local 3-Pack"). How can a Malaysian SME appear in both? [CoCU C05.3.1]

*Jawapan Contoh / Sample Answer:* The Google Map Pack (Local 3-Pack) is the set of three business listings with a map that appears at the top of Google results for local search queries (e.g. "kedai makan near me," "plumber Subang Jaya"). **Q35.** [SENARIO / SCENARIO] Explain how Core Web Vitals scores are measured differently in "Lab Data" vs "Field Data" — and which is more important for Google ranking. [CoCU C05.1.3]

*Jawapan Contoh / Sample Answer:* Lab Data is collected in a controlled, simulated environment — Google PageSpeed Insights and Lighthouse run a headless browser with a predefined network speed (Slow 4G) and device spec (mid-range Android) to measure CWV scores. Lab data is consistent and reproducible, making it useful for diagnosing specific performance issues and tracking improvements after optimisations. However, it does not reflect real user conditions — actual Malaysian users may be on 5G, fibre, or slow 3G; on a RM3,000 flagship phone or a RM600 budget device. Field Data (also called Real User Monitoring / RUM) is collected from actual Chrome browser users visiting the page and reported to the Chrome User Experience Report (CrUX dataset). Google uses field data — not lab data — as a Google ranking signal through the Page Experience update. A page can score "Good" in lab conditions but "Poor" in field data if real users experience slow connections or old devices. Conversely, a page with "Poor" lab data might have "Good" field data if the actual user base is primarily on fast fibre connections. For ranking purposes: Field Data (CrUX) is what Google measures. For debugging and optimisation: Lab Data is the actionable tool. Best practice: check both in Google Search Console (Field) and PageSpeed Insights (Lab) to get a complete picture.
