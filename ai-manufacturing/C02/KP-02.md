## 1. Senibina Sistem AI PdM

Sebelum mempelajari platform-platform khusus, penting untuk memahami senibina (architecture) umum sistem AI PdM. Pemahaman ini membolehkan pelatih menilai dan memilih platform yang paling sesuai untuk senario kilang tertentu.

### 1.1 Lapisan Komponen Sistem AI PdM

Sistem AI PdM yang lengkap terdiri daripada empat lapisan (layers):

**Lapisan 1 — Pengumpulan Data (Data Collection Layer)**
- Sensor (vibration, thermal, pressure, current, acoustic) → mengumpul data raw
- Gateway IoT (IoT Gateway) → mengagregat data dari pelbagai sensor
- Edge device → boleh melakukan pra-pemprosesan data sebelum dihantar ke cloud

**Lapisan 2 — Pengangkutan Data (Data Transport Layer)**
- Protokol IoT: MQTT (Message Queuing Telemetry Transport), OPC-UA, Modbus TCP/IP
- Sambungan: Wi-Fi industri, LAN industri, 4G/5G (untuk lokasi terpencil), atau LoRaWAN (untuk sensor battery-powered jarak jauh)
- Data security: TLS/SSL encryption untuk transmisi data

**Lapisan 3 — Pemprosesan dan Analisis AI (AI Processing Layer)**
- Cloud atau Edge AI platform memproses data yang masuk
- Pra-pemprosesan: pembersihan data, normalisasi, interpolasi nilai hilang
- Model ML: deteksi anomali, ramalan kegagalan, pengkelasan keadaan
- Dashboard dan visualisasi: real-time equipment health status

**Lapisan 4 — Tindak Balas dan Integrasi (Action & Integration Layer)**
- Sistem amaran (alert system): email, SMS, WhatsApp Business, notifikasi aplikasi
- Integrasi dengan Computerised Maintenance Management System (CMMS)
- Penjanaan work order automatik apabila amaran tahap kritikal dicapai
- Laporan penyelenggaraan dan rekod historis

### 1.2 Diagram Aliran Data Ringkas

```
[Sensor Kilang] → [IoT Gateway/Edge] → [Platform AI Cloud]
                                              ↓
                              [Model Analisis Siri Masa / Anomaly Detection]
                                              ↓
                              [Dashboard + Alert System + CMMS Integration]
                                              ↓
                              [Pasukan Penyelenggaraan → Tindakan Terancang]
```

## 2. Platform AI Penyelenggaraan Ramalan

### 2.1 IBM Maximo AI

**IBM Maximo** adalah platform Enterprise Asset Management (EAM) yang paling matang di pasaran, kini dengan modul AI terintegrasi dikenali sebagai **IBM Maximo Application Suite (MAS)** dengan komponen **Maximo Monitor** dan **Maximo Health & Predict**.

**Ciri-ciri utama:**

| Ciri | Penerangan |
|---|---|
| **Maximo Monitor** | Pemantauan kondisi peralatan secara real-time; dashboard yang boleh dikonfigurasi; amaran berasaskan ambang dan anomali AI |
| **Maximo Health & Predict** | Menjana skor kesihatan peralatan (Equipment Health Score 0–100); meramal bilakah peralatan akan mencapai titik kegagalan; mencadangkan tarikh penyelenggaraan optimum |
| **Maximo Visual Inspection** | Pemeriksaan visual berasaskan AI menggunakan imej kamera |
| **Integrasi CMMS** | Penjanaan work order automatik terus ke dalam sistem Maximo EAM |
| **IoT Integration** | Menyokong IBM Watson IoT Platform dan pelbagai protokol sensor standard |

**Kelebihan IBM Maximo AI:**
- Paling matang untuk perusahaan besar dengan inventori aset yang kompleks
- Integrasi penuh dengan sistem ERP IBM (dan boleh berintegrasi dengan SAP, Oracle)
- Jejak rekod terbukti di sektor utiliti, petroleum & gas, dan pembuatan berat
- AI model yang telah pra-latih (pre-trained) untuk jenis kegagalan peralatan yang biasa

**Pertimbangan:**
- Kos lesen yang lebih tinggi — lebih sesuai untuk perusahaan berskala besar (enterprise-grade)
- Kompleksiti pemasangan (implementation) yang lebih tinggi; memerlukan pakar IBM yang berkelayakan
- Kurva pembelajaran (learning curve) yang lebih curam untuk pengguna baru

**Kesesuaian senario:**
- Kilang petrokimia atau pembuatan berat dengan aset bernilai tinggi (> RM10 juta per unit)
- MNC yang sudah menggunakan IBM Maximo sebagai CMMS dan ingin menambah lapisan AI
- Syarikat dengan keperluan pematuhan ketat (audit trail, regulatory compliance)

**Konteks Malaysia:** IBM Maximo digunakan oleh beberapa syarikat utiliti dan petroleum besar di Malaysia. Untuk kilang E&E atau automotif Tier-2 yang lebih kecil, kos dan kompleksiti IBM Maximo mungkin berlebihan.

### 2.2 Microsoft Azure Predictive Maintenance

**Microsoft Azure** menawarkan set perkhidmatan cloud AI yang komprehensif untuk penyelenggaraan ramalan. Pendekatan Azure adalah lebih *modular* — pengguna boleh memilih dan menggabungkan perkhidmatan Azure yang diperlukan.

**Perkhidmatan Azure utama untuk PdM:**

| Perkhidmatan | Fungsi |
|---|---|
| **Azure IoT Hub** | Pengumpulan dan pengurus data sensor dari ribuan peranti IoT secara selamat |
| **Azure Stream Analytics** | Pemprosesan data sensor masa nyata (real-time streaming); pengesanan anomali pada tahap edge/cloud |
| **Azure Machine Learning (AML)** | Platform untuk membina, melatih, dan menggunakan model ML tersuai untuk ramalan kegagalan |
| **Azure Anomaly Detector** | Perkhidmatan API kognitif yang terlatih untuk mengesan anomali dalam data siri masa secara automatik |
| **Azure Digital Twins** | Membina model digital (twin) peralatan atau barisan pengeluaran untuk simulasi dan ramalan |
| **Power BI** | Dashboard visualisasi yang terintegrasi dengan Azure untuk memaparkan status kesihatan peralatan |

**Aliran kerja tipikal Azure PdM:**

1. Sensor kilang → Azure IoT Hub (pengumpulan data)
2. Azure Stream Analytics → proses data real-time, tapis anomali segera
3. Azure Data Lake → simpan data historis untuk latihan model
4. Azure Machine Learning → bina dan latih model ramalan kegagalan (LSTM, isolation forest, dll.)
5. Deployed model → skor kesihatan dan amaran secara real-time
6. Power BI dashboard → paparan status dan tren kepada pengguna

**Kelebihan Azure PdM:**
- Integrasi semula jadi dengan ekosistem Microsoft (Office 365, Teams untuk notifikasi, Power BI)
- Skalabiliti tinggi — boleh mulakan kecil dan berkembang mengikut keperluan
- Azure Anomaly Detector boleh digunakan tanpa kepakaran ML yang mendalam
- Harga bayar-sebagai-guna (pay-as-you-go) — lebih mesra bajet untuk SME
- Tutorial dan dokumentasi yang sangat komprehensif dalam Bahasa Inggeris

**Pertimbangan:**
- Memerlukan kepakaran teknikal untuk menggabungkan pelbagai perkhidmatan Azure
- Kos boleh meningkat dengan cepat jika volume data sensor sangat tinggi
- Bergantung pada sambungan internet yang stabil ke Azure cloud

**Contoh senario sesuai:**
- Kilang E&E di Bayan Lepas yang sudah menggunakan Microsoft 365 dan ingin menambah kemampuan AI PdM tanpa menukar ekosistem teknologi sedia ada
- Syarikat dengan pasukan IT dalaman yang mempunyai kemahiran Azure

### 2.3 AWS Lookout for Equipment

**Amazon Web Services (AWS) Lookout for Equipment** adalah perkhidmatan AI PdM yang dikhususkan — direka bentuk khusus untuk pemantauan kesihatan peralatan industri tanpa memerlukan kepakaran AI yang mendalam.

**Cara Kerja AWS Lookout for Equipment:**

1. **Muat naik data historis sensor** (sekurang-kurangnya 14 hari data normal; cadangan 180+ hari)
2. **AWS melatih model secara automatik** berdasarkan corak normal peralatan anda yang spesifik
3. **Model digunakan secara real-time** melalui AWS IoT Greengrass atau API
4. **Pengesanan anomali** dilaporkan dengan skor keyakinan (confidence score) dan komponen sensor yang paling menyumbang kepada anomali
5. **Integrasi** dengan AWS SNS (Simple Notification Service) untuk amaran, atau ke dashboard Amazon Managed Grafana

**Ciri-ciri yang membezakan AWS Lookout for Equipment:**

| Ciri | Penerangan |
|---|---|
| **No-code ML** | AWS melatih model secara automatik; pengguna tidak perlu menulis kod ML |
| **Equipment-specific baseline** | Model dilatih berdasarkan data peralatan anda yang sebenar, bukan model generik |
| **Diagnostic output** | Menunjukkan sensor mana yang paling menyumbang kepada anomali (explainability) |
| **Inference scheduling** | Boleh dikonfigurasi untuk menjalankan inferens setiap 5 minit, 15 minit, atau 1 jam |
| **AWS IoT Greengrass** | Boleh menjalankan model di edge untuk latency rendah |

**Kelebihan AWS Lookout for Equipment:**
- Paling mudah digunakan untuk pasukan yang tidak mempunyai pakar data science
- Model dilatih khusus untuk peralatan anda — lebih tepat daripada model generik
- Harga berdasarkan bilangan sensor dan volum data — boleh dimulakan dengan kos yang sangat rendah
- Sesuai untuk pelatih dan pelaksanaan projek perintis (pilot project)

**Pertimbangan:**
- Lebih terhad berbanding Azure AML atau IBM Maximo dalam keupayaan penyesuaian model
- Ekosistem AWS yang lebih ketat — sukar untuk integrasi dengan sistem bukan AWS
- Bergantung sepenuhnya pada cloud AWS (tiada pilihan on-premise yang mudah)

**Kesesuaian senario:**
- SME atau kilang yang ingin mencuba PdM untuk kali pertama dengan kos dan kerumitan minimum
- Projek perintis (pilot) untuk membuktikan nilai PdM sebelum melabur dalam platform yang lebih besar
- Persekitaran latihan dan akademik

## 3. Analisis Data Siri Masa (Time-Series Data Analysis)

Data sensor peralatan kilang adalah data siri masa — iaitu data yang direkodkan pada selang masa yang tetap, membentuk jujukan yang disusun mengikut kronologi. Memahami sifat data siri masa adalah asas untuk memilih teknik AI yang sesuai.

### 3.1 Ciri-ciri Data Siri Masa Sensor Peralatan

**Frekuensi pencuplikan (Sampling Rate):**
- Sensor getaran: biasanya 5,000–50,000 Hz (sangat tinggi frekuensi; data agregat sebelum disimpan)
- Sensor suhu/tekanan: biasanya 1 titik data setiap 1 saat hingga 1 minit
- Sensor arus: bergantung pada keperluan analisis — 1 Hz hingga 10 kHz

**Pola-pola dalam data siri masa peralatan:**
- **Trend (Tren):** Perubahan perlahan dan progresif dari semasa ke semasa — contoh, suhu bearing meningkat secara perlahan selama beberapa minggu sebelum gagal
- **Seasonality (Kebermusiman):** Corak yang berulang pada selang masa tetap — contoh, suhu mesin lebih tinggi pada sesi pengeluaran puncak (peak production)
- **Noise:** Variasi rawak yang tidak bermakna — contoh, getaran kecil semasa pengeluaran normal
- **Anomali:** Perubahan mendadak atau tidak lazim yang menandakan masalah yang berpotensi

### 3.2 Pra-pemprosesan Data Siri Masa (Time-Series Data Preprocessing)

Sebelum model AI dapat melatih atau membuat ramalan, data sensor mentah (raw) perlu diproses:

**a) Pengendalian Nilai Hilang (Missing Value Handling)**
- Sensor kadang-kala menghasilkan nilai hilang (null) disebabkan gangguan sambungan atau sensor rosak
- Kaedah: interpolasi linear, forward fill, atau pelabelan sebagai downtime
- Penting: jangan membuang rekod dengan nilai hilang secara sewenang-wenang — ini boleh memadamkan maklumat kegagalan

**b) Penormalan (Normalization / Scaling)**
- Sensor berbeza menghasilkan nilai dalam julat yang sangat berbeza (getaran: 0–50 mm/s; suhu: 20–200°C; arus: 0–500A)
- Normalisasi ke skala 0–1 atau penstandardan Z-score membolehkan model AI membandingkan semua sensor secara saksama

**c) Pengesanan dan Pengendalian Outlier**
- Nilai di luar julat fizikal yang munasabah (contoh: suhu -999°C) adalah ralat sensor, bukan bacaan sebenar
- Perlu dikenal pasti dan dialihkan sebelum latihan model

**d) Pengekstrakan Ciri (Feature Extraction)**
- Penghitungan ciri statistik daripada tetingkap masa (time window): min, sisihan piawai, min, maks, kurtosis, RMS (Root Mean Square), FFT components
- Pengurangan dimensi menggunakan teknik seperti PCA (Principal Component Analysis) jika bilangan sensor sangat banyak

### 3.3 Teknik Pengesanan Anomali (Anomaly Detection)

**Definisi anomali dalam konteks peralatan:** Sebarang corak dalam data sensor yang menyimpang dengan ketara daripada corak normal yang telah dipelajari oleh model.

Terdapat tiga kategori teknik anomali detection yang digunakan dalam AI PdM:

**Kategori 1 — Teknik Berasaskan Ambang (Threshold-Based)**

Paling ringkas: tentukan nilai minimum dan maksimum yang boleh diterima, dan flagkan bila nilai melanggar ambang.

- **Kelebihan:** Mudah dijelaskan; mudah dikonfigurasikan; sifar latihan model
- **Kelemahan:** Tidak dapat mengesan anomali kontekstual (nilai dalam julat normal tetapi corak tidak normal); menghasilkan banyak amaran palsu (false alarms)
- **Contoh:** Amaran jika suhu bearing > 85°C

**Kategori 2 — Teknik Statistik (Statistical Methods)**

*Isolation Forest:*
- Algorithm berasaskan pokok keputusan (decision tree) yang mengasingkan titik data yang "luar biasa" dengan membina pokok rawak
- Anomali adalah titik yang lebih mudah diasingkan (memerlukan lebih sedikit pembahagian)
- Sangat efektif untuk data multidimensi (banyak sensor serentak)
- Tidak memerlukan label data latihan (unsupervised) — sesuai untuk senario kilang di mana label kegagalan historis mungkin tidak lengkap

*Z-Score Method:*
- Anomali apabila nilai menyimpang lebih dari 3 sisihan piawai daripada min historis
- Ringkas dan boleh dijelaskan kepada pengurus kilang yang bukan pakar AI

*CUSUM (Cumulative Sum Control Chart):*
- Menjejak jumlah kumulatif penyimpangan dari sasaran untuk mengesan pergeseran kecil yang konsisten (kecil tetapi berterusan)
- Berguna untuk mengesan trend degradasi perlahan

**Kategori 3 — Pembelajaran Mendalam (Deep Learning Methods)**

*LSTM (Long Short-Term Memory):*
- Jenis Recurrent Neural Network (RNN) yang direka khas untuk data berjujukan (sequential data)
- Belajar corak dalam data siri masa yang panjang; dapat "mengingati" hubungan antara bacaan masa kini dan bacaan puluhan jam yang lalu
- Sangat sesuai untuk ramalan kegagalan di mana corak kegagalan muncul secara progresif
- Memerlukan data latihan yang lebih banyak dan sumber pengkomputeran yang lebih tinggi

*Autoencoder:*
- Rangkaian neural yang dilatih untuk membina semula data normal
- Anomali dikesan apabila ralat pembinaan semula (reconstruction error) sangat tinggi — bermakna model tidak dapat membina semula corak yang dilihat kerana ia tidak pernah melihat corak sebegitu semasa latihan
- Sangat berguna untuk data sensoran multivariat (banyak sensor serentak)

### 3.4 Kesalahan Tafsiran yang Perlu Dielakkan

> **PENTING — False Positive vs. False Negative dalam PdM:**
>
> - **False Positive (Amaran Palsu):** Model meramal kegagalan tetapi peralatan sebenarnya masih baik. Menyebabkan penyelenggaraan tidak perlu, membuang masa dan kos.
> - **False Negative (Kegagalan Terlepas):** Model tidak meramal kegagalan tetapi peralatan sebenarnya gagal. Ini adalah risiko yang lebih serius — menyebabkan downtime tidak dirancang.
>
> Dalam konteks PdM, adalah lebih baik memiliki kadar false positive yang sederhana tinggi berbanding kadar false negative yang tinggi — lebih baik menjalankan pemeriksaan yang tidak diperlukan daripada terlepas kegagalan peralatan yang sebenar.

## 4. Optimasi Jadual Penyelenggaraan Berasaskan AI

### 4.1 Dari Amaran ke Jadual Penyelenggaraan

Output model AI PdM bukan sahaja amaran — ia perlu diterjemahkan kepada jadual penyelenggaraan yang boleh dilaksanakan. Proses ini melibatkan:

**Langkah 1 — Penilaian Keterukan (Severity Assessment)**

Setiap amaran diklasifikasikan mengikut tahap keterukan:

| Tahap | Skor Kesihatan | Tindakan |
|---|---|---|
| **Normal** | 80–100 | Pantau sahaja; pemantauan berterusan |
| **Perhatian** (Watch) | 60–79 | Tingkatkan frekuensi pemantauan; jadualkan pemeriksaan |
| **Amaran** (Warning) | 40–59 | Jadualkan penyelenggaraan dalam 7–14 hari |
| **Kritikal** (Critical) | < 40 | Penyelenggaraan segera; pertimbangkan henti berancang |

**Langkah 2 — Ramalan Horizon Masa (Time-to-Failure Prediction)**

Model PdM yang lebih canggih menghasilkan bukan sahaja "ada anomali" tetapi juga "bilakah kegagalan dijangka berlaku":

- Horizon masa memberikan tetingkap perancangan (planning window)
- Contoh output: "Bearing No. 3 dijangka gagal dalam 9 ± 2 hari dengan keyakinan 87%"
- Maklumat ini membolehkan pasukan penyelenggaraan menempah komponen ganti, menjadualkan teknisi, dan merancang downtime semasa waktu pengeluaran rendah

**Langkah 3 — Pertimbangan Pengoptimuman Jadual**

Jadual penyelenggaraan optimum mengambil kira:
- **Keperluan peralatan:** Masa kritikal untuk penyelenggaraan (sebelum kegagalan dijangka)
- **Jadual pengeluaran:** Elakkan penyelenggaraan semasa waktu pengeluaran puncak
- **Ketersediaan sumber:** Teknisi terlatih, komponen ganti, peralatan penyelenggaraan
- **Kebergantungan antara peralatan:** Peralatan yang saling bergantung perlu diselaraskan

### 4.2 Integrasi dengan CMMS (Computerised Maintenance Management System)

CMMS adalah sistem pengurusan rekod penyelenggaraan — menguruskan work orders, inventori alat ganti, rekod sejarah peralatan, dan penjadualan teknisi. Integrasi AI PdM dengan CMMS mengautomasi aliran kerja:

```
[Amaran AI PdM] → [CMMS: Auto-generate Work Order]
                       ↓
         [Teknisi menerima work order di telefon/tablet]
                       ↓
         [Teknisi melaksanakan penyelenggaraan & rekodkan]
                       ↓
         [CMMS kemas kini rekod historis peralatan]
                       ↓
         [Data rekod kembali ke model AI untuk latihan semula]
```

Integrasi ini mencipta kitaran pembelajaran berterusan (continuous learning loop) di mana model AI bertambah baik dari semasa ke semasa.

### 4.3 Metrik Kejayaan Jadual Penyelenggaraan AI

Untuk menilai keberkesanan program PdM, kilang perlu memantau:

| KPI | Formula | Sasaran Tipikal |
|---|---|---|
| % Penyelenggaraan Terancang vs. Reaktif | Planned PM / (Planned + Reactive) × 100% | > 80% terancang |
| Kadar Amaran Palsu (False Alarm Rate) | False Positives / Total Alarms × 100% | < 20% |
| Pengurangan MTTR | (MTTR Sebelum − MTTR Selepas) / MTTR Sebelum | > 20% pengurangan |
| Peningkatan OEE | OEE Selepas − OEE Sebelum (dalam mata peratusan) | > 5 mata peratusan |
| % Pengurangan Downtime Tidak Dirancang | (Downtime Sebelum − Selepas) / Sebelum × 100% | > 30% |

## 5. Pertimbangan Pelaksanaan di Kilang Malaysia

### 5.1 Cabaran Sambungan dan Infrastruktur

Kilang-kilang Malaysia, terutamanya di kawasan perindustrian seperti Pasir Gudang, Senai FIZ, dan Klang, boleh menghadapi cabaran berikut:

- **Sambungan internet yang tidak stabil** di kawasan perindustrian tertentu — pertimbangkan edge computing untuk pemprosesan dan penyimpanan data sensor secara tempatan
- **Peralatan lawas (legacy equipment)** yang tidak mempunyai antara muka digital — perlukan sensor tambahan dan gateway IoT khusus
- **Keperluan keselamatan siber (cybersecurity)** untuk data sensor kilang yang sensitif — pilih platform dengan penyulitan data hujung-ke-hujung (end-to-end encryption)

### 5.2 Strategi Pelaksanaan Bertahap

Untuk kilang Malaysia yang baru memulakan perjalanan PdM, pendekatan bertahap yang disarankan:

**Fasa 1 (0–3 bulan) — Projek Perintis:**
- Pilih 2–3 peralatan kritikal sahaja
- Pasang sensor asas (suhu + getaran)
- Gunakan platform yang paling mudah (AWS Lookout for Equipment atau Azure Anomaly Detector)
- Himpun data selama 30–90 hari untuk baseline

**Fasa 2 (3–12 bulan) — Pengembangan:**
- Tingkatkan bilangan peralatan dipantau
- Tambah jenis sensor (current, acoustic)
- Bina model ML yang lebih khusus
- Integrasi dengan CMMS

**Fasa 3 (12+ bulan) — Pengoptimuman:**
- Model AI berlatih pada data historis yang cukup
- Ramalan kegagalan yang lebih tepat
- Pengoptimuman jadual penyelenggaraan automatik
- Laporan OEE terintegrasi

### 5.3 Insentif MIDA untuk Industri 4.0

Kilang Malaysia yang melaksanakan AI PdM boleh layak mendapat sokongan melalui:

- **MIDA Industry 4.0 Incentives (Insentif MIDA untuk Industri 4.0):** Potongan cukai pelaburan (Investment Tax Allowance / ITA) atau pengecualian cukai (Pioneer Status) untuk pelaburan dalam teknologi Industri 4.0, termasuk IoT dan AI
- **MIDA IMPAK Assessment:** Syarikat yang telah mendapat skor IMPAK tinggi mungkin mendapat keutamaan dalam permohonan insentif
- **HRD Corp SBL-Khas:** Majikan boleh menuntut subsidi latihan berkaitan AI PdM melalui skim ini

> Pelatih dinasihatkan untuk merujuk laman web rasmi MIDA (www.mida.gov.my) untuk maklumat insentif terkini, kerana kadar dan kelayakan boleh berubah.

## Soalan Ulangkaji / Review Questions

1. Seorang pengurus kilang di Nusajaya Tech Park ingin melaksanakan AI PdM untuk kali pertama pada 5 unit pam kritikal, dengan bajet terhad dan tiada pakar data science dalaman. Platform manakah — IBM Maximo AI, Azure Predictive Maintenance, atau AWS Lookout for Equipment — yang paling sesuai? Berikan tiga sebab untuk pilihan anda.

2. Terangkan perbezaan antara tiga kaedah pengesanan anomali: (a) ambang (threshold), (b) Isolation Forest, dan (c) LSTM Autoencoder. Untuk data sensor getaran mesin kilang dengan 5 tahun data historis yang lengkap, kaedah manakah paling sesuai? Jelaskan.

3. Data siri masa suhu bearing menunjukkan nilai-nilai berikut dalam tempoh 10 minit (°C): 72, 74, 71, 73, 182, 70, 72. Angka 182°C ini, adakah ia anomali sebenar atau ralat sensor? Apakah dua langkah pra-pemprosesan yang perlu dilakukan untuk mengesahkannya?

4. Jelaskan konsep "false positive" dan "false negative" dalam konteks sistem amaran AI PdM. Mengapa false negative dianggap lebih berbahaya berbanding false positive dalam persekitaran kilang?

5. Lukis dan terangkan empat lapisan senibina sistem AI PdM dari sensor peralatan hingga ke tindakan pasukan penyelenggaraan.
