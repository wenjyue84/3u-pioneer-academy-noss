## Prosedur Langkah demi Langkah / Step-by-Step Instructions

### Bahagian A: Rajah Seni Bina Integrasi (45 minit)

#### Langkah A1: Lukis Rajah Seni Bina Menggunakan draw.io

Buka [diagrams.net](https://diagrams.net) (draw.io) dan lukis rajah seni bina integrasi yang mengandungi semua komponen berikut:

**Komponen yang mesti ada dalam rajah:**

| Lapisan | Komponen |
|---|---|
| **Lantai kilang (Level 0)** | 3 barisan pengeluaran (Line A, B, C); 6 kamera (2 per barisan); produk bergerak pada konveyor |
| **Pengiraan Edge (Level 1)** | 1 Edge PC per barisan (3 jumlah); model AI YOLOv8 berjalan pada setiap Edge PC; GPU NVIDIA |
| **Lapisan komunikasi** | REST API (HTTP POST) dari setiap Edge PC ke MES; nombor port: 8080 (sintetik) |
| **MES (Level 3)** | Ignition MES Server; Modul Quality Management; Pangkalan data rekod kualiti |
| **Lapisan tindakan** | PLC Reject Arm (isyarat dari Edge PC ke PLC melalui digital I/O); Dashboard kualiti masa nyata |

**Arahan melukis:**
1. Gunakan bentuk segi empat untuk peranti dan sistem
2. Gunakan anak panah berlabel untuk menunjukkan arah aliran data
3. Labelkan setiap sambungan dengan protokol yang digunakan
4. Gunakan warna berbeza untuk lapisan berbeza (contoh: hijau = fizikal, biru = IT, merah = amaran)

Eksport rajah sebagai PNG atau PDF dan sertakan dalam laporan anda.

### Bahagian B: Definisi Skema Rekod Kualiti MES (30 minit)

#### Langkah B1: Reka Bentuk Skema Rekod Kualiti

Berdasarkan seni bina kilang KTPJ, reka bentuk skema rekod kualiti untuk jadual `inspection_results` dalam MES Ignition.

Isi Jadual B1 dalam Bahagian Rekod Pelatih:
- Nama medan
- Jenis data
- Contoh nilai untuk 3 rekod berbeza (1 LULUS, 1 GAGAL satu kecacatan, 1 GAGAL dua kecacatan)
- Tujuan medan

Medan minimum: `inspection_id`, `product_id`, `line_id`, `timestamp`, `result`, `defect_class`, `confidence`, `image_path`, `model_version`

#### Langkah B2: Definisikan Peraturan Pencetus Amaran

Reka bentuk minimum **4 peraturan amaran** untuk sistem KTPJ. Untuk setiap peraturan, tentukan:
- Keadaan pencetus (trigger condition)
- Tindakan sistem (system action)
- Masa respons sasaran

Isi Jadual B2 dalam Bahagian Rekod Pelatih.

---

### Bahagian C: Pengiraan Keperluan Sistem (30 minit)

#### Langkah C1: Kira Keperluan Bandwidth Rangkaian

Untuk setiap barisan pengeluaran (60 unit/minit, 2 kamera, REST API):

```
Bilangan payload API/minit per barisan = 60 unit × 2 kamera = 120 payload/minit
Saiz setiap payload JSON (metadata sahaja) = anggap 2 KB
Bandwidth rekod = 120 × 2 KB = 240 KB/minit = 4 KB/saat per barisan

Untuk 3 barisan: 3 × 4 KB/saat = 12 KB/saat
```

> **Nota:** Imej biasanya TIDAK dihantar melalui REST API ke MES (terlalu besar). Imej disimpan terus pada Edge PC atau NAS, dan hanya `image_path` dihantar dalam rekod. Kira storan imej secara berasingan.

#### Langkah C2: Kira Keperluan Storan Imej

Gunakan data KTPJ untuk mengira:

**(a) Storan imej FAIL sehari:**
```
Unit/hari = 172,800
Kadar FAIL (dijangka dengan AI) = 0.4%
Unit FAIL/hari = 172,800 × 0.004 = 691.2 ≈ 692 unit
Imej per unit FAIL = 2 kamera × 1 imej = 2 imej
Imej FAIL/hari = 692 × 2 = 1,384 imej
Storan imej FAIL/hari = 1,384 × 600 KB = 830,400 KB ≈ 811 MB ≈ 0.81 GB
```

**(b) Storan imej SEMUA unit (jika semua imej disimpan selama 30 hari untuk audit):**
```
Imej/hari = 172,800 unit × 2 kamera = 345,600 imej/hari
Storan/hari = 345,600 × 600 KB = 207,360,000 KB ≈ 197.8 GB/hari
Storan 30 hari = 197.8 × 30 = 5,934 GB ≈ 5.8 TB
```

**(c) Keputusan amali:** Simpan semua imej selama 7 hari (untuk semakan cepat); simpan HANYA imej FAIL untuk 12 bulan (untuk audit ISO).

Sahkan pengiraan di atas dan jawab soalan dalam Bahagian Rekod Pelatih (Jadual C1).

#### Langkah C3: Kira Keperluan Masa Inferens

Untuk setiap Edge PC (menguruskan 1 barisan, 2 kamera):

```
Kelajuan barisan = 60 unit/minit = 1 unit/saat
Masa inferens model = 8 ms/imej
2 kamera = 2 imej/unit → masa inferens = 2 × 8 ms = 16 ms/unit
Masa yang tersedia = 1,000 ms/unit (1 saat)
Margin masa = 1,000 - 16 = 984 ms (untuk I/O, REST API call, logging, dsb.)
```

Soalan: Adakah sistem mencukupi dari segi kelajuan? Rekodkan jawapan dalam Bahagian Rekod Pelatih.

### Bahagian D: Perbandingan Prestasi AI vs. Pemeriksaan Manual (30 minit)

#### Langkah D1: Isi Jadual Perbandingan

Gunakan data KTPJ berikut (data sintetik):

**Rekod pemeriksaan manual KTPJ (sebelum AI — 30 hari lalu):**
- Jumlah unit diperiksa: 518,400 (hanya 3 syif pertama setiap hari, kerana pekerja tidak cukup)
- Pekerja pemeriksa: 6 orang (2 per barisan)
- Unit yang tidak diperiksa: 30% (tiada cukup masa)
- Kadar kecacatan ditemui oleh pemeriksa: 0.8%
- Aduan pelanggan dalam 30 hari: 23 kes kecacatan terlepas (escaped defects)
- Gaji pemeriksa: RM1,800/bulan × 6 = RM10,800/bulan

**Rekod AI vision inspection KTPJ (pilot 30 hari):**
- Jumlah unit diperiksa: 5,184,000 (100% — setiap unit)
- Kadar kecacatan ditemui oleh AI: 1.2% (lebih tinggi daripada manual — AI mengesan yang terlepas)
- Recall model: 95% (dari keputusan validasi)
- Precision model: 88%
- Aduan pelanggan dalam 30 hari pilot: 2 kes
- Kos sistem AI (ansuran bulanan): RM8,500/bulan (perkakasan + perisian)

Isi Jadual D1 dalam Bahagian Rekod Pelatih.

#### Langkah D2: Kira Penjimatan Kos Bulanan

```
Kos pemeriksa manual     = RM10,800/bulan
Kos sistem AI            = RM8,500/bulan
Penjimatan gaji terus    = RM10,800 - RM8,500 = RM2,300/bulan

Kos aduan pelanggan (anggaran):
  Manual: 23 kes × RM500/kes (kos pengendalian) = RM11,500/bulan
  AI:     2 kes × RM500/kes = RM1,000/bulan
  Penjimatan aduan = RM10,500/bulan

Jumlah penjimatan = RM2,300 + RM10,500 = RM12,800/bulan
ROI bulan ke-1 = (RM12,800 - RM8,500) ÷ RM8,500 × 100% = 50.6%
```

Sahkan pengiraan dan rekod dalam Bahagian Rekod Pelatih.
