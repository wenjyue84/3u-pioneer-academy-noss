## 1. Seni Bina MES (Manufacturing Execution System Architecture)

### 1.1 Apakah MES?

**MES (Manufacturing Execution System / Sistem Pelaksanaan Pembuatan)** adalah lapisan perisian yang menjambatani perancangan pengeluaran di peringkat ERP (Enterprise Resource Planning) dengan operasi fizikal di lantai kilang (shop floor).

MES menjawab soalan masa nyata: "Apa yang sedang berlaku di lantai kilang *sekarang*?"

### 1.2 Hirarki Automasi Kilang (ISA-95 / Purdue Reference Model)

```
┌─────────────────────────────────────────────────────┐
│   LEVEL 4 — Business (ERP / SAP / Oracle)          │  Perancangan perniagaan, pemasaran
│   (Perancangan sumber perusahaan)                   │
├─────────────────────────────────────────────────────┤
│   LEVEL 3 — MES / SCADA / Historian                │  Pelaksanaan pengeluaran, kualiti,
│   (Pelaksanaan & pengurusan operasi)                │  penjadualan, penyelenggaraan
├─────────────────────────────────────────────────────┤
│   LEVEL 2 — SCADA / HMI / DCS                     │  Kawalan proses, pengawasan
│   (Kawalan & pengawasan)                            │
├─────────────────────────────────────────────────────┤
│   LEVEL 1 — PLC / DCS Controllers                  │  Kawalan logik program
│   (Kawalan asas)                                    │
├─────────────────────────────────────────────────────┤
│   LEVEL 0 — Sensors, Actuators, Cameras            │  Fizikal: penderia, motor, kamera AI
│   (Proses fizikal)                                  │
└─────────────────────────────────────────────────────┘
```

Sistem AI vision inspection berada di **Level 0–1**: kamera (Level 0) menghantar keputusan kepada pengawal atau terus ke MES (Level 3).

### 1.3 Modul Fungsi MES yang Relevan dengan Kualiti

Standard ISA-95 mendefinisikan 11 modul fungsi MES. Yang paling relevan untuk AI vision quality control:

| Modul MES | Fungsi | Kaitan dengan AI Vision |
|---|---|---|
| **Quality Management** | Merekod keputusan ujian dan pemeriksaan; menguruskan NCR | Penerima utama data AI vision |
| **Product Tracking & Genealogy** | Menjejak pergerakan setiap unit di setiap stesen kerja | Menerima ID unit dan keputusan pemeriksaan |
| **Production Dispatching** | Mengagihkan arahan kerja ke stesen pengeluaran | Boleh memasukkan logik "tahan jika model AI tidak keyakinan" |
| **Performance Analysis** | Mengira OEE, kadar kecacatan, trend kualiti | Menggunakan data AI vision untuk laporan kualiti |
| **Document Management** | Menyimpan rekod SOP, spesifikasi produk | Menyimpan imej kecacatan yang ditangkap |

### 1.4 Contoh MES yang Digunakan di Kilang Malaysia

| MES | Vendor | Penggunaan Lazim di Malaysia |
|---|---|---|
| SAP Manufacturing Execution (ME) | SAP SE | MNC besar, automotif, aeroangkasa |
| Siemens Opcenter (bekas SIMATIC IT) | Siemens | E&E, semikonduktor |
| Rockwell Automation FactoryTalk | Rockwell Automation | Automotif, F&B |
| Plex Smart Manufacturing | Rockwell Automation | Kilang sederhana |
| Ignition (Inductive Automation) | Inductive Automation | Pelbagai industri; popular untuk projek kustom |
| OEE.ai / Datanomix | Pelbagai startup | SME yang mahu MES mudah tanpa kos besar |

## 2. Corak Integrasi AI Vision → MES

### 2.1 Gambaran Keseluruhan Pilihan Integrasi

Tidak ada cara tunggal yang "betul" untuk mengintegrasikan AI vision dengan MES. Pilihan bergantung pada:
- MES yang digunakan (adakah ia menyokong API REST, OPC-UA, atau hanya pangkalan data SQL?)
- Keperluan latensi (masa nyata dalam ms, atau laporan kumpulan setiap minit?)
- Keperluan keteguhan (adakah sistem boleh berfungsi jika sambungan rangkaian terputus?)

### 2.2 Corak 1: REST API (HTTP/HTTPS)

**Cara kerja:**
```
[Kamera + AI Model] → HTTP POST → [MES API Endpoint]
Payload JSON: {product_id: "PCB-20260729-0042", result: "FAIL",
               defect_class: "solder_bridge", confidence: 0.91,
               bbox: [340, 210, 45, 12], timestamp: "2026-07-29T08:42:11.304Z"}
```

**Kelebihan:**
- Standard terbuka; semua bahasa pengaturcaraan menyokong HTTP.
- Mudah untuk nyahpepijat (debug) menggunakan alat seperti Postman.
- Sesuai untuk MES berasaskan web moden.

**Kekurangan:**
- Latensi lebih tinggi berbanding protokol OT (10–100 ms berbanding sub-ms untuk PLC langsung).
- Memerlukan sambungan rangkaian yang stabil.

**Kesesuaian:** Platform moden (LandingLens, Roboflow) menyokong penghantaran hasil inferens melalui REST API — pilihan paling mudah untuk integrasi awal.

### 2.3 Corak 2: OPC-UA (Open Platform Communications — Unified Architecture)

**Cara kerja:** OPC-UA adalah standard komunikasi industri neutral-vendor yang direka untuk pertukaran data antara peranti lantai kilang dan sistem tahap lebih tinggi.

```
[Kamera AI + OPC-UA Client] → OPC-UA Server (dalam MES/SCADA) → Pangkalan data MES
```

**Kelebihan:**
- Standard industri IEC 62541; disokong oleh hampir semua MES dan SCADA.
- Menyokong pemberitahuan berasaskan acara (event-based) — tidak perlu poll setiap saat.
- Mempunyai model keselamatan terbina dalam (sijil x.509, pengesahan).

**Kekurangan:**
- Lebih kompleks untuk dikonfigurasi berbanding REST API.
- Memerlukan OPC-UA client library dalam kod Python/C++ model AI.

**Kesesuaian:** Pilihan terbaik untuk kilang yang sudah mempunyai SCADA atau MES OPC-UA-enabled, contohnya kilang automotif di Shah Alam.

### 2.4 Corak 3: MQTT (Message Queuing Telemetry Transport)

**Cara kerja:**
```
[Kamera AI] → MQTT Publisher → [MQTT Broker (mosquitto/HiveMQ)] → MQTT Subscriber (MES)
Topic: factory/line1/vision/inspection
```

**Kelebihan:**
- Protokol ringan, direka untuk peranti IoT dengan lebar jalur terhad.
- Sokongan Quality of Service (QoS) — jaminan penghantaran mesej walaupun sambungan terputus seketika.
- MQTT Broker boleh dipasang di dalam kilang (on-premise) untuk mengelak kebergantungan pada internet.

**Kekurangan:**
- Asynchronous — penghantar tidak tahu sama ada mesej diterima dan diproses dengan betul oleh MES.
- Memerlukan pengurusan broker MQTT tambahan.

**Kesesuaian:** Sesuai untuk integrasi IoT pelbagai peranti — kilang dengan banyak kamera di stesen berbeza yang perlu menghantar data ke satu MES pusat.

### 2.5 Corak 4: Tulis Terus ke Pangkalan Data (Direct DB Write)

**Cara kerja:** Kod AI vision menulis keputusan terus ke jadual kualiti dalam pangkalan data MES (SQL Server, PostgreSQL, Oracle DB).

```python
# Contoh pseudokod Python
import pyodbc
conn = pyodbc.connect("DRIVER={SQL Server};SERVER=mes-db01;DATABASE=QualityDB;...")
cursor = conn.cursor()
cursor.execute(
    "INSERT INTO inspection_results (product_id, result, defect_class, confidence, timestamp) VALUES (?, ?, ?, ?, ?)",
    ("PCB-20260729-0042", "FAIL", "solder_bridge", 0.91, "2026-07-29 08:42:11")
)
conn.commit()
```

**Kelebihan:** Paling mudah untuk MES legacy yang tidak mempunyai API.

**Kekurangan:** Menggabungkan sistem dengan erat (tight coupling); perubahan skema pangkalan data MES boleh merosakkan integrasi; risiko keselamatan (kod luaran menulis terus ke DB MES).

**Kesesuaian:** Gunakan hanya jika tiada pilihan lain (MES sangat lama tanpa API). Dapatkan kelulusan dari pasukan IT kilang sebelum menggunakan corak ini.

### 2.6 Cadangan Pemilihan Corak

| Senario | Corak Disyorkan |
|---|---|
| MES moden dengan API (SAP ME, Plex) | REST API |
| Kilang dengan SCADA/HMI OPC-UA | OPC-UA |
| Banyak kamera IoT, bandwidth rendah | MQTT |
| MES legacy tanpa API (pilihan terakhir) | Direct DB Write |
| Prototype / ujian awal | REST API (paling mudah dimulakan) |

## 3. Reka Bentuk Aliran Data Kualiti Masa Nyata

### 3.1 Seni Bina Aliran Data Lengkap

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        SENI BINA SISTEM AI VISION + MES                     │
│                                                                             │
│  [Barisan Pengeluaran]                                                      │
│  Produk bergerak →                                                          │
│  ┌──────────────┐   Imej    ┌────────────────┐   JSON    ┌──────────────┐  │
│  │  Kamera Area │──────────►│  Edge PC       │──────────►│  MES Server  │  │
│  │  Industri    │           │  (YOLOv8 +     │  REST API │  (Modul      │  │
│  │  (trigger    │           │   Python)      │  / OPC-UA │   Quality)   │  │
│  │   dari PLC)  │           │                │           │              │  │
│  └──────────────┘           └────────┬───────┘           └──────┬───────┘  │
│                                      │                          │           │
│                                      │ Isyarat I/O             │ Data      │
│                                      ▼                          ▼           │
│                             ┌────────────────┐        ┌──────────────────┐ │
│                             │  PLC / Reject  │        │  Dashboard       │ │
│                             │  Arm / Alarm   │        │  Kualiti Masa    │ │
│                             │  (tolak unit   │        │  Nyata (SCADA/   │ │
│                             │   cacat)       │        │  BI)             │ │
│                             └────────────────┘        └──────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 Skema Rekod Kualiti Minimum

Setiap rekod pemeriksaan dalam MES mesti mengandungi sekurang-kurangnya medan berikut:

| Medan | Jenis Data | Contoh | Tujuan |
|---|---|---|---|
| `inspection_id` | UUID | `"a3f7-..." ` | Kunci primer unik |
| `product_id` | String | `"PCB-20260729-0042"` | ID serialisasi produk |
| `batch_id` | String | `"LOT-2026-07-29-B03"` | Lot pengeluaran |
| `line_id` | String | `"LINE-A-STATION-4"` | Stesen pemeriksaan |
| `timestamp` | DateTime | `2026-07-29T08:42:11.304Z` | Masa pemeriksaan (UTC) |
| `result` | Enum | `"PASS"` / `"FAIL"` | Keputusan akhir |
| `defect_class` | String / Null | `"solder_bridge"` | Kelas kecacatan (null jika PASS) |
| `confidence` | Float (0–1) | `0.91` | Keyakinan model AI |
| `bbox_x, y, w, h` | Integer / Null | `340, 210, 45, 12` | Koordinat kecacatan |
| `image_path` | String | `"/images/PCB-0042.jpg"` | Laluan ke imej tersimpan |
| `model_version` | String | `"yolov8m-pcb-v2.3"` | Versi model AI yang digunakan |

### 3.3 Pencetus Amaran (Alert Triggers) dalam MES

Selepas rekod pemeriksaan dimasukkan, MES boleh mencetuskan amaran berdasarkan peraturan:

| Peraturan Pencetus | Keadaan | Tindakan MES |
|---|---|---|
| **Unit tolak segera** | result = FAIL | Hantar isyarat kepada PLC reject arm (dalam <50 ms) |
| **Alert kadar kecacatan** | >3 FAIL berturut-turut | Isyarat amaran kepada QA engineer melalui SCADA alarm |
| **Alert kadar kecacatan % lot** | Kadar FAIL > 2% dalam lot semasa | Hentikan barisan; buka Work Order NCR automatik |
| **Alert keyakinan rendah** | confidence < 0.60 untuk mana-mana inferens | Tandakan untuk pemeriksaan manual semula |
| **Alert traceability** | product_id tidak sepadan dengan Work Order aktif | Tahan unit; isyarat kepada operator |

### 3.4 Senario Traceability — Contoh

**Senario:** Pelanggan automotif melaporkan kegagalan dalam komponen yang dipasang dua bulan lalu. Nombor siri komponen: `COMP-2026-05-14-0892`.

**Proses traceability dalam MES:**

```
1. Cari inspection_id berkaitan product_id = "COMP-2026-05-14-0892"
   → Rekod ditemui: result=PASS, confidence=0.73, timestamp=2026-05-14T10:22:07Z

2. Semak model_version = "yolov8m-pcb-v1.9"
   → Adakah model v1.9 mempunyai kelemahan yang diketahui?
   → Semak log kualiti model untuk tarikh tersebut

3. Dapatkan image_path dan semak imej asal
   → Imej menunjukkan solder void kecil — berada di bawah ambang keyakinan pada masa itu (0.73 < 0.80)

4. Semak semua produk dari lot yang sama (batch_id = "LOT-2026-05-14-B07")
   → 847 unit dalam lot; 12 unit mempunyai confidence 0.65–0.79 → panggil semula untuk semak manual

5. Kemaskini ambang keyakinan minimum kepada 0.80 dan latih semula model dengan imej solder void baru
```

**Ini adalah traceability yang bermakna.** Tanpa MES integration, langkah 1–4 memerlukan berminggu-minggu siasatan manual.

## 4. ISO 9001:2015 dan Traceability Kualiti

### 4.1 Klausa ISO 9001:2015 yang Berkaitan

ISO 9001:2015 adalah standard sistem pengurusan kualiti yang paling luas diterima pakai oleh kilang di Malaysia. Tiga klausa paling relevan:

**Klausa 8.5.2 — Identification and Traceability (Pengenalan dan Kebolehjejakan)**

> "The organisation shall use suitable means to identify outputs when it is necessary to ensure the conformity of products and services. The organisation shall identify the status of outputs with respect to monitoring and measurement requirements throughout production and service provision."

Implikasi: Setiap unit produk mesti boleh dikenal pasti dan riwayat pemeriksaannya boleh ditelusuri. Sistem AI vision + MES memenuhi keperluan ini secara automatik apabila direka bentuk dengan betul.

**Klausa 8.5.3 — Property Belonging to Customers or External Providers**

> Apabila komponen pelanggan diproses dalam kilang subkontraktor, traceability mesti dikekalkan untuk komponen tersebut.

**Klausa 8.7 — Control of Nonconforming Outputs (Kawalan Output Tidak Akur)**

> "The organisation shall ensure that outputs that do not conform to their requirements are identified and controlled to prevent their unintended use or delivery."

Implikasi: Setiap unit FAIL mesti ditandakan dengan jelas (fizikal dan dalam rekod MES) dan tidak boleh dilepaskan tanpa kelulusan khusus (NCR review, concession, atau rework).

### 4.2 Dua Jenis Traceability

| Jenis | Definisi | Cara AI Vision Menyumbang |
|---|---|---|
| **Product Traceability (Kebolehjejakan Produk)** | Keupayaan untuk menjejak satu unit produk tertentu melalui keseluruhan proses pengeluaran | Setiap rekod pemeriksaan dikaitkan dengan ID produk unik |
| **Process Traceability (Kebolehjejakan Proses)** | Keupayaan untuk mengenal pasti parameter proses yang digunakan semasa menghasilkan produk tertentu | Rekod menyimpan model_version, kamera, pencahayaan, dan parameter lain pada masa pemeriksaan |

Kedua-dua jenis diperlukan untuk siasatan kegagalan yang komprehensif.

### 4.3 Keperluan Simpanan Rekod

ISO 9001:2015, Klausa 7.5.3 memerlukan rekod terkawal (documented information) disimpan dan dilindungi. Untuk rekod AI vision inspection:

| Jenis Rekod | Tempoh Simpanan Disyorkan | Catatan |
|---|---|---|
| Rekod pemeriksaan (pass/fail + metadata) | Minimum 3 tahun; 10 tahun untuk komponen keselamatan | Bergantung kepada keperluan pelanggan dan industri |
| Imej kecacatan | 1–3 tahun | Storan boleh besar — anggaran 1 MB/imej × 100,000 imej/bulan = 100 GB/bulan |
| Versi model AI dan parameter | Seumur hayat model aktif + 2 tahun selepas persaraan | Penting untuk analisis retroaktif |
| Rekod pengesahan model (validation logs) | Seumur hayat model aktif | Diperlukan untuk audit ISO |

### 4.4 Audit Dalaman ISO 9001 — Perkara yang Disemak

Auditor ISO yang menyemak sistem AI vision biasanya mengesahkan:

1. Adakah prosedur bertulis (SOP) untuk kalibrasi kamera dan pencahayaan?
2. Adakah rekod menunjukkan bilangan unit yang diperiksa dan kadar FAIL per lot?
3. Adakah unit FAIL ditandakan fizikal dan diasingkan daripada barisan?
4. Adakah NCR (Non-Conformance Report) dibuka untuk lot dengan kadar kecacatan tinggi?
5. Adakah tindakan pembetulan (corrective action) dan pencegahan (preventive action) didokumenkan?
6. Adakah model AI disahkan semula selepas sebarang perubahan perkakasan kamera atau pencahayaan?

## 5. Reka Bentuk Spesifikasi Integrasi (Integration Specification Document)

Dokumen ini disediakan oleh jurutera AI dan digunakan untuk handoff kepada pasukan IT kilang untuk pelaksanaan. Bahagian minimum yang diperlukan:

### 5.1 Struktur Dokumen Spesifikasi Integrasi

**1. Gambaran Keseluruhan Sistem**
- Rajah seni bina (architecture diagram) menunjukkan semua komponen
- Senarai IP address dan port yang digunakan
- Keperluan rangkaian (bandwidth, latensi, firewall rules)

**2. Spesifikasi API / Protokol**
- Endpoint URL atau OPC-UA node ID
- Format mesej (JSON schema)
- Kaedah pengesahan (authentication)
- Pengendalian ralat dan mekanisme retry

**3. Skema Pangkalan Data**
- Jadual dan medan yang ditulis oleh sistem AI
- Kunci asing yang perlu dikaitkan dengan rekod MES sedia ada

**4. Keperluan Prestasi**
- Latensi maksimum dari penangkapan imej ke rekod dalam MES: `< 500 ms`
- Kadar transaksi: `10 pemeriksaan/saat pada kapasiti puncak`
- Uptime minimum: `99.5%` (membenarkan ~44 jam downtime setahun)

**5. Prosedur Siaran dan Rollback**
- Langkah untuk mengemas kini versi model AI tanpa menghentikan barisan
- Prosedur rollback kepada versi model sebelumnya jika prestasi merosot

**6. Ujian Penerimaan (UAT) Kriteria**
- Senarai semak yang mesti lulus sebelum sistem dilancarkan ke pengeluaran penuh

## 6. Contoh Senario: Kilang PCB di Nusajaya Tech Park

Kilang E&E di Nusajaya Tech Park, Johor melaksanakan integrasi AI vision dengan MES Ignition mereka. Maklumat berikut adalah data sintetik untuk tujuan pengajaran:

**Data barisan:**
- Kelajuan barisan: 80 unit PCB/minit
- Masa pemeriksaan per unit (kamera ke keputusan): 0.3 saat
- 3 jenis kecacatan: solder_bridge, missing_component, solder_void
- Sasaran Recall: ≥ 95%; Sasaran Precision: ≥ 85%

**Pilihan integrasi:** REST API (Ignition menyediakan endpoint REST API melalui modul Ignition Web Dev)

**Aliran data per minit:** 80 panggilan API POST × ~2 KB/payload = 160 KB/minit = 9.6 MB/jam

**Simpanan imej:** 80 imej/minit × 0.5 MB/imej = 40 MB/minit = 57.6 GB/hari (imej FAIL sahaja disimpan: andaikan 2% FAIL → 1.15 GB/hari)

**Pencetus amaran dikonfigurasi:**
- >3 unit FAIL berturut-turut → amaran kepada QA station dalam 30 saat
- Kadar FAIL lot > 3% → hentikan barisan, buka NCR automatik

## Soalan Ulangkaji / Review Questions

1. Terangkan perbezaan antara integrasi REST API dan integrasi OPC-UA untuk menghubungkan sistem AI vision dengan MES. Dalam keadaan apa anda akan memilih OPC-UA berbanding REST API?

2. Sebuah kilang getah mempunyai 5 kamera AI vision di sepanjang barisan sarung tangan, menghasilkan 200 rekod pemeriksaan/minit. Setiap rekod mengandungi payload 3 KB, dan setiap imej FAIL (dijangka 1%) disimpan pada 800 KB. Kira: (a) saiz data rekod MES per hari (anggap 8 jam operasi); (b) saiz simpanan imej FAIL per hari.
