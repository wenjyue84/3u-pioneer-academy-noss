## Skema Jawapan / Marking Scheme

*(For trainer use only — not to be distributed to trainees)*

**Q1(a):** Any two of: SST code mapping / SST-02 report generation; double-entry GL engine; bank reconciliation module; multi-currency support; accounts receivable/payable modules. (2 marks each)

**Q1(b):** Any two of: stronger presence in construction/trading sector; integrated SQL Payroll module; batch entry for high-volume transactions; 200+ built-in report templates. (2 marks each)

**Q1(c):** Advantage — any one of: automatic bank feed integration; native Hubdoc integration; cloud-first architecture; growing Xero adviser network in Malaysia. Limitation — any one of: SST module less comprehensive than AutoCount/SQL; no built-in EPF/SOCSO/EIS payroll for Malaysian statutory contributions; pricing in USD. (2 marks each)

**Q1(d):** Shared credentials violate the Security principle (Keselamatan) of PDPA 2010 — cannot trace which individual accessed which financial record; impossible to establish accountability; recommended practice is individual login per user. (3 marks)

**Q2(a):** Invoice Number (INV-2088 vs INV-2089); SST Amount (RM 0 vs RM 90.00). Note: Total Amount error flows from SST error — accept as consequence of SST field error if explained. (2 marks each)

**Q2(b):** Invoice Number: posting with wrong number creates a duplicate record; the actual INV-2089 cannot be matched if it appears again; risk of double payment or missed supplier credit. SST Amount: posting RM 0 SST means the company under-records SST paid to supplier; if SST-registered input credit is applicable, it would be lost; audit discrepancy. (3 marks each)

**Q2(c):** Step 1 — identify the two incorrect fields in the Dext review screen; Step 2 — correct invoice number from INV-2088 to INV-2089 in Dext; Step 3 — correct SST amount from RM 0 to RM 90 and total from RM 1,500 to RM 1,590 in Dext; Step 4 — re-validate corrected data against physical invoice; approve and post. (1–2 marks each, total 5)

**Q3(a):** Adjusted book balance = Bank statement balance (RM 45,200) − Outstanding cheque (RM 3,500) + Interest credited (RM 120) − Bank charge (RM 50) [bank charge reduces book balance further] = RM 45,200 − RM 3,500 + RM 120 − RM 50 = RM 41,770. Accept equivalent working. (5 marks: 2 for correct method, 3 for correct answer)

**Q3(b):** Any three of: (1) Bank charge — record as expense in books; (2) Interest credited — record as income in books; (3) Timing difference (cheque issued, not yet presented) — list as outstanding item in reconciliation; (4) Direct debit/payment not yet recorded in books — record in books; (5) Data entry error — identify and reverse the error entry. (2 marks each)

**Q3(c):** Any two of: Bank Reconciliation Report (purpose: proof of month-end reconciliation, for auditor review); Trial Balance (purpose: summary of all account balances, for accountant review); General Ledger detail export (purpose: full transaction list for audit trail); AR/AP Aging Report (purpose: outstanding balances for audit). (2 marks each)

**Q4(a):** A Chart of Accounts is a structured list of account codes used to classify all income and expense transactions. It is important because: (1) it ensures consistency — all staff categorise the same type of expense the same way; (2) it produces meaningful reports — management can see totals by category; (3) it supports SST compliance — SST codes are linked to specific accounts. (4 marks)

**Q4(b):** TNB — Utilities — Electricity (account 6400); Agensi Kreatif ABC — Marketing and Advertising (account 6600); Peguam XYZ — Professional Fees (account 6800). (2 marks each)

**Q4(c):** Set up a supplier rule in Dext/AutoCount: navigate to supplier rules → create/edit rule for the supplier → assign a fixed account code (e.g., 6600 Marketing if that is the correct category) → save rule → all future invoices from that supplier auto-categorise to 6600. She should maintain a Rule Register (Daftar Peraturan) documenting each rule, when it was set, who set it, and when it was last reviewed. (5 marks)

**Q5 (SOP — 20 marks):** Mark holistically. Full marks require: all 6 elements covered (pre-processing check, OCR validation, posting, bank reconciliation, audit export, PDPA handling); logical sequential structure; practical and actionable language; at least 4 reconciliation steps; PDPA element references Security and Retention principles specifically; export section names at least 2 document types. Deduct 2 marks for each element missing or substantially incomplete.

**Q6(a) (10 marks):** Award marks for: correct identification that AutoCount has full SST module for manufacturing (2); QuickBooks does not natively support SST-02 (2); AutoCount supports EPF/SOCSO in companion payroll module while QuickBooks payroll is US-focused (2); AutoCount/SQL have local reseller support for Malaysian compliance updates (2); recommendation for AutoCount with clear justification referencing SST and statutory requirements (2).

**Q6(b) (10 marks):** PDPA principles: Security (Keselamatan) — WhatsApp is not a company-authorised secure channel for financial data; Disclosure (Pendedahan) — personal financial data shared via insecure channel. Risk: data breach risk if phone lost/hacked; expense data may contain personal data (individual payment amounts, supplier identities). Three corrective measures — any three: (1) establish company-approved file sharing method (SharePoint, Google Drive with access control, company email); (2) delete existing financial reports from personal WhatsApp immediately; (3) train all staff on approved data sharing channels; (4) implement a Data Handling SOP with approved tools list; (5) conduct PDPA awareness session. (2 marks each corrective measure, 4 marks for principle/risk identification)
