## 1. Pengenalan kepada Analisis Aliran Kerja / Introduction to Workflow Analysis

### 1.1 What is a Workflow? (Apakah Aliran Kerja?)

A **workflow (aliran kerja)** is a defined sequence of steps — performed by people, systems, or a combination of both — that transforms an input into a desired output. In an office environment, workflows govern how work moves from one person or department to another until a task is complete.

**Examples of common office workflows in Malaysian SMEs:**

| Workflow | Trigger | Output |
|---|---|---|
| Invoice processing (Pemprosesan Invois) | Supplier sends invoice | Payment authorised and recorded |
| Leave application (Permohonan Cuti) | Employee submits request | Approved / rejected leave record |
| Purchase requisition (Permohonan Pembelian) | Department needs supplies | Purchase order issued |
| New employee onboarding (Penerimaan Pekerja Baru) | Staff confirmed | Completed onboarding checklist |
| Monthly report compilation (Penyediaan Laporan Bulanan) | Month-end | Management report submitted |

Understanding the current state of each workflow — who does what, in what sequence, and how long each step takes — is the essential first step before any automation can be designed.

### 1.2 Why Workflow Analysis Before Automation?

Deploying AI tools without first understanding existing workflows is a common and costly mistake. The risks include:

- **Automating inefficiency:** If the existing process has redundant steps, automating it simply executes those redundancies faster — the underlying problem remains.
- **Missing integration points:** AI tools must connect to existing systems (accounting software, email, HR platforms). Without mapping the workflow, connection gaps are discovered only after purchase.
- **User resistance:** When employees do not understand what they previously did and what the AI will replace, resistance to change is higher.
- **Misaligned expectations:** Management expects cost savings; without a baseline measurement, there is no way to demonstrate that savings were achieved.

The rule is: **document, then automate.**

## 2. Pemetaan Proses / Process Mapping

### 2.1 Flowcharts (Carta Alir)

The **flowchart (carta alir)** is the standard tool for documenting office workflows. Each symbol has a specific meaning:

| Symbol | Shape | Meaning |
|---|---|---|
| Start / End (Mula / Tamat) | Oval / Rounded rectangle | The beginning or end of a process |
| Process Step (Langkah Proses) | Rectangle | An action performed by a person or system |
| Decision Point (Titik Keputusan) | Diamond | A yes/no or if/else branch |
| Document (Dokumen) | Rectangle with wavy bottom | A document or form is created or used |
| Connector (Penghubung) | Circle | Continues the flow on another page |
| Arrow (Anak Panah) | Arrow line | Direction of flow |

**Standard flowchart tools available to trainees:**
- **Microsoft Visio** — included in Microsoft 365 subscriptions; most widely used in Malaysian corporate offices
- **Lucidchart** — cloud-based; free tier available; integrates with Google Workspace and Microsoft 365
- **draw.io / diagrams.net** — free and open-source; no account required; exports to PNG and PDF
- **Microsoft PowerPoint / Word SmartArt** — suitable for simple workflows; universally accessible

### 2.2 How to Draw a Workflow Flowchart — Step by Step

Follow these 6 steps to map any office workflow:

**Step 1 — Define the scope**
Identify the start event (trigger) and the end state (output). Example: start = "Customer calls to place order"; end = "Order confirmation sent to customer."

**Step 2 — List all steps in sequence**
Interview the person(s) who perform the workflow. Ask: "What do you do first? What do you do next? What happens if X is missing?" Write each action as a verb phrase.

**Step 3 — Identify decision points**
Look for any step where the answer determines two different paths. Example: "Is the invoice amount above RM5,000?" → Yes → requires Director approval; No → proceeds to accounts clerk.

**Step 4 — Assign roles (swim lanes)**
A **swim lane diagram (rajah lorong renang)** adds a horizontal lane for each role or department. Each step sits in the lane of the person responsible. This reveals where handoffs (pertukaran tangan) occur — these are common bottleneck and automation opportunity points.

**Step 5 — Add timing**
Note the time taken for each step (in minutes or hours). This data forms the baseline for ROI calculation later.

**Step 6 — Validate with stakeholders**
Walk through the completed flowchart with the actual process owner. Confirm sequence, decision points, and timing are accurate. Update based on feedback.

### 2.3 Worked Example — Leave Application Workflow in a Malaysian SME

The following is a simplified flowchart narrative for a typical manual leave application process:

```
[Employee] Fill in leave form (paper/email) → 5 min
    ↓
[Employee] Submit to direct supervisor → 0 min (walk / email)
    ↓
[Supervisor] Review leave balance? → Decision
    ├── No leave balance → Reject, notify employee → END
    └── Leave available →
        ↓
[Supervisor] Approve and sign form → 2 min
    ↓
[HR Clerk] Record in attendance register (Excel) → 10 min
    ↓
[HR Clerk] Notify payroll of approved leave → 5 min
    ↓
[Employee] Receives confirmation → END
```

**Total time per leave request: ~22 minutes (human effort) across 3 people**

With an AI-assisted HR platform (e.g., Kakitangan.com), this workflow is compressed to:
- Employee submits via mobile app → 1 min
- System auto-checks leave balance → 0 min (automatic)
- Supervisor approves in app → 1 min
- Attendance and payroll records updated automatically → 0 min

**Total time per leave request: ~2 minutes — an 91% reduction in administrative time.**

## 3. Mengenal Pasti Peluang Automasi / Identifying Automation Opportunities

### 3.1 Characteristics of Automation-Suitable Tasks

Not all office tasks are equally suitable for AI automation. Tasks that are strong candidates share these characteristics:

| Characteristic | Description | Office Example |
|---|---|---|
| **Repetitive (Berulang)** | Same steps performed many times per day/week | Data entry, filing, sending standard emails |
| **Rule-based (Berasaskan Peraturan)** | The output can be determined by clear if/then rules | Leave balance checks, invoice threshold approvals |
| **High volume (Jumlah Tinggi)** | Performed at scale — more volume = more time saved | Processing 100 invoices/month vs. 2 |
| **Structured data (Data Berstruktur)** | Input is a standard form, spreadsheet, or database field | Purchase order forms, payroll spreadsheets |
| **Low creativity requirement** | The task follows a standard template with minimal judgement | Sending payment reminders, generating standard reports |
| **Measurable output (Output Boleh Diukur)** | Success or failure is clearly defined | Invoice correctly matched to purchase order |

### 3.2 Tasks That Are NOT Good Automation Candidates

Equally important is knowing what NOT to automate:

| Task Type | Reason |
|---|---|
| Complex negotiations or conflict resolution | Requires nuanced human judgement and relationship management |
| Creative strategy decisions | AI can assist but the decision requires human accountability |
| Tasks with highly variable unstructured inputs | Handwritten notes, verbal instructions — AI accuracy drops significantly |
| Tasks requiring physical presence | Reception, maintenance inspections |
| One-off tasks that never repeat | Setup cost exceeds benefit |

### 3.3 The Automation Opportunity Matrix

Plot each identified task on this 2×2 matrix to prioritise:

```
                HIGH IMPACT ON BUSINESS
                        │
    ┌───────────────────┼───────────────────┐
    │   QUICK WINS      │   MAJOR PROJECTS  │
    │  Low effort,      │  High effort,     │
LOW │  High impact →    │  High impact →    │ HIGH
EFFORT│  Automate first  │  Plan carefully  │ EFFORT
    ├───────────────────┼───────────────────┤
    │   FILL-INS        │   AVOID           │
    │  Low effort,      │  High effort,     │
    │  Low impact →     │  Low impact →     │
    │  Automate if easy │  Deprioritise     │
    └───────────────────┼───────────────────┘
                        │
                LOW IMPACT ON BUSINESS
```

**Quick Wins** are the highest priority for a first AI automation project — they demonstrate value quickly with minimal risk.

## 4. Penilaian Jurang Kesediaan AI / AI Readiness Gap Analysis

### 4.1 What is an AI Readiness Gap Analysis?

An **AI Readiness Gap Analysis (Penilaian Jurang Kesediaan AI)** is a structured assessment that compares an organisation's current state against the minimum requirements for successful AI adoption. It identifies gaps that must be addressed before or during implementation.

The assessment covers five dimensions:

| Dimension | What is assessed |
|---|---|
| **Data (Data)** | Is the required data available, structured, and accessible? |
| **Technology (Teknologi)** | Are existing systems compatible with AI tools? What integrations are needed? |
| **People (Sumber Manusia)** | Do staff have the skills and willingness to use AI tools? |
| **Process (Proses)** | Are current workflows documented and stable enough to automate? |
| **Governance (Tadbir Urus)** | Are data privacy (PDPA 2010), security, and approval policies in place? |

### 4.2 AI Readiness Assessment Questionnaire

Use this questionnaire to assess each dimension. Score each item: **0 = Not in place, 1 = Partially in place, 2 = Fully in place.**

**Dimension 1: Data**
- [ ] Key business data (customer records, financial data, HR records) is stored digitally, not only on paper
- [ ] Data is stored in a consistent, structured format (e.g., Excel spreadsheet, accounting software database)
- [ ] There are clear data ownership and update responsibilities — someone is accountable for data accuracy
- [ ] There is a data backup process in place

**Dimension 2: Technology**
- [ ] Office computers have internet access and can install or access cloud applications
- [ ] The organisation uses a digital accounting system (AutoCount, SQL Accounting, or equivalent)
- [ ] Staff have company email accounts (preferably Microsoft 365 or Google Workspace)
- [ ] There is an IT support contact person (internal or outsourced) for troubleshooting

**Dimension 3: People**
- [ ] Management is supportive of AI adoption and willing to allocate time for staff training
- [ ] At least one staff member has basic computer literacy (file management, email, spreadsheets)
- [ ] Staff are informed about the planned AI adoption — no significant fear or hidden resistance identified
- [ ] There is a designated "AI Champion" (Juara AI) or change lead within the organisation

**Dimension 4: Process**
- [ ] At least the top 5 office workflows have been documented (flowchart or written SOP)
- [ ] SOPs (Standard Operating Procedures / Prosedur Operasi Standard) exist and are followed
- [ ] Process owners (the person responsible for each workflow) have been identified
- [ ] Workflow timing has been measured — there is a baseline for "how long things take now"

**Dimension 5: Governance**
- [ ] The organisation is aware of PDPA 2010 obligations regarding data collection and storage
- [ ] There is a basic data security policy — password protection, access controls
- [ ] There is a process for approving new software tools before purchase
- [ ] Staff understand they must not upload confidential client data into public AI tools

**Scoring:**
- 0–8: Low readiness — foundational work needed before AI adoption
- 9–16: Moderate readiness — proceed with low-risk Quick Wins while addressing gaps
- 17–24: High readiness — proceed with structured AI implementation roadmap (KP-03)
- 25–32: Excellent readiness — ready for full AI adoption programme

### 4.3 Gap Analysis Output Table

Document each identified gap using this format:

| Dimension | Gap Identified | Severity (H/M/L) | Remediation Action | Timeline |
|---|---|---|---|---|
| Data | Customer database is on paper files only | High | Digitise records into Google Sheets or AutoCount | 4 weeks |
| People | No staff trained in Microsoft 365 | Medium | Enrol 2 key staff in Microsoft 365 Fundamentals | 2 weeks |
| Governance | No PDPA policy documented | High | Draft and publish internal data handling policy | 2 weeks |

## 5. Pengukuran Kos Masa / Time-Cost Measurement

### 5.1 Why Measure Time Cost?

Before a business can evaluate whether AI automation is worthwhile, it must establish a **baseline time cost** for each target workflow. This data feeds directly into the ROI calculation covered in KP-03.

### 5.2 Time-Cost Calculation Formula

```
Monthly Time Cost (hours) = Time per occurrence (hours) × Frequency per month (occurrences)

Monthly Labour Cost (MYR) = Monthly Time Cost (hours) × Effective Hourly Rate (MYR/hour)

Effective Hourly Rate = Monthly Gross Salary ÷ Monthly Working Hours
```

**Malaysian context — Monthly Working Hours:**
Standard working hours under the Employment Act 1955: 8 hours/day × 26 working days = 208 hours/month (for a standard 5-day week with Saturday off).

### 5.3 Worked Example — Invoice Processing Cost

**Scenario:** An accounts clerk at a Malaysian trading SME processes supplier invoices. Current manual process:
- Receive invoice by email or physical copy
- Key invoice details into AutoCount (vendor, amount, date, GL account, payment terms)
- Match to Purchase Order in AutoCount
- File physical copy in folder; save PDF scan to shared drive

**Time per invoice: 12 minutes (0.2 hours)**
**Volume: 80 invoices per month**
**Accounts clerk salary: RM2,800/month gross**

| Calculation | Value |
|---|---|
| Effective hourly rate | RM2,800 ÷ 208 = **RM13.46/hour** |
| Monthly time on invoice processing | 0.2 hours × 80 = **16 hours/month** |
| Monthly labour cost of this task | 16 × RM13.46 = **RM215.38/month** |
| Annual labour cost of this task | RM215.38 × 12 = **RM2,584.56/year** |

With an AI-assisted OCR invoice processing tool (e.g., Dext), processing time drops to ~2 minutes per invoice — an 83% reduction.

| Post-Automation | Value |
|---|---|
| Monthly time on invoice processing | 0.033 hours × 80 = **2.67 hours/month** |
| Monthly labour cost | 2.67 × RM13.46 = **RM35.94/month** |
| **Monthly saving** | **RM179.44/month → RM2,153.28/year** |

This baseline forms the foundation for the ROI calculation in KP-03.

## 6. Alat Pemetaan Proses / Process Mapping Tools

### 6.1 Microsoft Visio — Step-by-Step Guide

Microsoft Visio is included in Microsoft 365 Business Standard and above subscriptions, which are widely used in Malaysian corporate environments.

**To create a basic flowchart in Visio:**
1. Open Visio → Select "Basic Flowchart" template
2. From the Shapes panel (left side), drag a **Start** oval onto the canvas
3. Label the oval with the trigger event (e.g., "Employee submits leave request")
4. Drag a **Process** rectangle and connect it with an arrow to the start oval
5. Label the rectangle with the first action step
6. For decision points, drag a **Diamond** shape and add Yes/No labels to the branching arrows
7. Continue until the End oval is reached
8. Add swim lanes: **View → Task Panes → Shapes → "Cross-Functional Flowchart"** template includes swim lanes
9. Save as .vsdx; export as PDF or PNG for sharing

**Shortcut:** Select a shape on the canvas and press the **blue arrow** that appears — Visio will automatically create and connect a new shape of the same type.

### 6.2 Lucidchart — Step-by-Step Guide

Lucidchart is accessible from any browser at lucidchart.com. The free tier allows up to 3 active documents.

1. Sign in → New Document → Select "Flowchart" template
2. Click the "+" icon on any shape in the canvas to auto-generate the next connected shape
3. Use the left panel to search for shapes: type "flowchart" to filter to standard flowchart symbols
4. Double-click any shape to add label text
5. Drag the grey handles to resize shapes
6. Right-click → "Insert Row" in a swim lane table to add additional roles
7. Share → "Share Link" → set to "Anyone with link can view" to share with trainer or management
