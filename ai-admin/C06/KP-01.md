## 1. What Is Business Intelligence (Perisikan Perniagaan)?

### 1.1 Definition

**Business Intelligence (BI)** is the process of collecting, organising, and visualising business data so that decision-makers can understand what has happened, why it happened, and what is likely to happen next. BI transforms raw numbers — sales figures, expense records, headcount data — into charts, dashboards, and reports that management can read at a glance.

For a Malaysian SME with limited analytical staff, BI tools with built-in AI features serve as a "virtual analyst" — identifying trends, flagging anomalies, and suggesting interpretations without requiring the user to write complex formulas or code.

| BI Function | What It Does | Example |
|---|---|---|
| **Descriptive** | Summarises what happened | "Revenue this month was RM 142,500" |
| **Diagnostic** | Explains why it happened | "Revenue dropped because East Region sales fell 18%" |
| **Predictive** | Forecasts what may happen | "At current rate, Q4 revenue will reach RM 560,000" |
| **Prescriptive** | Recommends what to do | "Increase promotion spend in underperforming region" |

### 1.2 BI in the Malaysian SME Context

Malaysian SMEs generate data every day — invoices from AutoCount, attendance records from Kakitangan.com, customer orders from Shopee — but most of this data sits in separate systems and is never combined for analysis. A BI tool acts as the bridge that pulls these sources together and presents the combined picture.

Key benefits for Malaysian SME office administrators:

- Reduce time spent on monthly report preparation from hours to minutes
- Enable management to spot declining sales regions or rising expense categories early
- Produce professional management reports in formats that satisfy bank, investor, and auditor requirements
- Support compliance with PDPA 2010 by controlling who can view sensitive financial dashboards

## 2. Microsoft Power BI

### 2.1 Overview

**Microsoft Power BI** is a Business Intelligence and data visualisation platform developed by Microsoft. It is available in three editions:

| Edition | Cost | Best For |
|---|---|---|
| **Power BI Desktop** | Free (Windows app) | Building and designing reports on a local machine |
| **Power BI Service** | Free tier available; Pro at ~USD 10/user/month | Publishing and sharing reports via browser |
| **Power BI Premium** | Higher tier for enterprise | Large-scale deployment; AI-enhanced features |

For trainees and Malaysian SMEs at Level 3, **Power BI Desktop + Power BI Service free tier** is sufficient for all tasks in this CU.

### 2.2 Core Power BI Concepts

| Term | Malay Equivalent | Meaning |
|---|---|---|
| **Dataset (Kumpulan Data)** | Kumpulan Data | The raw data source connected to Power BI (e.g., an Excel file) |
| **Report (Laporan)** | Laporan | A collection of visualisations built from one or more datasets |
| **Dashboard (Papan Pemuka)** | Papan Pemuka | A single-page view of key visuals pinned from one or more reports |
| **Visual (Visual)** | Visual | A single chart, table, card, or map on the report canvas |
| **Measure (Ukuran)** | Ukuran | A calculated value (e.g., Total Revenue = SUM of all sales) |
| **Filter (Penapis)** | Penapis | Limits what data is shown (e.g., filter to one region or month) |
| **Slicer (Pemilih)** | Pemilih | An interactive filter element that the report reader can click |

### 2.3 AI Features in Power BI

#### 2.3.1 Q&A Natural Language Query

Power BI's **Q&A feature** allows users to type a question in plain English (or Malay) and receive a visual answer automatically. The AI interprets the question and selects the most appropriate chart type.

**Example questions:**

```
What is total revenue by month?
Show sales by region as a bar chart
Which product category has the highest profit margin?
Compare this quarter revenue to last quarter
```

The system reads your data fields and generates the appropriate visual in seconds — no formula writing required.

#### 2.3.2 Copilot for Power BI

**Copilot for Power BI** (available in Power BI Premium / Pro) allows users to:

- Type a description of the report they want and have Copilot generate a full report layout
- Ask "Summarise this report" and receive a written narrative of the key findings
- Request "Create a measure for gross profit margin" and have the DAX formula written automatically
- Use "Smart Narrative" to auto-generate a text summary that updates when filters are changed

#### 2.3.3 Quick Insights

**Quick Insights** scans a dataset and automatically detects statistical patterns — outliers, correlations, trends, and clusters. Users right-click a dataset in Power BI Service and select "Get quick insights" to receive a gallery of suggested visualisations based on what the AI found interesting in the data.

#### 2.3.4 Anomaly Detection

Power BI's **Anomaly Detection** feature monitors a time-series line chart and highlights data points that deviate significantly from expected patterns. This is particularly useful for:

- Flagging months where expenses spiked unexpectedly
- Identifying weeks where sales dropped below normal range
- Detecting data entry errors (e.g., a transaction recorded as RM 5,000 when it should be RM 500)

### 2.4 Connecting Power BI to Malaysian SME Data Sources

Power BI can connect to over 100 data sources. The most relevant for Malaysian SMEs:

| Data Source | Connection Method | Common Use |
|---|---|---|
| **Microsoft Excel (.xlsx)** | Get Data → Excel | Most common; AutoCount/SQL Accounting exports to Excel |
| **CSV file (.csv)** | Get Data → Text/CSV | Quick import of transaction logs |
| **Google Sheets** | Get Data → Google Sheets connector | Cloud-based SME data |
| **SharePoint List** | Get Data → SharePoint Online List | Office 365 users |
| **SQL Server / MySQL** | Get Data → Database | Larger SMEs with their own database |
| **Web (URL)** | Get Data → Web | Live data feeds, public datasets |

> **Practical note:** AutoCount Accounting exports monthly transaction reports to Excel. SQL Accounting exports general ledger and transaction history as CSV. Both formats import directly into Power BI with no conversion needed.

### 2.5 Building a Report in Power BI — Step Summary

1. **Get Data** — connect to your data source (Excel/CSV)
2. **Transform Data (Power Query)** — clean column names, remove blank rows, set data types
3. **Build Visuals** — drag fields onto the report canvas; select chart type from Visualisations pane
4. **Add Slicers** — drag a date or category field to act as an interactive filter
5. **Publish** — publish to Power BI Service for sharing via browser link

## 3. Google Looker Studio

### 3.1 Overview

**Google Looker Studio** (formerly Google Data Studio) is Google's free, browser-based BI and reporting tool. It is accessible at **lookerstudio.google.com** and requires only a Google account — making it particularly accessible for Malaysian SMEs already using Google Workspace.

| Feature | Google Looker Studio | Microsoft Power BI Desktop |
|---|---|---|
| **Cost** | Completely free | Free (Desktop); paid for sharing features |
| **Installation** | None — browser-based | Windows application required |
| **Google Sheets connection** | Native, real-time | Via connector (slightly complex) |
| **Excel / CSV** | Upload or connect via Google Sheets | Native direct connection |
| **Collaboration** | Real-time collaboration (like Google Docs) | Collaboration via Power BI Service (requires account) |
| **AI features** | Limited (Looker ML integration at enterprise level) | More extensive (Copilot, Q&A, Quick Insights) |
| **Best for** | Quick sharing, Google ecosystem users | Deeper analysis, Microsoft 365 users |

### 3.2 Key Features of Looker Studio

**Data Connectors:**
Looker Studio connects to over 800 data sources through native and partner connectors:

- Google Sheets (native — most common for Malaysian SMEs)
- Google Analytics 4
- YouTube Analytics
- BigQuery (for large datasets)
- MySQL / PostgreSQL
- CSV file upload
- Facebook Ads, Google Ads (via partner connectors)

**Visual Components:**
Looker Studio provides the following visual types:

| Visual Type | Malay Name | Best Use |
|---|---|---|
| Time series chart | Carta siri masa | Revenue or expense trends over time |
| Bar / column chart | Carta bar | Comparing categories (products, regions) |
| Pie / donut chart | Carta pai | Proportion breakdown (expense by category) |
| Scorecard | Kad skor | Displaying a single KPI number prominently |
| Table | Jadual | Detailed data with multiple columns |
| Geo map | Peta geografi | Sales by state/country |
| Bullet chart | Carta peluru | KPI vs. target comparison |

**Sharing and Embedding:**
Reports can be shared via a link, embedded in websites, or scheduled for automatic email delivery — making it easy to send management reports on a regular basis without manual effort.

### 3.3 Connecting Looker Studio to Google Sheets

The most common Malaysian SME workflow:

1. Keep business data in a Google Sheet (e.g., monthly sales log)
2. In Looker Studio, click **Add data → Google Sheets**
3. Select the spreadsheet and the sheet tab
4. The data appears as fields ready to use in visuals
5. When the Google Sheet is updated, Looker Studio visuals update automatically (near real-time)

This "live connection" means a dashboard built once in Looker Studio reflects the latest data without rebuilding the report.

## 4. Dashboard Design Principles (Prinsip Reka Bentuk Papan Pemuka)

### 4.1 The Three Core Principles

A BI dashboard is only valuable if the reader can understand it quickly. Three principles govern good dashboard design:

#### 4.1.1 Clarity (Kejelasan)

- Every visual must have a title that states exactly what it shows
- Avoid decorative elements that add no information (unnecessary gridlines, 3D effects, gradients)
- Use plain language in labels — "Monthly Revenue (RM)" not "Aggregated Gross Receipts Value"
- If a number needs explanation, add a text annotation or tooltip

#### 4.1.2 Visual Hierarchy (Hierarki Visual)

Place information in order of importance:

| Position | Content | Reason |
|---|---|---|
| **Top left** | Most important KPI (e.g., total revenue) | Eye naturally starts top-left |
| **Top centre / right** | Secondary KPIs (e.g., expenses, headcount) | Supporting context |
| **Middle** | Primary chart (trend line or bar chart) | Largest element draws most attention |
| **Bottom** | Detail tables or secondary breakdowns | Reader drills down after seeing summary |

#### 4.1.3 Colour (Warna)

| Colour Use | Rule |
|---|---|
| **Highlight positive** | Green for above-target values |
| **Highlight negative** | Red for below-target or declining values |
| **Neutral background** | White or light grey — never dark backgrounds for print |
| **Limit palette** | Maximum 4–5 colours in one dashboard |
| **Accessibility** | Avoid red-green combinations for colourblind readers; add labels |

### 4.2 Dashboard Anti-Patterns to Avoid

| Anti-Pattern | Why It Fails |
|---|---|
| More than 10 visuals per page | Overwhelms the reader; nothing stands out |
| Pie charts with more than 5 segments | Too many slices become unreadable |
| Bar charts without sorted order | Comparison is difficult when bars are unsorted |
| Missing data labels on key visuals | Reader cannot read exact values from the chart |
| Inconsistent number formats | Mixing "RM 1,000" and "1000" in the same dashboard |

### 4.3 Worked Example: Dashboard Layout for Syarikat Mentari Raya Sdn Bhd

*Note: Syarikat Mentari Raya Sdn Bhd is a fictional company created solely for teaching purposes. All data below is fabricated for illustration.*

**Scenario:** Syarikat Mentari Raya Sdn Bhd is a fictional electrical goods wholesaler based in Shah Alam. The admin team is asked to build a management dashboard for the Operations Director using the company's 12-month sales and expense data (January–December 2025).

**Fictional Dataset — Syarikat Mentari Raya Sdn Bhd (2025):**

| Month | Revenue (RM) | Expenses (RM) | Gross Profit (RM) | Sales Staff | Region |
|---|---|---|---|---|---|
| Jan | 98,000 | 72,000 | 26,000 | 5 | Central |
| Feb | 105,000 | 75,000 | 30,000 | 5 | Central |
| Mar | 112,000 | 78,000 | 34,000 | 6 | Central |
| Apr | 118,000 | 80,000 | 38,000 | 6 | North |
| May | 125,000 | 82,000 | 43,000 | 6 | North |
| Jun | 130,000 | 85,000 | 45,000 | 7 | Central |
| Jul | 122,000 | 88,000 | 34,000 | 7 | Central |
| Aug | 115,000 | 86,000 | 29,000 | 7 | East |
| Sep | 128,000 | 84,000 | 44,000 | 7 | East |
| Oct | 135,000 | 87,000 | 48,000 | 8 | Central |
| Nov | 142,500 | 90,000 | 52,500 | 8 | Central |
| Dec | 150,000 | 92,000 | 58,000 | 8 | Central |
| **TOTAL** | **1,480,500** | **999,000** | **481,500** | — | — |

**Verification of totals:**
- Revenue: 98,000 + 105,000 + 112,000 + 118,000 + 125,000 + 130,000 + 122,000 + 115,000 + 128,000 + 135,000 + 142,500 + 150,000 = **1,480,500** ✓

## 5. Choosing Between Power BI and Looker Studio

| Criteria | Choose Power BI | Choose Looker Studio |
|---|---|---|
| **Office suite** | Uses Microsoft 365 | Uses Google Workspace |
| **Data source** | AutoCount / SQL Accounting exports | Google Sheets primary source |
| **AI features needed** | Yes — Copilot, Q&A, Quick Insights | No — basic visualisation sufficient |
| **Budget** | Willing to pay for Pro features | Free only |
| **Team skill** | Comfortable with Windows applications | Prefers browser-based tools |
| **Sharing** | Internal team via Power BI Service | External sharing via link |

> For Malaysian SMEs with mixed environments, a common approach is to use **Looker Studio for quick sharing** (e.g., weekly dashboard sent to the owner) and **Power BI Desktop for deeper analysis** (e.g., quarterly deep-dive reports).

## 6. Data Privacy Considerations When Using BI Tools

When building dashboards that contain employee, customer, or financial data, PDPA 2010 obligations apply:

| Obligation | Practical Action |
|---|---|
| **Access control** | Set Power BI row-level security (RLS) so each manager only sees their own department's data |
| **No personal data in public dashboards** | Never publish a dashboard with employee names, IC numbers, or customer contact details |
| **Data retention** | Connected datasets must follow the company's data retention policy |
| **Third-party sharing** | Do not use an uncontracted third-party BI service to host confidential financial data |
