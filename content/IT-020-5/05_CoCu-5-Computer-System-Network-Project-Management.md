| Type / Framework | Description |
|------------------|-------------|
| PMI / PMBOK framework | The Project Management Institute's Body of Knowledge provides a standard framework for managing projects through five process groups: initiating, planning, executing, monitoring and controlling, and closing. Covers ten knowledge areas including scope, schedule, cost, quality, resource, communication, risk, procurement, stakeholder, and integration management. Used as the reference standard for IT project management. |
| Work breakdown structure (WBS) | A hierarchical decomposition of the project scope into manageable work packages. Each package has a defined deliverable, duration, resource assignment, and cost estimate. The WBS is the foundation for the project schedule (Gantt chart), cost baseline, and progress tracking. Changes to the WBS follow the change control process. |
| Network topology design | Selection and documentation of the physical and logical layout of network nodes and links. Common topologies include star (central switch), bus (shared backbone), mesh (redundant paths), ring, tree, and hybrid. The choice affects performance, fault tolerance, scalability, and cost. Design tools (Visio, draw.io, or open-source alternatives) are used to produce network diagrams. |
| Risk management process | Identification of project risks (cost overrun, scope creep, resource shortfall, technology immaturity, regulatory change, legal issues), assessment of probability and impact, development of response plans (avoid, mitigate, transfer, accept), and ongoing monitoring. A risk register is maintained and reviewed at each project meeting. |
| Procurement and vendor management | The process of sourcing, evaluating, and contracting vendors for hardware, software, ISP services, and outsourced work. Includes tender preparation, evaluation criteria, contract negotiation, SLA definition, and vendor performance monitoring. Government projects may use e-Perolehan. All procurement documents are retained for audit. |
| Change control | A formal process for evaluating, approving, and implementing changes to project scope, schedule, cost, or quality. All change requests are logged, assessed for impact, approved by the project manager or steering committee, and communicated to the team. Prevents scope creep and ensures project baselines remain accurate. |

| Management Framework / Tool | Description |
|------------------------------|-------------|
| Project initiation and kick-off | The formal start of a project: defining objectives, scope, stakeholders, and project organisation. A kick-off meeting aligns all parties on expectations, deliverables, timeline, and communication plan. The project charter or initiation document is the output, authorising the project manager to proceed and allocate resources. |
| Gantt chart and scheduling tools | Visual representation of the project schedule showing tasks, durations, dependencies, milestones, and resource assignments on a timeline. Produced using tools such as Microsoft Project, GanttProject, or open-source alternatives. The Gantt chart is the primary tool for tracking progress, identifying delays, and communicating status to stakeholders. |
| Project monitoring and control | Ongoing activities to track project performance against the plan: scope control (preventing scope creep), cost control (budget vs actual), schedule control (milestone tracking), quality control (testing results), and resource control (utilisation and availability). Status is reported through regular project meetings and progress reports. |
| Testing strategy (stress, UAT, PENTEST) | A structured approach to verifying the network meets requirements. Includes stress test (capacity under load), reliability test (uptime over time), burning test (hardware stress), availability test, usability test, penetration test (PENTEST, security validation), user acceptance test (UAT), and final acceptance test. Test plans, results, and defect logs are documented. |
| Knowledge management and lessons learned | The practice of capturing, organising, and sharing project knowledge for future reference. Includes best practice documentation (what worked well) and lessons learned (what to improve). Conducted during project closure and stored in the organisational knowledge base. Reduces repeated mistakes and accelerates future projects. |
| Process improvement (BPR, BPA, BPI) | Business Process Re-engineering (BPR) for fundamental redesign, Business Process Automation (BPA) for automating repetitive tasks, and Business Process Improvement (BPI) for incremental enhancement. Applied during project execution to optimise network operations, reduce manual effort, and improve service quality. Improvement initiatives are documented and measured. |

| Project Tool / Software | Description |

| Network design tools (Visio, draw.io) | Software for creating network topology diagrams, rack layouts, and cable maps. Licensed tools (Microsoft Visio) offer templates and integration with documentation suites. Open-source alternatives (draw.io, Dia) provide basic diagramming at no cost. Diagrams are version-controlled and included in project documentation. |
| Project management software | Tools for creating WBS, Gantt charts, resource plans, and tracking progress. Examples include Microsoft Project, Primavera, Jira, and open-source alternatives (OpenProject, ProjectLibre). Support collaboration, reporting, and integration with other enterprise tools. |
| Network testing tools | Hardware and software for validating network performance and security. Includes cable testers, protocol analysers (Wireshark), load generators (iPerf), vulnerability scanners (Nessus, OpenVAS), and penetration testing frameworks (Kali Linux, Metasploit). Results are documented in test reports. |
| Collaboration and documentation platforms | Tools for project team communication, document management, and knowledge sharing (e.g. Microsoft Teams, Confluence, SharePoint). These platforms centralise project documentation (meeting minutes, decision logs, change requests) and provide structured channels for stakeholder updates. Integration with project management tools enables linked notifications and automated status reporting. |


| Common Issue | Root Cause | Management Action |
|--------------|------------|-------------------|
| Project scope creep | Poor initial requirements definition; no formal change control; stakeholders adding features mid-project | Establish formal change control process; document and sign off scope at project initiation; assess impact of every change request before approval |
| Project cost overrun | Inaccurate estimation; unplanned procurement; vendor price changes; scope creep | Use detailed WBS for bottom-up estimation; include contingency in budget; track actual vs budget weekly; escalate variances early |
| Schedule delays and missed milestones | Resource shortfalls; dependency on vendor delivery; unrealistic timeline; poor task sequencing | Maintain resource-loaded schedule; identify critical path; manage vendor delivery dates in contract; conduct weekly progress reviews |
| Poor end-user adoption after roll-out | Insufficient user training; no awareness programme; user manual not developed or distributed | Plan end-user training as a project phase; develop user manual; conduct awareness programme before roll-out; collect feedback post-deployment |

## Employability Skills

This CoCu develops the following employability skills through the work activities:

### 1. Communication Skills
- **Mapping:** Present project proposals, progress reports, and closure summaries to senior management; prepare project documentation for stakeholder and compliance review; communicate project scope, timelines, and risk status to all project participants

### 2. Teamwork & Collaboration
- **Mapping:** Lead multi-disciplinary project teams including network engineers, vendors, and business stakeholders; collaborate with executive sponsors on scope and priority decisions; coordinate across organisational boundaries for multi-site deployments

### 3. Problem-solving
- **Mapping:** Address project risks including scope creep, resource conflicts, and technical obstacles; evaluate trade-offs between project timeline, cost, and quality; resolve issues escalated from project team members during implementation

### 4. Initiative & Self-reliance
- **Mapping:** Drive project milestones and deliverables proactively; make decisions on resource allocation and schedule adjustments; take responsibility for project outcomes including budget adherence and quality standards

### 5. Planning & Organizing
- **Mapping:** Develop project plans with WBS, Gantt charts, and resource allocation for system and network projects; organize procurement, installation, testing, and handover phases; manage project budgets, schedules, and change control processes

### 6. Self-management & Safety Awareness
- **Mapping:** Follow project governance and change control procedures; manage risk of project delays and budget overruns through monitoring and mitigation; ensure project deliverables meet security and compliance requirements

### 7. Technology Use & Technical Proficiency
- **Mapping:** Use project management tools (MS Project, Gantt charts, resource trackers) for planning and monitoring; understand system and network technologies sufficiently to validate technical deliverables; leverage reporting tools for project status and performance analysis

### 8. Learning Skills & Continuous Improvement
- **Mapping:** Stay informed on project management methodologies and IT project best practices; analyze project closure reports to identify lessons learned; improve estimation, planning, and risk management based on past project experience



## Attitude, Safety and Environmental

### Workplace Safety
- **Enterprise Risk Governance:** Establish and maintain governance frameworks that identify, assess, and mitigate IT-related risks at the organisational level. Ensure compliance with regulatory requirements and industry standards (ISO 27001, COBIT, ITIL).
- **Change Management at Scale:** Implement formal change management processes that balance innovation with stability; ensure all significant infrastructure changes are reviewed, approved, and documented for organisational accountability.
- **Cybersecurity Leadership:** Foster a culture of security awareness throughout the organisation; establish policies and procedures that protect critical systems, data, and intellectual property from threats.
- **Crisis Preparedness:** Develop and maintain disaster recovery and business continuity plans that protect the organisation's ability to operate during emergencies.

### Environmental Considerations
- **Sustainable IT Strategy:** Develop long-term IT strategies that consider environmental impact; promote energy-efficient infrastructure, virtualisation, and cloud solutions that reduce organisational carbon footprint.
- **Responsible Technology Governance:** Establish policies for responsible technology use, data privacy, and ethical IT practices that align with organisational values and community expectations.

### Professional Attitudes
- **Strategic Integrity:** Make decisions based on long-term organisational benefit; resist short-term pressures that could compromise system stability, security, or sustainability.
- **Visionary Leadership:** Champion innovation and emerging technologies while balancing risk; inspire teams to think strategically about technology's role in organisational success.
- **Stakeholder Trust:** Maintain credibility with executive leadership, boards, and external partners through transparent communication, ethical conduct, and delivery of promised results.
- **Continuous Improvement Culture:** Foster an environment where teams continuously learn from experiences, share knowledge, and improve processes to enhance organisational capability and competitiveness.
