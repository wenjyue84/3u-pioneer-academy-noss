## Tajuk / Title: Testing, Debugging and Publishing Interactive Multimedia

---

## 1. Objektif Pembelajaran / Learning Objectives

Selepas mempelajari Kertas Penerangan ini, pelatih akan dapat / After studying this Information Sheet, trainees will be able to:

1. Menerangkan jenis-jenis pengujian yang digunakan dalam pembangunan multimedia interaktif / Explain types of testing used in interactive multimedia development.
2. Menggunakan prosedur pengujian sistematik untuk mengenal pasti ralat / Use systematic testing procedures to identify errors.
3. Mengenal pasti dan membetulkan ralat biasa (bugs) dalam projek multimedia interaktif / Identify and correct common bugs in interactive multimedia projects.
4. Menerangkan format output dan platform penerbitan untuk produk multimedia interaktif / Explain output formats and publishing platforms for interactive multimedia products.
5. Menyediakan dokumentasi dan pakej penyerahan untuk projek multimedia interaktif yang lengkap / Prepare documentation and delivery package for a completed interactive multimedia project.

---

## 2. Kepentingan Pengujian / Importance of Testing

Pengujian (testing) adalah fasa kritikal dalam kitaran pembangunan multimedia interaktif. Tanpa pengujian yang menyeluruh, produk yang dihantar kepada klien atau pengguna mungkin mengandungi ralat yang menjejaskan pengalaman pengguna dan reputasi pembangun.

**Matlamat Pengujian:**
- Memastikan semua elemen interaktif berfungsi seperti yang dirancang.
- Mengesahkan kandungan adalah tepat dan bebas kesilapan.
- Memastikan keserasian dengan platform dan peranti sasaran.
- Mengesahkan prestasi (masa muat, kelancaran animasi).
- Memastikan aksesibiliti untuk semua pengguna.

---

## 3. Jenis-Jenis Pengujian / Types of Testing

### 3.1 Pengujian Fungsional / Functional Testing

Mengesahkan bahawa setiap elemen dan fungsi interaktif berfungsi dengan betul.

**Senarai semak pengujian fungsional / Functional testing checklist:**
- [ ] Semua butang berfungsi dan menghala ke destinasi yang betul
- [ ] Semua pautan (hyperlink) berfungsi
- [ ] Audio bermain dengan betul pada masa yang ditetapkan
- [ ] Video dipaparkan dan bermain dengan betul
- [ ] Animasi berjalan dengan lancar
- [ ] Kuiz/soalan menerima jawapan dan memberikan maklum balas yang betul
- [ ] Skor dikira dengan tepat
- [ ] Navigasi kembali (back) berfungsi
- [ ] Semua gambar dipaparkan

### 3.2 Pengujian Kebolehgunaan / Usability Testing

Menilai kemudahan penggunaan produk daripada perspektif pengguna sebenar.

**Kaedah Pengujian Kebolehgunaan:**

| Kaedah | Penerangan |
|--------|------------|
| **Think Aloud** | Pengguna menyebut fikiran mereka semasa menggunakan produk / User verbalises thoughts while using product |
| **Task Completion** | Pengguna diminta melengkapkan tugasan tertentu; masa dan ralat direkod / Users asked to complete specific tasks |
| **A/B Testing** | Dua versi berbeza diuji dengan kumpulan pengguna berbeza / Two different versions tested with different user groups |
| **Heuristic Evaluation** | Pakar menilai antara muka berdasarkan senarai heuristik / Expert evaluates interface against heuristics list |
| **Eye Tracking** | Rekod pergerakan mata pengguna untuk memahami corak pandangan / Records eye movement to understand viewing patterns |

### 3.3 Pengujian Silang-Pelayar / Cross-Browser Testing

Memastikan produk multimedia berfungsi dengan betul pada pelbagai pelayar web.

**Pelayar yang perlu diuji / Browsers to test:**
- Google Chrome (versi terkini dan N-1)
- Mozilla Firefox (versi terkini)
- Microsoft Edge (versi terkini)
- Apple Safari (untuk pengguna macOS/iOS)
- Mobile browsers (Chrome Mobile, Safari Mobile)

**Aspek yang perlu diuji / Aspects to test:**
- Paparan visual (layout, warna, fon)
- Fungsi JavaScript
- Pemutaran audio dan video
- Animasi CSS dan Canvas

### 3.4 Pengujian Prestasi / Performance Testing

Menilai kelajuan pemuatan dan responsif produk multimedia.

| Metrik | Nilai Disyorkan | Alat Pengujian |
|--------|-----------------|----------------|
| **Masa Muat Halaman / Page Load Time** | < 3 saat | Google PageSpeed Insights |
| **Masa hingga Interaktif / Time to Interactive** | < 5 saat | Lighthouse (Chrome DevTools) |
| **Saiz Fail Output / Output File Size** | Minimum yang wajar | Analisis manual |
| **Kadar Bingkai Animasi / Animation Frame Rate** | 60 fps | Chrome DevTools Performance |

### 3.5 Pengujian Aksesibiliti / Accessibility Testing

Memastikan produk boleh digunakan oleh semua pengguna, termasuk mereka yang mempunyai keperluan khas.

**Piawaian aksesibiliti / Accessibility standards:** WCAG 2.1 (Web Content Accessibility Guidelines)

**Aspek aksesibiliti utama / Key accessibility aspects:**
- Teks alternatif (alt text) untuk semua imej
- Kontras warna mencukupi (minimum 4.5:1)
- Navigasi boleh menggunakan papan kekunci
- Teks kapsyen (captions) untuk video
- Tidak bergantung pada warna sahaja untuk menyampaikan maklumat

---

## 4. Prosedur Pengujian Sistematik / Systematic Testing Procedure

### 4.1 Pelan Pengujian / Test Plan

Sebelum memulakan pengujian, sediakan pelan pengujian yang mengandungi:
1. Skop pengujian — apakah yang akan diuji
2. Persekitaran pengujian — peranti, pelayar, OS yang akan digunakan
3. Kes ujian (test cases) — senario ujian yang spesifik
4. Kriteria lulus/gagal — bagaimana menentukan sama ada ujian lulus

### 4.2 Borang Laporan Pepijat / Bug Report Form

Setiap pepijat yang ditemui hendaklah dilaporkan menggunakan format berikut:

| Medan | Penerangan |
|-------|------------|
| **ID Pepijat** | Nombor unik untuk pepijat / Unique bug number |
| **Tarikh Ditemui** | Tarikh pepijat dikenal pasti / Date bug identified |
| **Penguji** | Nama penguji / Tester name |
| **Penerangan** | Penerangan jelas tentang pepijat / Clear description of bug |
| **Langkah Replikasi** | Cara untuk menghasilkan semula pepijat / Steps to reproduce the bug |
| **Keputusan Dijangka** | Apa yang sepatutnya berlaku / What should happen |
| **Keputusan Sebenar** | Apa yang sebenarnya berlaku / What actually happened |
| **Keterukan** | Kritikal / Tinggi / Sederhana / Rendah |
| **Status** | Terbuka / Dalam pembaikan / Selesai |

## 5. Penyahpepijatan (Debugging) / Debugging

### 5.1 Ralat Biasa dan Penyelesaian / Common Errors and Solutions

#### Ralat Navigasi / Navigation Errors
| Masalah | Punca | Penyelesaian |
|---------|-------|--------------|
| Butang tidak berfungsi | Trigger tidak ditetapkan / Trigger not set | Semak dan tetapkan trigger yang betul |
| Halaman salah dipaparkan | Nombor halaman / nama skrin salah / Wrong page number / scene name | Semak sasaran navigasi trigger |
| Navigasi menggelongsor / Navigation looping | Trigger mencipta gelung tak terhingga / Trigger creating infinite loop | Semak logik dan tambah syarat berhenti |

#### Ralat Media / Media Errors
| Masalah | Punca | Penyelesaian |
|---------|-------|--------------|
| Audio tidak bermain | Format tidak disokong / Unsupported format | Tukar format; semak sokongan pelayar |
| Video tidak dipaparkan | Codec tidak disokong / Unsupported codec | Encode semula sebagai H.264 MP4 |
| Imej tidak muncul | Laluan fail salah / Wrong file path | Betulkan laluan relatif fail |
| Media lambat dimuatkan | Fail terlalu besar / File too large | Optimalkan dan mampat aset |

#### Ralat Logik / Logic Errors
| Masalah | Punca | Penyelesaian |
|---------|-------|--------------|
| Skor tidak dikira dengan betul | Formula atau variable salah | Semak nilai pemboleh ubah dalam debugger |
| Maklum balas salah dipaparkan | Syarat logik terbalik / Inverted logic condition | Semak syarat benar/salah dalam trigger |

### 5.2 Alat Penyahpepijatan / Debugging Tools

| Alat | Perisian | Fungsi |
|------|---------|--------|
| **Preview Mode** | Adobe Animate, Storyline | Uji projek dalam persekitaran simulasi |
| **Output Window** | Adobe Animate | Papar mesej trace() dan ralat |
| **Chrome DevTools** | Google Chrome | Konsol JavaScript, pemeriksaan elemen, rangkaian |
| **Firefox Developer Tools** | Mozilla Firefox | Serupa dengan Chrome DevTools |
| **Variable Watcher** | Articulate Storyline | Pantau nilai pemboleh ubah semasa runtime |

## 6. Format Output dan Penerbitan / Output Formats and Publishing

### 6.1 Format Output Utama / Main Output Formats

| Format | Penerangan | Kegunaan Terbaik |
|--------|------------|-----------------|
| **HTML5** | Laman web standard; berjalan dalam pelayar / Standard webpage; runs in browser | Web deployment; kandungan dalam talian |
| **SCORM 1.2** | Piawaian e-pembelajaran lama / Older e-learning standard | LMS lama (Moodle, Blackboard) |
| **SCORM 2004** | Piawaian e-pembelajaran terkemaskini / Updated e-learning standard | LMS moden dengan sokongan SCORM 2004 |
| **xAPI (Tin Can)** | Piawaian penjejakan pembelajaran moden / Modern learning tracking standard | LRS (Learning Record Store); penjejakan lanjutan |
| **EXE (Windows)** | Fail boleh laku Windows / Windows executable file | Aplikasi desktop; kiosk tanpa internet |
| **APP (macOS)** | Aplikasi macOS | Kiosk macOS; distribusi desktop Apple |
| **APK (Android)** | Pakej aplikasi Android | Aplikasi mudah alih Android |
| **IPA (iOS)** | Pakej aplikasi iOS | Aplikasi mudah alih iOS |
| **PDF** | Dokumen mudah alih / Portable document | Output bukan interaktif; dokumentasi |

### 6.2 Prosedur Penerbitan dalam Adobe Animate / Publishing Procedure in Adobe Animate

1. **File → Publish Settings** — Buka tetapan penerbitan.
2. Pilih format output yang dikehendaki (HTML5 Canvas, AIR, dll.).
3. Tetapkan nama dan lokasi fail output.
4. Semak tetapan kualiti audio dan video.
5. Klik **Publish** — Fail output akan dihasilkan.
6. Uji fail output dalam persekitaran sasaran.

### 6.3 Prosedur Penerbitan dalam Articulate Storyline / Publishing in Articulate Storyline

1. **Home → Publish** — Buka panel penerbitan.
2. Pilih destinasi: **Web**, **Articulate 360**, **LMS**, **CD/DVD**, **Word**.
3. Pilih format piawaian e-pembelajaran jika relevan: SCORM 1.2 / SCORM 2004 / xAPI.
4. Tetapkan pilihan output (resolusi, kualiti, laporan LMS).
5. Klik **Publish** — Folder output dihasilkan.
6. Muat naik folder output ke LMS atau pelayan web.

## 7. Penyerahan Projek / Project Delivery

### 7.1 Pakej Penyerahan / Delivery Package

Pakej penyerahan projek multimedia interaktif yang lengkap mengandungi:

| Item | Penerangan |
|------|------------|
| **Fail Output Akhir** | Produk multimedia siap dalam format yang disepakati |
| **Fail Sumber** | Fail projek asal (FLA, STORY, dll.) untuk penyelenggaraan masa hadapan |
| **Pustaka Aset** | Semua fail media (audio, video, grafik) yang digunakan |
| **Manual Pengguna** | Panduan cara menggunakan produk (jika diperlukan) |
| **Panduan Teknikal** | Keperluan sistem, kaedah pemasangan, panduan penyelenggaraan |
| **Laporan Pengujian** | Rekod semua pengujian yang dijalankan dan keputusannya |
| **Dokumentasi Projek** | Peta struktur, carta alir, nota pembangunan |

### 7.2 Senarai Semak Penyerahan / Delivery Checklist

- [ ] Semua fungsi interaktif diuji dan berfungsi dengan betul
- [ ] Semua media dioptimumkan
- [ ] Pengujian silang-pelayar selesai
- [ ] Fail output dihasilkan dalam format yang dipersetujui
- [ ] Fail sumber disimpan dan disertakan
- [ ] Dokumentasi lengkap disediakan
- [ ] Hak cipta semua aset media dipatuhi
- [ ] Klien / pensyarah meluluskan produk akhir

---

## 9. Rumusan / Summary

Pengujian dan penyahpepijatan adalah fasa kritikal yang memastikan produk multimedia interaktif berfungsi seperti yang dirancang, mudah digunakan, dan serasi dengan platform sasaran. Empat jenis pengujian utama — fungsional, kebolehgunaan, silang-pelayar, dan prestasi — mesti dijalankan secara sistematik menggunakan pelan pengujian dan borang laporan pepijat. Setelah semua pepijat dibetulkan, produk diterbitkan dalam format yang sesuai — HTML5 untuk web, SCORM untuk LMS, atau EXE untuk aplikasi desktop. Pakej penyerahan yang lengkap mengandungi fail output, fail sumber, pustaka aset, dan dokumentasi projek.
