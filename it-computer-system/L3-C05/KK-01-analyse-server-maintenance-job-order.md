## Objektif / Objectives

By the end of this activity, the trainee will be able to:
1. Read and interpret a server maintenance job order accurately.
2. Identify the scope of maintenance work required (hardware and/or OS).
3. Verify server details against inventory records.
4. Prioritise and schedule maintenance tasks based on urgency and downtime constraints.
5. Document findings and obtain supervisor sign-off before proceeding.

## Langkah Keselamatan / Safety Precautions

- This is a planning and documentation exercise; no live server access is required.
- Handle all job order documents with care; do not alter or annotate the original form.
- Treat simulated system information as confidential — do not share outside the classroom.
- If any server described in the job order is marked as a production/critical system, flag this to the instructor before proceeding.

## Prosedur / Procedure

| Langkah / Step | Arahan / Instruction |
|----------------|----------------------|
| 1 | Receive the simulated job order from the instructor. Read the entire document from start to finish without skipping any section. Note the job order number, date raised, and requesting department. |
| 2 | Identify the server(s) listed in the job order. Record the hostname, IP address, server model, and serial number as stated. Cross-check each entry against the inventory record to confirm the asset exists and details match. |
| 3 | Extract the reported symptoms or maintenance tasks listed in the job order (e.g., "server fans generating abnormal noise", "OS patch update required", "RAID array showing degraded status"). List each task separately. |
| 4 | Classify each task by category: (a) Hardware maintenance, (b) OS/software maintenance, or (c) both. Record the classification next to each task. |
| 5 | Assess the urgency of each task using the following scale: Critical (system down or at risk), High (degraded performance), Medium (scheduled preventive), Low (cosmetic/non-impacting). Record the urgency rating for each task. |
| 6 | Identify the maintenance window stated in the job order (permitted downtime period). If no window is stated, note this as an open issue requiring clarification from the requestor. |
| 7 | List all tools, replacement parts, and access credentials (e.g., iDRAC/iLO password, OS admin account) required to complete the work. Mark any items that are unavailable as "to be sourced". |
| 8 | Check whether the maintenance work requires a change request (CR) approval per organisational policy. If a CR is required, note the CR number or flag that one must be raised before work begins. |
| 9 | Prepare a maintenance work plan: sequence the tasks in logical execution order, estimate time for each task, and identify any dependencies (e.g., OS maintenance cannot begin until hardware replacement is complete). |
| 10 | Submit the completed analysis — including the inventory cross-check, task classification list, urgency ratings, work plan, and open issues — to the instructor for review and sign-off. |

---

## Hasil Dijangka / Expected Outcome

Upon completing this activity, the trainee will have produced:
- A verified server inventory cross-check confirming asset details.
- A classified and prioritised task list extracted from the job order.
- A documented maintenance work plan with task sequence and time estimates.
- A list of required tools, parts, and access credentials.
- All open issues (missing information, pending approvals) clearly identified.
