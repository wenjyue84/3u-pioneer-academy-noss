**Objektif / Objective:** Simulate project execution management by processing change requests, performing EVM analysis, resolving team conflicts, conducting a quality gate review, and producing a formal project status report.

**Arahan / Instructions:** Trainees are required to complete all tasks using the approved Project Management Plan from KK(2/4) as the input. Refer to KP(3/4) for reference. Consult the instructor if clarification is needed.

---

## Objektif / Objective

Apply project monitoring and control techniques — EVM, change control, issue management, quality gates, and stakeholder reporting — to manage a simulated mid-project execution scenario.

---

## Tempoh / Duration

12 hours (distributed across 3 sessions of 4 hours each)

## Senario / Scenario

**Situasi: Minggu 10 daripada 18 / Situation: Week 10 of 18**

The Prisma Teknologi Sdn. Bhd. headquarters network upgrade project is now at Week 10. The project manager has received the following information from the team and stakeholders:

**Data Prestasi / Performance Data (Week 10):**

| Item | Nilai / Value |
|------|---------------|
| Budget at Completion (BAC) | RM 450,000 (excluding management reserve) |
| % of work planned to be complete by Week 10 | 52% |
| % of work actually completed by Week 10 | 46% |
| Actual cost spent to date | RM 224,000 |

**Isu-isu / Issues Received:**

- **Isu 1:** The cabling contractor has reported that structured cabling on Floors 3 and 4 is behind by 6 working days due to unexpected concrete walls requiring additional conduit work. Floor 3 and 4 cabling is on the critical path.
- **Isu 2:** The core switches (2 units) were delivered with firmware version 17.3.1 instead of the specified minimum 17.6.x. The network engineer reports that the older firmware does not support the VLAN policy design.
- **Isu 3:** The HR Department Head has complained that she was not informed of a planned 4-hour network test on Wednesday morning that disrupted her team's work.

**Permintaan Perubahan / Change Requests Received:**

- **CR-001:** The IT Manager requests adding 15 additional IP phones to the scope (VoIP over PoE). Estimated cost: +RM 22,500. Estimated schedule impact: +5 days.
- **CR-002:** The Network Security Officer requests that all switch management interfaces be restricted to a dedicated out-of-band management VLAN. This is a design change with no additional cost and 2 days additional configuration effort.
- **CR-003:** The Finance Head requests early deployment of the file server (originally planned for Week 14) to Week 11 due to a month-end reporting requirement. No cost change; requires resequencing of activities.

**Senario Konflik / Conflict Scenario (Instructor-assigned card):**

The Network Engineer and the vendor's on-site technician disagree on the VLAN segmentation design. The Network Engineer insists on a flat Layer 3 design; the vendor proposes a hierarchical design using VSS (Virtual Switching System). Both parties are unwilling to compromise and the disagreement is causing a 2-day standstill in configuration work.

## Prosedur / Procedures

| Langkah | Arahan / Instruction |
|---------|---------------------|
| **1** | Using the performance data provided, calculate all EVM metrics: PV, EV, AC, SV, CV, SPI, CPI, EAC, VAC. Show all workings. Interpret each metric and state clearly whether the project is on track, behind schedule, over budget, or a combination. |
| **2** | Based on the EVM analysis, propose a corrective action plan. Identify which specific activities or areas you would investigate first. Describe the recovery strategy (crashing, fast tracking, or scope reduction) with specific actions, the estimated time/cost to recover, and the risks introduced by the recovery strategy. |
| **3** | Process all three change requests using the Change Control Process from KP(3/4). For each CR: (a) complete a Change Request Form, (b) perform an impact analysis (scope, schedule, cost, risk, quality), (c) make a CCB recommendation (Approve / Reject / Defer) with justification, and (d) if approved, update the schedule and budget baseline. |
| **4** | Log all three issues in the Issue Log. For each issue: (a) assess severity (High / Medium / Low), (b) identify root cause, (c) assign an owner, (d) propose a resolution action with target date, and (e) state whether escalation to the sponsor is required. |
| **5** | Address the conflict scenario between the Network Engineer and the vendor technician. (a) Identify which conflict resolution technique is most appropriate. (b) Facilitate a simulated 15-minute mediation session with classmates role-playing the parties. (c) Produce a written resolution agreement documenting the agreed technical approach and the rationale. |
| **6** | Review the communications failure identified in Issue 3 (HR Head not informed of network test). (a) Identify the gap in the Communications Management Plan. (b) Propose a revised communication protocol for planned maintenance or test windows. (c) Draft a formal apology communication to the HR Head from the Project Manager. |
| **7** | Conduct a simulated Quality Gate Review for the Pre-Implementation Gate. Using the Quality Gate Checklist template, assess whether the project has met all criteria to proceed from design/procurement to implementation. For any criteria not yet met, document the gap and the action required before proceeding. |
| **8** | Review the Risk Register from KK(2/4). Update the register based on the situation at Week 10: (a) change the status of any risks that have materialised, (b) revise probability/impact for any risks whose profile has changed, (c) add any new risks identified from the Week 10 situation, (d) close any risks no longer applicable. |
| **9** | Prepare a complete formal Project Status Report for Week 10 using the status report template. The report must include: Executive Summary with traffic light status, Milestone Status table, EVM performance table and trend interpretation, Top 3 Risks and Top 3 Issues, Change Request summary, Upcoming Activities (Weeks 11–12), and Decisions Required from the Sponsor. |
| **10** | Present the Week 10 Status Report to the class in a 15-minute simulated Steering Committee presentation. The instructor will role-play the project sponsor and ask questions. Respond to all questions confidently and factually. Incorporate feedback and submit the final status report. |

## Hasil Jangkaan / Expected Outcome

Upon completion of this Work Sheet, trainees shall produce:

1. EVM calculation table with all metrics, interpretations, and corrective action plan
2. Three completed Change Request Forms with impact analysis and CCB recommendations
3. Updated schedule and budget baseline (reflecting approved changes)
4. Issue Log with four entries (three given + any new from analysis) fully populated
5. Written conflict resolution agreement
6. Revised communication protocol and formal apology letter
7. Completed Quality Gate Checklist with gaps and actions
8. Updated Risk Register (Week 10 status)
9. Formal Week 10 Project Status Report
10. 15-minute Steering Committee presentation delivered
