**Objektif / Objective:** Conduct a structured requirements analysis for a computer system and network upgrade project, produce a Requirements Traceability Matrix (RTM), and present findings to stakeholders.

**Arahan / Instructions:** Trainees are required to complete all tasks according to the procedures in this Work Sheet. Refer to KP(1/4) for reference. Consult the instructor if clarification is needed.

## Objektif / Objective

Apply structured requirements elicitation and analysis techniques to produce a complete, validated, and prioritised requirements set for a computer system and network project.

## Senario / Scenario

**Nama Projek / Project Name:** Sistem Rangkaian Bersepadu Ibu Pejabat / Headquarters Integrated Network System

**Latar Belakang / Background:**

Syarikat Prisma Teknologi Sdn. Bhd. baru sahaja berpindah ke ibu pejabat baharu berkapasiti 350 pengguna. Infrastruktur rangkaian sedia ada adalah usang dan tidak mampu menyokong keperluan operasi masa kini. Pengurusan atasan telah meluluskan bajet sebanyak RM 500,000 untuk menaik taraf sepenuhnya infrastruktur sistem komputer dan rangkaian syarikat.

*(Prisma Teknologi Sdn. Bhd. has recently relocated to a new headquarters with capacity for 350 users. The existing network infrastructure is outdated and cannot support current operational requirements. Senior management has approved a budget of RM 500,000 for a full upgrade of the company's computer system and network infrastructure.)*

## Prosedur / Procedures

| Langkah | Arahan / Instruction |
|---------|---------------------|
| **1** | Read the project brief document thoroughly. Highlight all explicit and implicit requirements. List a minimum of 20 raw requirement statements before proceeding. |
| **2** | Classify each raw requirement into one of the four categories: Functional (F), Non-Functional (NF), Technical (T), or Business (B). Record your classification with justification for each. |
| **3** | Prepare an interview guide for TWO of the stakeholders listed above. Each guide must contain a minimum of 8 open-ended questions designed to elicit detailed, unambiguous requirements. |
| **4** | Conduct simulated stakeholder interviews with classmates role-playing the assigned stakeholders. Record all responses. Identify any new requirements or conflicts that emerge. |
| **5** | Resolve any conflicting requirements identified in Step 4. Document the conflict, the resolution approach used (e.g., escalation to sponsor, compromise), and the agreed resolution. |
| **6** | Apply MoSCoW prioritisation to all confirmed requirements. Justify each classification with reference to project objectives, budget, or stakeholder priority. |
| **7** | Validate each requirement against the four criteria: Complete, Consistent, Testable, and Achievable. Mark any requirements that fail validation and revise them. |
| **8** | Construct a Requirements Traceability Matrix (RTM) for all approved requirements. Each row must contain: Req ID, Requirement Statement, Source, Category, Priority (MoSCoW), Design Component (proposed), Acceptance Test (proposed), and Status. |
| **9** | Prepare a 10-minute stakeholder presentation summarising: (a) elicitation process used, (b) key requirements by category, (c) conflicts resolved, (d) top 5 Must Have requirements with acceptance criteria. |
| **10** | Present to the class (simulated stakeholder review). Respond to questions and incorporate any valid feedback into the RTM. Submit all documents to the instructor. |

---

## Hasil Jangkaan / Expected Outcome

Upon completion of this Work Sheet, trainees shall produce:

1. Requirements classification table (minimum 20 requirements, all four categories represented)
2. Two completed stakeholder interview guides with recorded responses
3. Conflict resolution log (minimum 1 resolved conflict)
4. MoSCoW prioritisation table with justifications
5. Validated RTM (all requirements meeting the four validation criteria)
6. 10-minute stakeholder presentation (slides or whiteboard)
