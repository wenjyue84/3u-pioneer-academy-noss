## Bahagian A: Soalan Pelbagai Pilihan / Section A: Multiple Choice (20 marks)

Answer all 10 questions. Each question carries 2 marks.

**A1.** A Requirements Traceability Matrix (RTM) serves primarily to:

- (a) Track the cost of each requirement
- (b) Link each requirement to its source, design component, and test case
- (c) Assign requirements to individual team members
- (d) Replace the project schedule

**A2.** Which requirement type describes the condition "System uptime must be ≥ 99.9% per month"?

- (a) Functional requirement
- (b) Technical requirement
- (c) Non-functional requirement
- (d) Business requirement

**A3.** In MoSCoW prioritisation, a "Could Have" requirement means:

- (a) The project will fail if this is not delivered
- (b) This requirement is explicitly excluded from the current project
- (c) This is a nice-to-have; it can be deferred if resources are constrained
- (d) This requirement must be delivered before any others

**A4.** The Joint Application Development (JAD) workshop technique is most valuable because it:

- (a) Replaces the need for individual stakeholder interviews
- (b) Brings multiple stakeholders together to resolve conflicting requirements quickly
- (c) Is the cheapest elicitation technique available
- (d) Only requires the project manager to attend

**A5.** Which of the following is an example of a Business requirement?

- (a) The server must have a minimum of 128 GB RAM
- (b) The system must comply with PDPA 2010 data classification requirements
- (c) The firewall must support deep packet inspection
- (d) Network latency within the LAN must not exceed 5 ms

**A6.** A requirement that states "The system should be fast" fails the validation criterion of:

- (a) Completeness
- (b) Consistency
- (c) Testability
- (d) Achievability

**A7.** The Hawthorne Effect is a limitation of which elicitation technique?

- (a) Document analysis
- (b) Questionnaire
- (c) Interview
- (d) Observation

**A8.** Once requirements are approved by all stakeholders, they are said to be:

- (a) Closed
- (b) Archived
- (c) Baselined
- (d) Transferred

**A9.** A Change Control Board (CCB) is responsible for:

- (a) Writing new requirements
- (b) Reviewing and deciding on change requests to baselined requirements
- (c) Performing acceptance testing
- (d) Managing the project budget

**A10.** The IEEE 830 standard relates to:

- (a) Network cable specifications
- (b) Software requirements specifications
- (c) Project risk management
- (d) Earned Value Management formulas

## Bahagian B: Soalan Jawapan Pendek / Section B: Short Answer (30 marks)

**B1.** List and briefly describe FOUR (4) types of requirements found in computer system and network projects. Give one example of each. *(8 marks)*

**B2.** Explain THREE (3) advantages of conducting a JAD (Joint Application Development) workshop compared to conducting individual interviews for requirements elicitation. *(6 marks)*

**B3.** A project manager receives the following requirement: *"The network must perform well under load."* Explain why this requirement fails the validation process and rewrite it as a properly validated requirement. *(4 marks)*

**B4.** Describe the FOUR (4) steps of the Change Control Process that must be followed when a stakeholder requests a change to a baselined requirement. *(8 marks)*

**B5.** Explain TWO (2) reasons why a feasibility assessment must be conducted before requirements are baselined, and name THREE (3) dimensions of feasibility. *(4 marks)*

## Bahagian C: Soalan Esei / Section C: Essay (50 marks)

**C1.** You have been appointed as the project manager for a computer system and network upgrade project for a manufacturing company with 400 employees across three sites. The company's managing director has given you a one-page brief describing the business problem but no detailed technical requirements.

(a) Describe the requirements elicitation plan you would develop, identifying FOUR (4) elicitation techniques you would use, which stakeholders you would apply each technique to, and why you selected those techniques. *(15 marks)*

(b) Once requirements have been gathered, describe the process you would use to classify, validate, and prioritise them before presenting to stakeholders for baseline approval. *(15 marks)*

(c) Construct a sample Requirements Traceability Matrix (RTM) for FIVE (5) requirements drawn from a network upgrade scenario. Your RTM must include the following columns: Req ID, Requirement Statement, Type (F/NF/T/B), Priority (MoSCoW), Source, Design Component (proposed), Acceptance Test (proposed), Status. *(20 marks)*
