**Objektif / Objective:** Execute a structured project closure, produce all closure documentation (lessons learned, closure report, handover package), and formally hand over the delivered system to the client operations team.

## Senario / Scenario

**Situasi: Akhir Projek / Situation: Project End — Week 18**

The Prisma Teknologi Sdn. Bhd. headquarters network upgrade project has reached completion. All implementation activities are finished. The following summary of final project status has been provided by the instructor:

**Ringkasan Status Akhir / Final Status Summary:**

| Item | Butiran / Details |
|------|-------------------|
| Tarikh Siap Sebenar / Actual Completion Date | 1 November 2026 (1 minggu lambat / 1 week late) |
| Kos Akhir / Final Actual Cost | RM 406,500 (bajet: RM 450,000 / budget: RM 450,000) |
| Kadar Lulus UAT / UAT Pass Rate | 97.3% (146 daripada 150 kes ujian / 146 of 150 test cases passed) |
| Defek Kritikal / Critical Defects | 0 (sifar) |

## Prosedur / Procedures

| Langkah | Arahan / Instruction |
|---------|---------------------|
| **1** | Complete the Final Acceptance Checklist (12-item checklist from KP(4/4)) for the project. For each item, state: (a) whether it is complete, (b) the evidence of completion (document reference or observation), and (c) for incomplete items — the resolution plan and responsible party. |
| **2** | Prepare an Outstanding Items Register for the two open items identified in the scenario. For each item: (a) describe the item, (b) assess whether it prevents final acceptance or can be accepted with conditions, (c) propose a retention amount or bond if applicable, and (d) obtain simulated client agreement (instructor role-plays the client representative). |
| **3** | Prepare the full As-Built Documentation package. Using the instructor-provided as-built templates, produce the following documents (use simulated/sample data appropriate to the scenario): (a) As-Built Network Diagram (hand-drawn or digital — clearly labelled), (b) Equipment Inventory with minimum 10 items (model, serial number, firmware, warranty expiry, vendor contact), (c) IP Address Plan (minimum 4 VLANs, showing subnet, gateway, DHCP range, reserved ranges), (d) SOP for ONE common administrative task (e.g., adding a new VLAN). |
| **4** | Facilitate a Lessons Learned Workshop with the class group (simulating the project team). Using the guiding questions from KP(4/4), generate a minimum of 8 lesson entries covering at least 4 categories (Planning, Technical, Communication, Quality). Record all findings in the Lessons Learned Register with the format: ID, Category, Description, Impact, Recommendation, Owner. |
| **5** | Produce the Project Closure Report. The report must contain all sections listed in KP(4/4) Section 5.1. Key data to include: (a) Budget vs. Actual comparison table (use the scenario data above), (b) Schedule variance — planned completion Week 18 (31 Oct 2026) vs. actual Week 19 (1 Nov 2026), (c) UAT quality performance summary, (d) Top 3 lessons from the Lessons Learned Register, (e) Final deliverables checklist, (f) Outstanding items and resolution plan. |
| **6** | Prepare the Project Acceptance Certificate. Fill in all fields using scenario data. Present the certificate to the instructor (role-playing as the client representative CIO). Conduct a brief 10-minute handover presentation — demonstrate that all deliverables have been received and that the client is ready to sign. Obtain the instructor's signature as simulated client sign-off. |
| **7** | Prepare the Administrative Closure checklist. For each of the 14 document categories in KP(4/4) Section 6.1, state: (a) document name, (b) current location in the archive folder, and (c) retention period. Organise the physical or digital archive folder to match the checklist. |
| **8** | Develop the BAU Transition Plan. Using the template from KP(4/4) Section 7.1, complete the BAU handover table with realistic dates (starting from 1 November 2026). Identify the specific training the IT operations team requires before the 30-day hypercare period begins. Draft the hypercare support arrangement — who from the project team is available, what their response SLA is (e.g., 4-hour response for Critical issues during hypercare), and how issues are escalated. |
| **9** | Draft the Post-Implementation Review (PIR) plan. Define: (a) PIR date (Day 30 post go-live), (b) 5 evaluation questions with measurable success criteria, (c) data sources for each question (e.g., network monitoring system, user survey, actual cost reports), and (d) who will conduct the PIR and who will receive the findings report. |
| **10** | Compile the full Closure Package (all outputs from Steps 1–9) into a single organised folder with a table of contents. Present the Closure Package to the instructor in a final 20-minute closure review meeting. The instructor will verify completeness and sign off on the Project Closure Report. Receive verbal feedback and document it as the final entry in the Lessons Learned Register. |
