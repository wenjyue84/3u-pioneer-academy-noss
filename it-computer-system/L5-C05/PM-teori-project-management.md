## Kaedah Pengajaran / Teaching Method (4-Step)

### 1. PERSEDIAAN (Preparation)

| Langkah / Step | Aktiviti / Activity | Masa / Duration |
|----------------|---------------------|-----------------|
| 1.1 | Welcome trainees; take attendance | 5 min |
| 1.2 | State the learning objectives for the session, referencing the relevant KP | 10 min |
| 1.3 | Connect the topic to trainees' workplace experience or prior knowledge — invite brief sharing | 10 min |
| 1.4 | Provide a context overview: how this topic fits within the full project management lifecycle | 5 min |

### 2. PENYAMPAIAN (Presentation)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 2.1 | Deliver theory content from the relevant KP using structured slides and worked examples |
| 2.2 | Explain key terms, frameworks, and standards (PMBOK®, PRINCE2, MoSCoW, EVM, RACI, CPM) with real-world IT project scenarios |
| 2.3 | Use interactive whiteboard exercises: draw WBS diagrams, solve CPM network problems, calculate EVM metrics live |
| 2.4 | Present case studies of IT projects (network upgrades, data centre builds, ERP rollouts) — analyse what went right and what went wrong |
| 2.5 | Incorporate bilingual delivery: explain key PM terms in both English and Malay; refer to KP glossary tables |
| 2.6 | Highlight professional standards: PDPA 2010 compliance, ISO 21502, JPK assessment requirements |
| 2.7 | Encourage questions and address common misconceptions (e.g., "EVM is too complex for small projects", "requirements never change") |

### 3. PENGGUNAAN (Application)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 3.1 | Distribute the corresponding KT (Assignment Sheet) at the end of each KP session |
| 3.2 | Trainees attempt KT individually; numerical sections (CPM, EVM) may be attempted in pairs for peer checking |
| 3.3 | Instructor circulates to observe reasoning, address misconceptions, and provide targeted guidance |
| 3.4 | Discuss answers to Section A (MCQ) as a class — explain why distractors are wrong, not just why the correct answer is right |
| 3.5 | For Section C essay questions, review model answer structures and marking criteria before trainees write |

### 4. PENGESAHAN (Confirmation)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 4.1 | Review the 3–5 most important learning points from the session |
| 4.2 | Conduct structured oral questioning: pose a scenario and ask trainees to identify the appropriate PM response |
| 4.3 | Collect completed KT; provide written feedback within one week |
| 4.4 | Preview the next session — state the topic, the KP to read in advance, and any pre-reading required |
| 4.5 | Record attendance and session completion in the instructor log |

## Panduan Penyampaian Topik / Topic Delivery Guide

### KP(1/4): Requirements Analysis — 26.25 hours

**Topik Utama / Key Topics:**
- Types of requirements (F, NF, T, B) — definitions and IT examples
- Elicitation techniques — interview guides, JAD workshop facilitation, questionnaire design
- Requirements documentation: BRD structure, SRS (IEEE 830), RTM construction
- MoSCoW prioritisation — practical classification exercises
- Validation criteria: Complete, Consistent, Testable, Achievable — identifying failures and rewriting
- Stakeholder analysis and the RACI model
- Feasibility assessment dimensions
- Change control for requirements (baseline and change request process)

**Aktiviti Disyorkan / Recommended Activities:**
- Live exercise: Build a mini-RTM from a one-page project brief (groups of 3)
- Role-play: Conduct a 10-minute requirements interview with the instructor playing a CIO
- Workshop simulation: Present requirements to the class as a stakeholder review

**Bahan Rujukan / Reference Materials:** KP(1/4), PMBOK® Ch. 5, IEEE 830 summary handout

---

### KP(2/4): Project Planning — 31.50 hours

**Topik Utama / Key Topics:**
- Project scope statement components
- WBS construction — hierarchical decomposition rules, 100% Rule, WBS Dictionary
- Activity definition, sequencing, and dependency types (FS, SS, FF, SF)
- CPM: Forward Pass, Backward Pass, Total Float, Critical Path identification
- Gantt chart construction and interpretation using project management software
- Schedule compression: crashing vs. fast tracking — trade-off analysis
- Cost estimation methods — analogous, parametric, bottom-up, three-point (PERT)
- Budget structure: direct/indirect costs, contingency reserve, management reserve
- EVM baseline: Planned Value (S-curve), EAC formula derivation
- Risk identification, assessment (P×I matrix), and response planning (Avoid/Mitigate/Transfer/Accept)
- Communications Management Plan — stakeholder communication matrix

**Aktiviti Disyorkan / Recommended Activities:**
- Hands-on: Build a 10-activity WBS and CPM network diagram on the whiteboard
- Lab exercise: Enter a 15-activity project into Microsoft Project / ProjectLibre; generate Gantt chart
- Calculation drill: EVM practice set — 10 scenarios with increasing complexity
- Group work: Develop a Risk Register for a given IT project scenario

**Bahan Rujukan / Reference Materials:** KP(2/4), PMBOK® Ch. 6 & 7, Microsoft Project tutorial

---

### KP(3/4): Project Execution Management — 39.38 hours

**Topik Utama / Key Topics:**
- Work assignment and team direction — RACI in practice
- Information distribution — status report formats, meeting structures
- Issue management — issue log, severity classification, escalation criteria
- EVM monitoring: calculating and interpreting SV, CV, SPI, CPI, EAC, VAC
- Schedule and cost variance analysis — root cause identification and corrective action
- Integrated change control — 5-step CCB process, change request form, impact analysis
- Team development: Tuckman's 5 stages — PM interventions per stage
- Conflict management: 5 techniques (Collaborate, Compromise, Accommodate, Force, Withdraw)
- Performance management: one-on-ones, feedback models, escalation to functional manager
- QA vs. QC — process audits vs. product inspection
- Quality gates — design, pre-implementation, integration test, UAT, security, go-live
- Configuration management — CMDB, version control, change documentation
- Risk monitoring — Risk Review meetings, risk materialisation to issue transition
- Vendor and contract management — delivery acceptance, SLA monitoring
- Status reporting — traffic light system, executive summary structure

**Aktiviti Disyorkan / Recommended Activities:**
- Simulation: Process two change requests — complete forms, perform impact analysis, conduct CCB meeting
- Role-play: Conflict resolution — instructor plays a difficult stakeholder; trainee mediates
- Case study: Analyse a real-world IT project failure (e.g., public sector ERP overrun) — identify PM errors
- Scenario analysis: Given EVM data, diagnose project health and present recovery plan to the class

**Bahan Rujukan / Reference Materials:** KP(3/4), PMBOK® Ch. 4 & 8–13, Tuckman (1965)

---

### KP(4/4): Project Closure — 7.87 hours

**Topik Utama / Key Topics:**
- Normal vs. early closure — conditions and processes for each
- Final acceptance checklist — 12 criteria and evidence requirements
- Outstanding items register — conditions for conditional acceptance
- Client handover — demonstration, walkthrough, sign-off process
- As-built documentation package — network diagram, equipment inventory, IP plan, SOPs
- Warranty and support transition — escalation path, vendor introductions
- Lessons learned workshop facilitation — guiding questions, register format
- Project Closure Report — all sections; budget vs. actual narrative
- Administrative closure — document retention policy (7 years), archive structure, resource release
- BAU transition plan — hypercare period, post-implementation review (PIR)

**Aktiviti Disyorkan / Recommended Activities:**
- Simulation: Full handover presentation — trainee presents to instructor (role-playing as CIO); instructor raises objections to outstanding items
- Group exercise: Lessons learned workshop — analyse a case study project; produce a 5-entry register
- Document review: Review a sample (incomplete) Project Closure Report — identify missing sections

**Bahan Rujukan / Reference Materials:** KP(4/4), PMBOK® Ch. 4.7, PRINCE2 Closing a Project process

## Penilaian Teori / Theory Assessment

Upon completion of all 4 KP/KT sessions, trainees will sit for the Knowledge Assessment (KA):

- **Kod / Code:** IT-020-5:2013-C05/KA
- **Tempoh minimum / Minimum duration:** 2 hours 30 minutes
- **Format:** Written examination — Section A (MCQ), Section B (short answer incl. numerical), Section C (essay)
- **Jumlah markah / Total marks:** 100
- **Markah lulus / Pass mark:** 60% (as per JPK and institutional requirements)
