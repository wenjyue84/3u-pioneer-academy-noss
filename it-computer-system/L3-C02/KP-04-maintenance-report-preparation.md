## Objektif Pembelajaran / Learning Objectives

Upon completion of this Information Sheet, trainees shall be able to:

1. Explain the purpose and importance of a computer maintenance report in an IT service environment
2. Identify all mandatory fields and sections required in a complete maintenance report
3. Write accurate, clear, and professional technical descriptions of maintenance tasks performed
4. Distinguish between a preventive maintenance report and a corrective maintenance report and describe how each differs in content
5. Submit a completed maintenance report correctly within organisational procedures

---

## 1.0 Purpose of the Maintenance Report

A computer maintenance report (laporan penyelenggaraan komputer) is the formal written record of all maintenance activities carried out on a computer system. It is prepared by the technician upon completion of the maintenance task and submitted to the supervisor or IT manager.

The maintenance report serves several important functions:

| Function | Description |
|----------|-------------|
| Evidence of work performed | Provides a documented record that the maintenance was carried out as scheduled or requested |
| Audit trail | Supports IT governance, ISO compliance, and internal audit requirements |
| Asset history | Contributes to the cumulative maintenance history of the computer asset (rekod aset) |
| Fault pattern analysis | Enables the IT manager to identify recurring faults or systems that require replacement |
| Accountability | Establishes clear responsibility — which technician performed which action on which date |
| Billing and cost tracking | In contracted service environments, the report supports invoice generation and cost allocation |

A maintenance report that is incomplete, inaccurate, or submitted late undermines the integrity of the entire maintenance programme and creates risk during audits or warranty claims.

---

## 2.0 Types of Maintenance Reports

There are two primary types of maintenance reports corresponding to the two main maintenance activities in CoCU 2.

| Report Type | Trigger | Key Content Difference |
|-------------|---------|----------------------|
| **Preventive Maintenance Report** (Laporan Penyelenggaraan Pencegahan) | Completion of a scheduled PM task | Lists all PM checklist items completed; records system status before and after; notes any items deferred to the next cycle |
| **Corrective Maintenance Report** (Laporan Penyelenggaraan Pembetulan) | Resolution of a reported fault | Includes fault description, diagnosis methodology, root cause identified, corrective action taken, and verification test result |

Both report types share a common structure but differ in the sections covering the maintenance activity details.

## 3.0 Structure and Content of a Maintenance Report

### 3.1 Header Section — System and Request Information

The header uniquely identifies the maintenance activity. Every field must be completed accurately.

| Field | Description | Example |
|-------|-------------|---------|
| Report number | Unique identifier, usually generated by the IT helpdesk system | MR-2024-0315 |
| Request / work order number | Reference to the original maintenance request | WO-2024-0312 |
| Asset tag | Physical label on the computer unit | PC-FIN-042 |
| Serial number | Manufacturer's serial number (from the system label or BIOS) | CNT12345678 |
| Make and model | Computer manufacturer and model name | Dell OptiPlex 7010 |
| Location | Building, floor, room, and department | Block A, Level 2, Finance Department |
| Type of maintenance | Preventive / Corrective / Predictive | Preventive |
| Date and time of commencement | When work began | 15 March 2024, 09:00 |
| Date and time of completion | When work ended and system was returned to service | 15 March 2024, 11:30 |
| Technician name | Full name of the technician performing the work | Ahmad bin Kamaruddin |
| Technician ID / Employee number | Staff or trainee identification number | EMP-1042 |

### 3.2 System Configuration Record

Before performing any maintenance, the technician records the system's configuration. This provides a baseline against which post-maintenance status can be compared.

| Component | Pre-Maintenance State | Post-Maintenance State |
|-----------|----------------------|----------------------|
| Operating system and build | Windows 10 Pro, Build 19044 | Windows 10 Pro, Build 19045 |
| RAM installed | 8 GB DDR4 (2 × 4 GB) | 8 GB DDR4 (2 × 4 GB) |
| Primary storage | 500 GB HDD, 72% used | 500 GB HDD, 68% used |
| Antivirus version and definitions | Kaspersky 21.3, definitions 01/03/2024 | Kaspersky 21.3, definitions 15/03/2024 |
| GPU driver version | NVIDIA 527.37 | NVIDIA 551.23 |
| BIOS version | F.12 | F.14 |

Recording pre- and post-maintenance configuration confirms that updates were applied and provides evidence if a configuration change causes a new issue after maintenance.

### 3.3 Maintenance Activity Details — Preventive Maintenance

For a preventive maintenance report, the activity details section mirrors the PM checklist and records the outcome of each task.

**Format:**

| # | Task Performed | Result | Remarks |
|---|---------------|--------|---------|
| 1 | External cleaning — monitor, keyboard, mouse | Completed | Heavy dust accumulation on keyboard; cleaned thoroughly |
| 2 | Internal dust removal — heatsink, fans, PSU vent | Completed | Heatsink fins were approximately 60% blocked with dust; compressed air applied |
| 3 | Thermal paste replacement | Completed | Previous paste was dry and cracked; new Arctic MX-4 applied |
| 4 | Cable and connector inspection | Completed | All connections secure; one SATA data cable re-seated (was partially loose) |
| 5 | OS security updates | Completed | KB5035845 installed; system restarted |
| 6 | Driver updates | Completed | GPU driver updated from 527.37 to 551.23; NIC driver updated |
| 7 | BIOS update | Completed | Updated from F.12 to F.14 per vendor security advisory |
| 8 | Antivirus definitions update and full scan | Completed | Definitions updated; no threats detected in full scan |
| 9 | Disk error check (chkdsk) | Completed | No errors found |
| 10 | Disk cleanup | Completed | 4.2 GB recovered |
| 11 | Disk defragmentation | Not applicable | System has SSD; Optimise (TRIM) run instead |
| 12 | S.M.A.R.T. status check | Completed | All attributes normal; no reallocation events |
| 13 | Startup programmes review | Completed | 3 non-essential items disabled (OneDrive, Teams auto-start, Spotify) |
| 14 | Backup verification | Completed | Last backup 14/03/2024 22:00 — completed successfully; test restore of 2 files confirmed |

**Deferred items** (items not completed and reasons):

| # | Task | Reason Deferred | Recommended Action |
|---|------|----------------|--------------------|
| — | CMOS battery replacement | Voltage acceptable (3.02 V); not due until annual cycle | Schedule for next annual PM |

### 3.4 Maintenance Activity Details — Corrective Maintenance

For a corrective maintenance report, the activity details section follows the six-step fault-finding methodology and must record each step clearly.

**Fault Description (as reported by user):**

> "The computer shuts down by itself after about 20 minutes of use. This started two days ago. No new software was installed."

**Diagnosis:**

| Step | Action Taken | Finding |
|------|-------------|---------|
| Initial observation | Powered on system; monitored CPU temperature using HWMonitor | CPU temperature reached 94°C within 15 minutes of light use (safe maximum for this CPU is 72°C) |
| Physical inspection | Opened chassis | Heatsink fins completely blocked with dust; CPU fan spinning at reduced speed |
| Thermal paste inspection | Removed heatsink | Thermal paste completely dried and cracked; contact area inadequate |

**Root Cause:** Blocked heatsink and degraded thermal paste causing CPU thermal throttling and protective shutdown.

**Corrective Action Taken:**

| Step | Action |
|------|--------|
| 1 | Cleaned heatsink fins and CPU fan with compressed air and soft brush |
| 2 | Cleaned old thermal paste from CPU IHS and heatsink base with IPA 91% |
| 3 | Applied new thermal paste (Arctic MX-4, rice-grain amount) to CPU centre |
| 4 | Re-mounted heatsink using cross-pattern tightening |
| 5 | Cleaned case interior; confirmed case fan operation (intake front, exhaust rear) |

**Verification Test:**

System powered on and run under load (CineBench R23) for 30 minutes. Maximum CPU temperature recorded: 67°C. No shutdown occurred. System returned to normal operation.

**Parts Used:**

| Part | Part Number / Description | Quantity | Source |
|------|--------------------------|----------|--------|
| Thermal paste | Arctic MX-4, 4 g tube | 1 | IT store inventory |

### 3.5 System Functionality Verification

Regardless of maintenance type, the technician must confirm the system is fully functional before returning it to the user.

A minimum functionality verification includes:

- [ ] System powers on and reaches the Windows desktop without errors
- [ ] No abnormal error messages or event log warnings upon startup
- [ ] All connected peripherals (keyboard, mouse, monitor, printer) are detected and functional
- [ ] Network connectivity confirmed (ping to gateway and external DNS)
- [ ] Key business applications launch successfully
- [ ] CPU and GPU temperatures are within safe operating range at idle

### 3.6 Recommendations Section

The recommendations section is the technician's professional assessment of any additional work required that was beyond the scope of the current maintenance activity.

**Format:**

| # | Recommendation | Priority | Reason |
|---|---------------|----------|--------|
| 1 | Replace HDD with SSD within 3 months | High | S.M.A.R.T. data shows 47 reallocated sectors — drive is beginning to fail |
| 2 | Upgrade RAM from 4 GB to 8 GB | Medium | System consistently uses 85–90% of RAM; performance will improve significantly |
| 3 | Replace UPS battery | Low | UPS battery capacity at 72%; not urgent but should be replaced before next annual PM |

Recommendations must be factual and supported by evidence observed during the maintenance activity. Do not recommend unnecessary upgrades.

### 3.7 Sign-Off Section

| Role | Name | Signature | Date |
|------|------|-----------|------|
| Technician | | | |
| Supervisor / IT Manager | | | |
| User acceptance (for CM) | | | |

The user acceptance signature (for corrective maintenance) confirms that the user has tested the system and is satisfied the reported fault has been resolved.

## 4.0 Writing Standards for Maintenance Reports

A maintenance report is an official organisational document. The following writing standards apply:

- **Be factual and specific.** Do not use vague language such as "cleaned computer" — write "removed dust from CPU heatsink fins, case fans (front intake × 2, rear exhaust × 1), and PSU exhaust vent using compressed air."
- **Use standard technical terminology.** Use the correct component names and acronyms (e.g. HDD, SSD, RAM, BIOS, GPU, NIC).
- **Record measurements where applicable.** CPU temperature before and after, free disk space recovered, battery voltage.
- **Record part numbers for replaced components.** This enables procurement to order identical replacements in future.
- **Write in the past tense.** The report describes actions that have already been completed.
- **Avoid abbreviations that are not universally understood.** Spell out on first use: e.g. "Operating System (OS)".
- **Do not include personal opinions.** The report records facts, not complaints about the user or the equipment.

---

## 5.0 Report Submission and Filing

Upon completion, the maintenance report must be:

1. **Reviewed by the technician** for completeness and accuracy before submission.
2. **Signed** by the technician, supervisor, and (for CM) the user.
3. **Submitted** to the IT manager or helpdesk within the timeframe specified by organisational policy — typically the same working day or within 24 hours of completion.
4. **Filed** in the asset's maintenance history folder (physical or electronic). Many organisations use a helpdesk system (e.g. Freshservice, Jira Service Management, or a local database) to store maintenance records digitally.
5. **Linked to the original work order** in the helpdesk system so that the request is formally closed.

A report submitted late, unsigned, or filed in the wrong location is treated as incomplete by auditors.

---

## 6.0 Common Errors in Maintenance Report Preparation

| Error | Consequence | Prevention |
|-------|-------------|------------|
| Leaving fields blank (especially asset tag or serial number) | Report cannot be matched to the correct asset; audit failure | Complete every mandatory field; verify asset tag against the physical label before writing |
| Vague activity descriptions ("cleaned PC", "fixed problem") | Report provides no audit or technical value; supervisor cannot verify work | Describe every action specifically; include measurements and part numbers |
| Omitting the recommendations section | Management unaware of impending failures; system fails before next PM | Always review S.M.A.R.T. data and system condition before completing the report |
| Not recording pre- and post-maintenance configuration | Cannot prove that updates were applied; disputes about system state | Record OS build number, driver versions, and antivirus definition date before and after |
| Submitting without technician signature | Report has no legal or administrative standing | Sign before submission; never submit an unsigned report |
| Filing in the wrong asset folder | Maintenance history contaminated; wrong repair history used for future decisions | Verify the asset tag matches the folder or helpdesk ticket before filing |
