## Kaedah Pengajaran / Teaching Method (4-Step)

### 1. PERSEDIAAN (Preparation)

| Langkah / Step | Aktiviti / Activity | Masa / Duration |
|----------------|---------------------|-----------------|
| 1.1 | Welcome trainees and take attendance | 5 min |
| 1.2 | State the learning objectives for the session | 5 min |
| 1.3 | Connect topic to trainees' prior knowledge and workplace context — emphasise the management (not technical operations) focus of Level 5 | 5 min |
| 1.4 | Provide overview of the Information Sheet (KP) content and its link to the corresponding KT assignment | 5 min |

### 2. PENYAMPAIAN (Presentation)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 2.1 | Deliver theory content from the relevant KP using slides, case studies, and real-world examples |
| 2.2 | Explain key terms and framework concepts: ISMS, ISO/IEC 27001:2022 clauses, risk management, SOC governance, incident lifecycle, management reporting |
| 2.3 | Use diagrams: ISO/IEC 27001 clause structure, risk matrix, incident lifecycle flowchart, SOC KPI dashboard example, policy hierarchy pyramid |
| 2.4 | Present case studies from real security incidents (anonymised) to contextualise management decision-making |
| 2.5 | Contrast Level 5 governance responsibilities with Level 4 technical operations at each topic |
| 2.6 | Encourage questions and address misconceptions — particularly around the distinction between *operating* security controls and *managing* the ISMS |
| 2.7 | Highlight Malaysian regulatory context: PDPA 2010, BNM RMiT, relevant sector-specific requirements |

### 3. PENGGUNAAN (Application)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 3.1 | Distribute the corresponding KT (Assignment Sheet) for the session |
| 3.2 | Trainees complete the assignment individually or in guided pairs |
| 3.3 | Instructor provides guidance and prompts critical thinking — ask "Why?" and "What would you decide?" rather than providing answers |
| 3.4 | Discuss answers and common decision-making errors with the class; highlight the consequences of poor management decisions |

### 4. PENGESAHAN (Confirmation)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 4.1 | Review key learning points from the session |
| 4.2 | Conduct brief oral questioning to verify understanding — use scenario-based questions, not recall questions |
| 4.3 | Collect completed KT for marking and feedback |
| 4.4 | Preview the next session topic |
| 4.5 | Record attendance and session completion |

## Penyampaian Topik Terperinci / Detailed Topic Delivery Notes

### KP(1/4) — Security Requirements Analysis (20.7 hours)

| Topic | Key Teaching Points |
|-------|---------------------|
| ISMS overview and Level 5 scope | Emphasise: ISMS is a management system, not a product; Level 5 = governance and oversight |
| ISO/IEC 27001:2022 structure | Walk through Clauses 4–10; explain the Plan-Do-Check-Act (PDCA) cycle |
| Organisational context analysis | Internal vs. external context; use a real Malaysian SME as a case study for context identification |
| Interested parties analysis | Map stakeholders to their specific requirements; use a fintech company example |
| Gap analysis methodology | Demonstrate a 5-item gap analysis exercise on the whiteboard |
| Level 5 vs. Level 4 responsibilities | Use a role comparison table; discuss what decisions each level makes independently vs. escalates |

### KP(2/4) — Security Management Planning (18.0 hours)

| Topic | Key Teaching Points |
|-------|---------------------|
| Risk assessment methodology | Likelihood × Impact matrix; walk through 3 worked examples |
| Risk treatment options | Emphasise that "Accept" requires formal documentation and management sign-off |
| Statement of Applicability | Demonstrate SoA structure with 5 sample Annex A controls |
| Security governance framework | Policy hierarchy pyramid; role accountability matrix |
| SMART security objectives | Common errors: objectives that are not measurable; objectives with no deadline |
| Implementation roadmap | Prioritisation by risk; budget estimation; change management considerations |

### KP(3/4) — Managing Computer System Security (45.0 hours)

| Topic | Key Teaching Points |
|-------|---------------------|
| ISMS control implementation oversight | Distinguish: *directing* implementation vs. *performing* it |
| SOC governance | SOC KPI dashboard; how to interpret MTTD/MTTR trends; escalation governance |
| Incident management lifecycle | Use the 6-phase model; emphasise management decision points (containment approval, regulatory notification) |
| Malaysian notification obligations | PDPA 2010 Section 12A (if enacted); BNM RMiT incident notification timelines; discuss industry-specific requirements |
| IAM governance | JML process; PAM controls; periodic access review governance |
| Vulnerability management | SLA framework; escalation for SLA breaches; emergency change management |
| Security awareness | Programme design; effectiveness measurement; phishing simulation interpretation |

### KP(4/4) — Security Management Reporting (6.3 hours)

| Topic | Key Teaching Points |
|-------|---------------------|
| Reporting audience hierarchy | Different formats for Board, Steering Committee, and operational staff |
| KPI selection and calculation | Common errors: vanity metrics vs. risk-based metrics |
| Internal audit process | Finding classification; root cause analysis (5-Why demonstration) |
| Management Review (Clause 9.3) | Walk through all required inputs and outputs |
| Executive dashboard design | Principles: visual, concise, risk-led, decision-enabling |
| Continual improvement (Clause 10) | Corrective action register; closing the PDCA loop |

## Penilaian Teori / Theory Assessment

Upon completion of all 4 KP/KT sessions, trainees will sit for the Knowledge Assessment (KA):

- **Code:** IT-020-5:2013-C03/KA
- **Duration:** 2 hours 30 minutes
- **Format:** Written test (MCQ, short answer, essay)
- **Total marks:** 100
- **Pass mark:** 60 marks (60%)
- **Note:** KA is closed-book; no reference materials permitted
