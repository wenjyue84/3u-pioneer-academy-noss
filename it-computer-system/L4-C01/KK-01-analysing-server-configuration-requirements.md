## Objektif / Objective

Conduct a structured requirements analysis for a server deployment scenario, producing a verified Requirements Summary and Requirements Traceability Matrix (RTM) ready for handover to the planning phase.

---

## Tempoh / Duration

6 hours (practical session)

---

## Peralatan dan Bahan / Equipment and Materials

| No. | Item | Quantity |
|-----|------|----------|
| 1 | Scenario brief / simulated project request (provided by instructor) | 1 per trainee |
| 2 | Stakeholder interview questionnaire template | 1 |
| 3 | Requirements categorisation worksheet | 1 |
| 4 | Requirements Traceability Matrix (RTM) template | 1 |
| 5 | Requirements Summary report template | 1 |
| 6 | Computer with word processor and spreadsheet software | 1 |
| 7 | Reference: NOSS IT-020-4:2013 CoCu 1 | 1 |

---

## Langkah Keselamatan / Safety Precautions

- Handle all scenario documents as confidential — do not share with other groups during individual assessment
- Save work regularly; use version-controlled filename (e.g. `requirements-analysis-v1.0-[name].docx`)
- Do not make assumptions not supported by the scenario brief — document unknowns as gaps requiring clarification

---

## Prosedur / Procedures

| Langkah | Arahan / Instruction |
|---------|---------------------|
| 1 | Receive the scenario brief from the instructor. Read the entire document carefully before writing anything. Identify the stated business context, the type of server deployment (new server, upgrade, or expansion), and any deadlines or constraints mentioned. |
| 2 | Using the Stakeholder Interview Questionnaire template, identify all stakeholder groups relevant to this scenario (Business Owner, IT Manager, Application Owner, Security Officer, Compliance). For each group, list the questions you would ask and the expected type of answer. |
| 3 | Extract all requirements stated or implied in the scenario brief. Record each requirement as a distinct, numbered entry using this format: Req ID, Description, Source, Category (Business / Technical / Compliance), Priority (M/S/N). |
| 4 | Apply MoSCoW prioritisation to each requirement. Mark each as Must Have (M), Should Have (S), or Nice to Have (N) based on the scenario context. Justify your priority rating in a brief note. |
| 5 | Identify dependencies between requirements. For each Must Have requirement, check whether it depends on another requirement being fulfilled first. Document the dependency (e.g. "R-004 depends on R-003 — encryption can only be configured after OS is selected"). |
| 6 | Identify gaps: requirements that are unclear, missing information, or cannot be fulfilled within the stated constraints (budget, timeline). For each gap, state: (a) what information is missing, (b) which stakeholder can provide it, (c) the impact if it is not resolved before planning begins. |
| 7 | Populate the Requirements Traceability Matrix (RTM) with all extracted requirements, their source, category, priority, and a placeholder column for "Design Reference" (to be filled in during planning). |
| 8 | Produce the Requirements Summary document using the provided template. The document must contain: project overview, stakeholder list, categorised requirements table, MoSCoW analysis, dependency notes, identified gaps, and assumptions. |
| 9 | Complete the self-assessment checklist on this Work Sheet. |
| 10 | Submit the Requirements Summary and RTM to the instructor for evaluation. |

---

## Hasil Dijangka / Expected Outcome

- A completed Requirements Summary document containing all requirements properly categorised and prioritised
- A populated RTM with minimum 10 requirements (or all requirements from the scenario brief, whichever is greater)
- All gaps and dependencies documented
- No unsupported assumptions — every assumption explicitly stated
