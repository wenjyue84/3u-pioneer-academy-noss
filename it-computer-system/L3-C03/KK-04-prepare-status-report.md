## Objektif / Objectives

Upon completion of this activity, the trainee will be able to:
1. Consolidate all repair job data — job order, troubleshooting log, and repair log — into a structured status report.
2. Record the pre-repair and post-repair condition of the computer unit accurately.
3. Document all components replaced or repaired, including part numbers and costs where applicable.
4. State the final resolution status and provide a recommendation for follow-up action if required.
5. Present the completed status report in a professional format suitable for customer handover and organisational record-keeping.

## Langkah Keselamatan / Safety Precautions

- Ensure all customer data referenced in the report is handled with strict confidentiality — do not include sensitive personal data beyond what is necessary for identification.
- Do not alter, omit, or misrepresent any repair findings. Falsifying a status report is a breach of professional conduct and may result in liability.
- Save the report file regularly during preparation to prevent data loss.
- Submit only the final approved version of the report; keep a copy in the job record archive.

## Prosedur / Procedure

| Langkah | Arahan / Instruction |
|---------|----------------------|
| 1 | Collect all source documents: the completed job order assessment form (KK-01), troubleshooting log (KK-02), and repair log (KK-03). Review each document to ensure all fields are complete before beginning the report. |
| 2 | Open the computer status report template on the PC. The template contains the following sections: (a) Job Information, (b) Unit Identification, (c) Pre-Repair Condition, (d) Work Performed, (e) Post-Repair Condition, (f) Parts Used, (g) Resolution Status, and (h) Recommendation. |
| 3 | Complete the **Job Information** section: enter the job order number, date received, date completed, customer name, contact number, and the name of the technician (yourself). |
| 4 | Complete the **Unit Identification** section: enter the asset tag, unit make and model, serial number, operating system version, and RAM/storage specifications as recorded on the job order. |
| 5 | Complete the **Pre-Repair Condition** section: describe the fault symptoms as reported by the customer and as confirmed during the assessment (KK-01). Use clear, factual language — for example: "Unit failed to complete POST; no display output; single long beep code indicating RAM fault." |
| 6 | Complete the **Work Performed** section: list every diagnostic step and repair action carried out, in chronological order. For each action, state: (a) what was done, (b) the tool or method used, and (c) the outcome. Reference the troubleshooting log (KK-02) and repair log (KK-03) for accuracy. Example entry: "Step 1: Ran sfc /scannow via elevated Command Prompt — 0 integrity violations found. Step 2: Removed and reseated RAM modules; system POST successful on restart." |
| 7 | Complete the **Post-Repair Condition** section: describe the condition of the unit after repair and testing. State each test performed and its result — for example: "Windows Memory Diagnostic completed with no errors. Unit boots to Windows desktop successfully. CPU temperature at idle: 45°C (within normal range). Original fault symptom resolved." |
| 8 | Complete the **Parts Used** section: list every component replaced or consumed during the repair. For each item, record: part description, part number, quantity, and unit cost (from the cost reference sheet). Calculate the subtotal. If no parts were replaced (software-only repair), state "Nil — software repair only." |
| 9 | Complete the **Resolution Status** field. Select one of the following: (a) **Fully Resolved** — fault confirmed resolved, unit returned to service; (b) **Partially Resolved** — fault partially resolved, further action required; (c) **Unresolved / Escalated** — fault not resolved; unit referred to manufacturer or specialist. Provide a one-sentence justification for the status selected. |
| 10 | Complete the **Recommendation** section: state any follow-up actions the customer should take. Examples: "Recommend OS reinstallation within 3 months if recurring BSODs occur." / "Customer advised to back up data weekly; current backup posture is nil." / "No further action required; unit in fully serviceable condition." |
| 11 | Proofread the entire report. Check for: (a) factual accuracy against source documents; (b) consistent terminology (hardware names, tool names); (c) spelling and grammar. Correct all errors before finalising. |
| 12 | Save the final report file using the naming convention: `[AssetTag]_[DDMMYYYY]_StatusReport.docx`. Print one copy if required by the instructor. Sign and date the signature block on the report. Submit the digital file and (if applicable) the printed copy to the instructor. |

---

## Hasil Dijangka / Expected Outcome

- A complete, professional computer status report containing all 8 required sections.
- Pre-repair and post-repair conditions clearly described and supported by evidence from the troubleshooting and repair logs.
- All parts used listed with part numbers and costs.
- Resolution status correctly stated with justification.
- Recommendation for follow-up action provided.
- Report proofread, saved with correct filename convention, signed, and dated.
