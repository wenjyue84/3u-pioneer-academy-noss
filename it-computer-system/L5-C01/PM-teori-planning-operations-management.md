## Kaedah Pengajaran / Teaching Method (4-Step)

### 1. PERSEDIAAN (Preparation)

| Langkah / Step | Aktiviti / Activity | Masa / Duration |
|----------------|---------------------|-----------------|
| 1.1 | Welcome trainees and record attendance | 5 min |
| 1.2 | State the learning objectives for the session — connect to the Work Activity and KP topic | 5 min |
| 1.3 | Contextualise topic with a real-world industry example or recent news event (e.g., a published IT outage case study, a Malaysian government ICT policy announcement) | 10 min |
| 1.4 | Distribute the KP and ask trainees to review the Learning Objectives before content delivery begins | 5 min |

### 2. PENYAMPAIAN (Presentation)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 2.1 | Deliver theory content from the relevant KP using slides, framework diagrams, and case study examples |
| 2.2 | Use the Socratic method — pose management scenarios and ask trainees to reason through decisions before revealing best-practice answers |
| 2.3 | Illustrate each concept with a Malaysian or regional industry context where possible (e.g., government agency IT budget process, local telco SLA structures) |
| 2.4 | Present common errors table from the KP and facilitate discussion on how each error could be prevented |
| 2.5 | For quantitative topics (KP3: availability, MTBF/MTTR; KP4: budget variance), work through at least two numerical examples step-by-step on the whiteboard before distributing practice questions |
| 2.6 | Highlight governance and compliance dimensions — MAMPU guidelines, COBIT, ISO references — to reinforce Level 5 management expectations |

### 3. PENGGUNAAN (Application)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 3.1 | Distribute the corresponding KT (Assignment Sheet) for the session |
| 3.2 | Trainees complete the assignment individually. For Section C situational questions, allow pair discussion before individual written submission |
| 3.3 | Instructor circulates to observe reasoning quality, provide targeted prompts (without giving answers), and identify common misconceptions for class debrief |
| 3.4 | Conduct class debrief — review Section A answers with explanation; call on 2–3 trainees to present their Section C analysis; discuss alternative approaches |

### 4. PENGESAHAN (Confirmation)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 4.1 | Review 3–5 key learning points from the session (ask trainees to volunteer, not lecture) |
| 4.2 | Oral check: pose one rapid-fire scenario per trainee (30 seconds per trainee) — "What would you do as IT Manager if…?" |
| 4.3 | Collect completed KT for marking and feedback; return within 3 working days |
| 4.4 | Preview the next session: connect current topic to the next KP to build cumulative understanding |
| 4.5 | Record attendance and session completion in the training log |

## Panduan Pengajaran Mengikut KP / Session-Specific Guidance

### KP(1/4) — Resource Planning (18 hours)

| Session Focus | Key Teaching Points | Recommended Activities |
|--------------|--------------------|-----------------------|
| Capacity planning concepts and ITIL framework | Business vs. Service vs. Component capacity management; utilisation thresholds | Baseline utilisation calculation exercise; threshold-based decision case study |
| Budget planning — CAPEX vs. OPEX | Depreciation concepts; budget development process; contingency | Budget line-item drafting exercise using a simulated organisation |
| Lifecycle management and CMDB | Asset lifecycle phases; lifecycle timeline table; CMDB field requirements | Asset register analysis exercise — identify assets approaching EOL |
| Integrated resource plan | TCO analysis; resource plan structure; executive summary writing | TCO comparison exercise: on-premises vs. cloud; resource plan outline drafting |

### KP(2/4) — Operations Coordination (15 hours)

| Session Focus | Key Teaching Points | Recommended Activities |
|--------------|--------------------|-----------------------|
| Organisational roles and interfaces | IT Manager's coordination role; service desk as SPOC; vendor categories | Org chart exercise: map roles to RACI matrix |
| ITIL Service Operation processes | Incident, Problem, Change, Request, Event Management | Incident priority matrix exercise; change type classification exercise |
| SLA, OLA, and Underpinning Contract | Hierarchy of agreements; OLA must support SLA; UC must underpin OLA | SLA vs. OLA alignment exercise; breach scenario analysis |
| Vendor relationship management | Governance calendar; performance scorecard; escalation matrix | Vendor scorecard completion exercise; negotiation role-play |
| Communication planning | Incident communication; change notification; management reporting channels | Draft a P1 incident user communication |

### KP(3/4) — Performance Monitoring (15 hours)

| Session Focus | Key Teaching Points | Recommended Activities |
|--------------|--------------------|-----------------------|
| KPI design and SMART principles | KPI types; SMART criteria; mapping KPIs to SLA targets | KPI table design exercise for a simulated organisation |
| Availability and reliability calculations | Availability formula; MTBF; MTTR; "nines" table | Numerical calculation drills (minimum 5 worked examples per trainee) |
| Monitoring framework design | 8 monitoring layers; alerting levels; threshold tuning | Monitoring layer mapping exercise; alert threshold calibration case study |
| Incident trend analysis | Volume trend; category breakdown; repeat incidents; MTTR trend | 6-month incident data analysis exercise; trend commentary writing |
| Dashboard design | RAG status; management vs. operational dashboards; visualisation principles | Dashboard design exercise: sketch a one-page management dashboard |

### KP(4/4) — Management Reporting (12 hours)

| Session Focus | Key Teaching Points | Recommended Activities |
|--------------|--------------------|-----------------------|
| Types of IT reports and audiences | Monthly ops report; budget variance; risk register; annual review | Report type mapping exercise: match report to audience |
| IT operations status report writing | Structure; RAG coding; writing principles; executive summary | Rewrite exercise: convert technical text into management language |
| Budget variance analysis | Variance formula; ±10% commentary rule; full-year forecast | Budget variance calculation and commentary exercise |
| IT risk management and reporting | Risk identification; Likelihood × Impact matrix; treatment strategies; risk register | Risk rating exercise; risk register completion for a simulated scenario |
| Full report package assembly | Consistency, accuracy, cross-referencing between sections | Full report review exercise: identify errors and inconsistencies in a sample report |

## Penilaian Teori / Theory Assessment

Upon completion of all 4 KP/KT sessions, trainees will sit for the Knowledge Assessment (KA):

- **Code:** IT-020-5:2013-C01/KA
- **Duration:** 2 hours
- **Format:** Written examination — MCQ (30 marks), Short Answer (30 marks), Essay/Situational (40 marks)
- **Pass mark:** 60 / 100
- **Scope:** All four Work Activities — KP(1/4) to KP(4/4)
