**Note on hour allocation rationale:**
- KK(1/4) receives the highest hours because requirements analysis is an iterative process at Level 5 — trainees must conduct multiple rounds of stakeholder engagement, gap analysis, and requirements validation before producing a report of sufficient quality for management approval.
- KK(3/4) has the second highest allocation because implementation management encompasses the broadest scope of activities: communication planning, training design and delivery, compliance monitoring, non-conformance management, and change control — each requiring dedicated practice time.

## Kaedah Pengajaran / Teaching Method (4-Step)

### 1. PERSEDIAAN (Preparation)

| Langkah / Step | Aktiviti / Activity | Masa / Duration |
|----------------|---------------------|-----------------|
| 1.1 | Welcome trainees; take attendance | 5 min |
| 1.2 | State practical learning objectives for the session; link to theory covered in KP | 5 min |
| 1.3 | Distribute KK (Work Sheet), scenario brief, and all blank templates for the session | 10 min |
| 1.4 | Review key theory points relevant to today's practical task (brief, not a re-lecture) | 10 min |
| 1.5 | Verify that all trainees have the required tools and materials at their workstations | 5 min |
| 1.6 | Clarify any questions on the KK procedures before trainees begin | 5 min |

### 2. PENYAMPAIAN (Demonstration)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 2.1 | For KK(1/4): demonstrate how to read and analyse a scenario brief; show how to populate the first two rows of a Requirements Register using the scenario data |
| 2.2 | For KK(2/4): demonstrate how to complete the Document Control Header; show a correctly written Purpose section vs a poorly written one; demonstrate creating a basic swimlane in the diagramming tool |
| 2.3 | For KK(3/4): demonstrate how to complete a Communication Plan table (first two rows); show how to assess a compliance observation against an SOP clause and complete a Non-Conformance Record |
| 2.4 | For KK(4/4): demonstrate the KPI calculation for SOP compliance rate using sample numbers on the whiteboard; show how to structure an Executive Summary opening paragraph |
| 2.5 | Show common errors and their consequences (e.g. leaving "Responsible" field blank in Requirements Register; using personal names instead of job titles in RACI matrix) |
| 2.6 | Answer all questions before trainees begin independent work |

### 3. PENGGUNAAN (Practice)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 3.1 | Trainees work through the KK procedures independently at their workstations |
| 3.2 | Instructor circulates continuously: observe work process, check document quality, ask guiding questions to probe understanding |
| 3.3 | At the midpoint of the session, pause for a brief check-in: trainees share one challenge; instructor addresses common issues with the class |
| 3.4 | For KK(2/4): when trainees complete the SOP draft, conduct a structured peer review — pairs exchange drafts and complete the Review Comment Register for each other's document |
| 3.5 | For KK(3/4), Bahagian C (Change Control): trainees present their revised SOP procedure steps to a neighbour for feedback before finalising |

### 4. PENGESAHAN (Confirmation)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 4.1 | Trainees submit all completed outputs to the instructor |
| 4.2 | Instructor reviews outputs against the KK Assessment Checklist; mark each criterion |
| 4.3 | Provide individual verbal feedback to each trainee covering: strengths, specific improvements required, and one priority action for the next session |
| 4.4 | Brief class debrief: share three common errors observed across the group (without naming individuals) and the correct approach |
| 4.5 | Trainees organise and file all documents; clean workstations |
| 4.6 | Record session completion and individual trainee progress in the training record system |

## Keselamatan dan Etika / Safety and Ethics Requirements

- All scenario documents contain simulated organisational data — treat as SULIT (Confidential); do not share outside the training room
- Do not use real staff names, real system credentials, or real organisation data in any practical document
- All draft documents must be watermarked "DRAF / DRAFT — LATIHAN / TRAINING USE ONLY"
- Save all work to the instructor-designated shared drive at the end of each session; do not retain on personal devices or cloud accounts
- Conduct peer review (KK-02) professionally and constructively; feedback must be specific and evidence-based, not personal

## Penilaian Amali / Practical Assessment

Upon completion of all 4 KK sessions, trainees will sit for the Performance Assessment:
- **Kod / Code:** IT-020-5:2013-C06/PA
- **Format:** Integrated practical scenario over two sessions (8 hours total)
- **Tempoh / Duration:** Session 1 (4 hours) + Session 2 (4 hours)
- **Assessment domains:** Process (30%), Output (30%), Attitude (15%), Compliance (15%), Communication (10%)
- **Pass mark:** 60% (60 out of 100 marks)

## Catatan Pengajar / Instructor Notes

- Level 5 trainees are expected to produce management-quality documents. Hold the standard high: reject documents that use informal language, omit mandatory fields, or fail to use job titles (vs personal names) in RACI matrices and SOP steps. Return with feedback and require correction.
- Document control hygiene (version numbers, watermarks, bilingual headers) must be emphasised from Session 1 and enforced consistently. Do not accept a document without a correct Document Control Header.
- Peer review in KK(2/4) is a deliberate professional skill development activity, not simply error-checking. Instruct trainees to provide written comments in the Review Comment Register using professional language, referencing the specific SOP section and the applicable quality criterion.
- For trainees who progress faster than the session time allows, provide extension tasks: e.g. draft a second SOP section, add an emergency procedure annex, or calculate a second set of KPIs with different data.
- Keep all session scenario briefs and data sets different from the PA scenario — the PA must test independent competency, not recall of practised scenarios.
