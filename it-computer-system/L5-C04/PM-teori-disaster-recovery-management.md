## Kaedah Pengajaran / Teaching Method (4-Step)

### 1. PERSEDIAAN (Preparation)

| Langkah / Step | Aktiviti / Activity | Masa / Duration |
|----------------|---------------------|-----------------|
| 1.1 | Welcome trainees and take attendance | 5 min |
| 1.2 | State the learning objectives for the session | 5 min |
| 1.3 | Relate the topic to current industry context: highlight recent disaster events affecting Malaysian organisations (e.g. data centre floods, ransomware incidents) | 10 min |
| 1.4 | Provide overview of the Information Sheet (KP) content and how it links to the corresponding KT assignment | 5 min |

### 2. PENYAMPAIAN (Presentation)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 2.1 | Deliver theory content from the relevant KP using slides, diagrams, and real-world case studies |
| 2.2 | Explain key terms with bilingual definitions: Recovery Time Objective (RTO) / Objektif Masa Pemulihan; Recovery Point Objective (RPO) / Objektif Titik Pemulihan; Business Impact Analysis (BIA) / Analisis Impak Perniagaan |
| 2.3 | Present worked examples: demonstrate BIA table completion; calculate RTO/RPO for a sample organisation |
| 2.4 | Show network and system recovery diagrams: primary site → DR site failover; backup chain (full → incremental → restore) |
| 2.5 | Present ISO 22301:2019 framework overview; explain which clauses govern DR planning and testing |
| 2.6 | Walk through a real Malaysian DR incident (anonymised case study) — what failed, what was recovered, lessons learnt |
| 2.7 | Highlight regulatory requirements for Malaysian organisations: BNM RMiT, PDPA, CyberSecurity Malaysia incident reporting |
| 2.8 | Encourage questions; address misconceptions (e.g. "backup = DR") |

### 3. PENGGUNAAN (Application)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 3.1 | Distribute the corresponding KT (Assignment Sheet) for the session |
| 3.2 | Trainees complete the assignment individually; instructor circulates to observe and guide |
| 3.3 | For analytical sections (BIA, risk matrix), trainees may work in pairs for peer discussion before individual write-up |
| 3.4 | Discuss common errors: incorrect RTO > MTD; RPO values inconsistent with backup frequency; risk scores calculated as addition rather than multiplication |

### 4. PENGESAHAN (Confirmation)

| Langkah / Step | Aktiviti / Activity |
|----------------|---------------------|
| 4.1 | Review key learning points from the session using a structured recap |
| 4.2 | Conduct brief oral questioning: "What is the difference between RTO and RPO?", "Name two types of DR site and compare them" |
| 4.3 | Collect completed KT for marking and provide written feedback within 5 working days |
| 4.4 | Preview the next session topic; indicate which sections of the next KP to pre-read |
| 4.5 | Record attendance and session completion in the training register |

## Penilaian Teori / Theory Assessment

Upon completion of all 4 KP/KT sessions, trainees will sit for the Knowledge Assessment (KA):

- **Code:** IT-020-5:2013-C04/KA
- **Duration:** 2 hours
- **Format:** Written examination — Section A: MCQ (30 marks); Section B: Short Answer (30 marks); Section C: Essay (40 marks)
- **Pass mark:** 60% (60/100)
- **Coverage:** All 4 Work Activities of CoCU 4
- **Condition:** Closed book

## Nota Pengajar / Instructor Notes

- Level 5 trainees are expected to have prior knowledge of networking fundamentals, server administration, and basic IT security (from L3 and L4 CUs). Theory delivery should build on this foundation rather than re-teach basics.
- Emphasise the **management dimension** of DR at Level 5: trainees are preparing for roles as IT managers or senior technicians who must justify DR investment to management, not merely execute technical steps.
- Use **real Malaysian incidents** where possible: the 2021 Klang Valley flash floods affecting data centres; ransomware incidents reported in JPDP and BNM advisories.
- Reinforce the distinction between DR and general IT support: DR is about pre-planned, tested, and approved procedures for declared disasters — not ad-hoc troubleshooting.
