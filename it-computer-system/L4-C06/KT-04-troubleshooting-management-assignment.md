## Soalan / Questions

### Bahagian A: Soalan Pelbagai Pilihan / Multiple Choice (20 marks)

**A1.** In ITIL terminology, an "incident" is best defined as:

- (a) The root cause of a recurring fault
- (b) Any unplanned interruption or degradation of a service
- (c) A scheduled maintenance activity that went wrong
- (d) A formal complaint from a user

**A2.** A P1 (Critical) incident should have a target resolution time of:

- (a) 3 business days
- (b) 4 hours
- (c) As defined in the organisation's SLA — typically ≤ 2 hours
- (d) Whenever the technician is next available

**A3.** The Known Error Database (KEDB) is used to:

- (a) Store usernames and passwords for system access
- (b) Record problems with known root causes and workarounds to speed up future incident resolution
- (c) Track the performance appraisals of maintenance technicians
- (d) Archive completed work orders

**A4.** The "5 Whys" technique is a method for:

- (a) Listing the five most common types of hardware failures
- (b) Conducting a Root Cause Analysis by asking "why" repeatedly until the root cause is identified
- (c) Calculating the MTBF of a server
- (d) Prioritising work orders by urgency

**A5.** After a P1 incident is resolved, which communication should be sent to management?

- (a) A verbal apology from the maintenance manager
- (b) An incident report covering root cause, resolution, business impact, and lessons learned — within 24 hours
- (c) A request for additional budget only
- (d) No communication is required if the incident was resolved within the SLA target

### Bahagian B: Soalan Jawapan Pendek / Short Answer (30 marks)

**B1.** Distinguish between an Incident, a Problem, and a Known Error. Give ONE (1) example of each in a computer system maintenance context. (9 marks)

**B2.** List and briefly describe the SIX (6) steps of the structured troubleshooting methodology from KP(4/5). (12 marks)

**B3.** List the SEVEN (7) sections of a Root Cause Analysis (RCA) report. (7 marks)

**B4.** State TWO (2) scenarios that should trigger a problem investigation (as distinct from a single incident response). (2 marks)

---

### Bahagian C: Soalan Esei / Essay (30 marks)

**C1.** Read the following incident description and answer the questions:

**Incident:** At 14:30 on a Tuesday, the helpdesk receives calls from 35 users reporting that they cannot access network file shares. The file server (FS-01) is unreachable. Investigation reveals:
- FS-01 is powered on but the OS is unresponsive at the console
- The RAID array status light is amber — one drive has failed
- The RAID was configured as RAID 5 with three drives
- The maintenance log shows the last full PM for FS-01 was 14 months ago (overdue)
- A replacement drive is not in the spare parts inventory

(a) Log this incident: classify the priority, estimate the business impact, and identify the immediate escalation steps. (8 marks)

(b) Describe the workaround you would implement while the server is being restored. What information would you communicate to the 35 affected users? (6 marks)

(c) Conduct a 5 Whys RCA for this incident. Show each "why" and its answer, leading to the root cause. (8 marks)

(d) Propose TWO (2) corrective actions and TWO (2) preventive actions arising from the RCA. Assign each an owner role and a target completion date. (8 marks)
