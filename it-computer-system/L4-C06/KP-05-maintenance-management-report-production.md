## Objektif Pembelajaran / Learning Objectives

Upon completion of this Information Sheet, trainees shall be able to:

1. Compile, analyse, and interpret maintenance performance data from multiple sources
2. Produce a structured maintenance management report in a format suitable for management review
3. Calculate and present key performance indicators (KPIs) relevant to maintenance management
4. Formulate recommendations for maintenance strategy improvement based on report findings
5. Present the maintenance management report effectively to technical and non-technical audiences

---

## 1.0 Purpose of the Maintenance Management Report

The Maintenance Management Report (Laporan Pengurusan Penyelenggaraan) is a formal document prepared by the maintenance manager and submitted to the IT Manager and senior management on a periodic basis (typically monthly and annually). It serves as:

- **An accountability instrument:** Demonstrating that maintenance activities were carried out as planned
- **A performance measurement tool:** Showing how well the maintenance function is meeting its SLA and KPI targets
- **A decision-support document:** Providing management with the data needed to approve additional resources, budget adjustments, or strategic changes
- **A continuous improvement driver:** Identifying trends, recurring problems, and areas for improvement

A well-prepared maintenance report positions the IT department as a professional, data-driven function rather than a reactive support unit.

---

## 2.0 Data Sources for the Maintenance Report

| Data Source | Information Provided |
|-------------|----------------------|
| CMMS / ITSM system | Work order completion data, labour hours, response and resolution times |
| Asset register | Asset inventory, age, warranty status, maintenance history |
| Incident records | Incident counts, priorities, resolution times, SLA compliance |
| Spare parts inventory | Parts consumed, stock levels, procurement costs |
| Financial records | Maintenance expenditure vs budget |
| Monitoring system logs | Uptime data, performance alerts, threshold breaches |
| Contractor invoices and reports | Contractor work completed, cost, compliance with SOW |

The maintenance manager must ensure all data sources are accurate and up to date before compiling the report.

---

## 3.0 Key Performance Indicators (KPI) for Maintenance Management

| KPI | Definition | Target (Example) |
|-----|------------|------------------|
| System Availability (%) | Uptime / (Uptime + Downtime) × 100 | ≥ 99.5% for Tier 1 systems |
| PM Compliance Rate (%) | PM tasks completed on schedule / PM tasks scheduled × 100 | ≥ 95% |
| Mean Time To Respond (MTTR-Response) | Avg time from incident logged to technician on-site/remote | P1: ≤ 30 min |
| Mean Time To Repair (MTTR-Repair) | Avg time from incident logged to service restored | P1: ≤ 2 hrs |
| Repeat Incident Rate (%) | Incidents that are a recurrence of a previously resolved fault | ≤ 10% |
| First-Time Fix Rate (%) | Incidents resolved without escalation or repeat visit | ≥ 85% |
| Maintenance Cost per Asset (RM) | Total maintenance cost / Number of managed assets | Compare to prior period and benchmark |
| Open Work Order Ageing | Work orders open beyond target resolution time | Target: 0% of P1/P2 open beyond SLA |
| KEDB Resolution Rate (%) | Known errors resolved / Total known errors × 100 | ≥ 60% per quarter |
| Contractor SLA Compliance (%) | Contractor deliverables met on time / Total deliverables × 100 | ≥ 95% |

## 4.0 Structure of the Monthly Maintenance Management Report

| Section | Content |
|---------|---------|
| 1. Executive Summary | Key highlights, major incidents, SLA compliance status — maximum 1 page |
| 2. Maintenance Activity Summary | PM tasks completed vs scheduled; corrective maintenance count; contractor activities |
| 3. Incident Report | Incident count by priority; trend vs prior month; major incidents summary |
| 4. KPI Dashboard | All tracked KPIs vs targets; traffic-light (RAG) status |
| 5. System Availability Report | Uptime per Tier 1 system; downtime events and causes |
| 6. Spare Parts and Inventory | Parts consumed; current stock levels; items requiring replenishment |
| 7. Budget Utilisation | Actual spend vs budget; variance explanation |
| 8. Open Items | Outstanding work orders; known errors; deferred maintenance |
| 9. Recommendations | Management actions required; proposed changes to plan or resources |
| 10. Appendices | Detailed work order logs; incident details; contractor performance records |

---

## 5.0 KPI Dashboard Design

The KPI dashboard is typically presented as a single-page summary using a RAG (Red-Amber-Green / Merah-Amber-Hijau) traffic-light system:

| Colour | Status | Meaning |
|--------|--------|---------|
| Green (Hijau) | On target | KPI is meeting or exceeding the target |
| Amber (Kuning) | At risk | KPI is within 5% of the target threshold — action required |
| Red (Merah) | Off target | KPI is below the target threshold — immediate action required |

**Example KPI Dashboard Extract:**

| KPI | Target | Actual | Status |
|-----|--------|--------|--------|
| System Availability (Tier 1) | ≥ 99.5% | 99.7% | Green |
| PM Compliance Rate | ≥ 95% | 91% | Amber |
| MTTR — P1 Resolution | ≤ 2 hrs | 3.5 hrs | Red |
| Repeat Incident Rate | ≤ 10% | 8% | Green |
| Maintenance Cost vs Budget | ≤ 100% | 94% | Green |

## 6.0 Annual Maintenance Management Report

In addition to monthly reports, the maintenance manager prepares an Annual Maintenance Management Report at the end of each year. This report covers:

1. **Full-year KPI performance** against annual targets
2. **Asset lifecycle summary:** Assets approaching end-of-life, replacement recommendations
3. **Major incident review:** Summary of all P1/P2 incidents with RCA outcomes and corrective action status
4. **Maintenance programme effectiveness:** Achieved vs planned PM; impact on availability and cost
5. **Budget analysis:** Full-year actual vs budget; cost per asset trend
6. **Contractor performance review:** Annual assessment of all contracted maintenance services
7. **Recommendations for next year:** Proposed changes to maintenance strategy, resources, budget, and plan

The annual report is presented to the IT steering committee or management and forms the basis for next year's maintenance plan and budget submission.

---

## 7.0 Report Writing Standards

The maintenance management report must conform to organisational and government documentation standards:

| Standard | Requirement |
|----------|-------------|
| Language | Bahasa Malaysia as the primary language for government organisations; bilingual where required |
| Format | Official letterhead; section headings; page numbering; version control |
| Data accuracy | All figures verified against source data before inclusion |
| Confidentiality | Mark report with appropriate classification (e.g. SULIT / TERHAD) if it contains sensitive system information |
| Approval | Signed by the maintenance manager; endorsed by the IT Manager before distribution |
| Distribution | Controlled distribution list; electronic copy filed in the document management system |

---

## 8.0 Presenting the Report to Management

When presenting the maintenance management report verbally:

1. **Open with the executive summary** — focus on what management needs to decide or act on
2. **Highlight KPIs in Red/Amber** — explain the cause and the action being taken
3. **Quantify the business impact** — express technical performance in terms management understands (e.g. "system downtime cost the organisation an estimated 8 person-hours of lost productivity")
4. **Present recommendations clearly** — state the recommendation, the expected benefit, and the resource required
5. **Invite questions and record decisions** — document any management instructions arising from the presentation
