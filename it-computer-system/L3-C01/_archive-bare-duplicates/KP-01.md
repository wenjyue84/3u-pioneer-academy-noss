## Tajuk / Title: Job Request Analysis and Requirements Interpretation

---

## Objektif Pembelajaran / Learning Objectives

Upon completion of this Information Sheet, trainees shall be able to:

1. Explain the purpose and structure of a job request and change order in computer system set-up
2. Identify and interpret hardware, software, and configuration requirements from a job request
3. Describe the differences between a standard desktop build and a custom workstation build
4. List the key decision criteria for analysing a job request

---

## 1.0 Introduction to Job Request Analysis

A job request (also called a work order or service request) is the formal document that initiates a computer system set-up task. It is issued by the help desk, supervisor, or client and contains the specifications that the technician must follow. Accurate analysis of the job request is the foundation of a successful set-up -- errors at this stage lead to wrong parts, incompatible hardware, or unmet user requirements.

A change order is a modification to an existing job request. It may add requirements (e.g. additional RAM), change specifications (e.g. different OS version), or cancel parts of the original request. Change orders must be documented and approved before work proceeds.

---

## 2.0 Job Request Structure

A typical job request contains the following information:

| Field | Description |
|-------|-------------|
| Job request number | Unique identifier for tracking |
| Date issued | Date the request was created |
| Requested by | Name and department of the person or entity requesting the set-up |
| Priority | Urgency level (e.g. Normal, High, Critical) |
| Description | Summary of what is needed (e.g. "New desktop PC for Finance Dept") |
| Hardware specifications | CPU model, RAM capacity, storage type and size, peripherals required |
| Software requirements | Operating system, applications, licence keys |
| Network requirements | IP address (static or DHCP), domain membership, VLAN |
| Delivery date | When the set-up must be completed |
| Approver | Person authorising the request and budget |

## 3.0 Standard Build vs Custom Build

The scope and complexity of the set-up depend on whether the job request specifies a standard or custom build:

| Aspect | Desktop / Standard Build | Workstation / Custom Build |
|--------|--------------------------|----------------------------|
| Scope/trigger | Standard office build: single PC, standard OS and applications, one user. Job request specifies model, OS version, and software list. | Custom or workstation build: high-end CPU/GPU, multiple drives, special software or dual-boot. Change request may specify hardware list, RAID, and software versions. |
| Tools and parts | Standard toolkit: screwdrivers, anti-static strap, USB installer. Parts from standard inventory; one system unit, monitor, keyboard, mouse. | Extended toolkit: multimeter, cable tester, thermal paste. Parts ordered per spec; multiple drives, expansion cards, or special peripherals. |
| Report | Set-up report with serial numbers, OS version, and user sign-off. | Set-up report with full hardware list, RAID config, software versions, and acceptance test result. |

## 4.0 Requirements Extraction Process

When analysing a job request, the technician should follow a systematic approach:

1. **Read the entire job request** before taking any action. Note any fields that are incomplete or unclear.
2. **Verify hardware specifications** against available inventory. Check CPU socket compatibility with the motherboard, RAM type and speed, storage interface (SATA, M.2 PCIe), and PSU wattage.
3. **Verify software requirements.** Confirm the OS version, licence availability, required applications, and any special configuration (e.g. dual-boot, domain join).
4. **Check for incompatibilities or conflicts.** A custom build may require components that are not in standard inventory or that need special ordering.
5. **Identify missing information.** If the job request does not specify a detail (e.g. monitor size, keyboard layout), clarify with the requestor before proceeding.
6. **Document the analysis.** Record verified requirements, identified gaps, and the planned set-up sequence for team review.

---

## 5.0 Decision Criteria

The following criteria guide the technician's decisions during job request analysis:

- **Budget:** Does the specified hardware fit within the approved budget?
- **Compatibility:** Are all specified components compatible with each other (socket, form factor, interface)?
- **Availability:** Are parts in stock, or do they need to be ordered?
- **Timeline:** Can the set-up be completed by the delivery date given current workload?
- **Policy compliance:** Does the specification conform to organisational IT standards and policies?

---

## 6.0 Common Errors in Job Request Analysis

| Error | Consequence | Prevention |
|-------|-------------|------------|
| Not reading the full request | Missing requirements discovered during set-up | Read the entire document first; use a checklist |
| Assuming default specifications | Wrong OS version or missing applications | Verify every field; clarify unknowns with the requestor |
| Ignoring compatibility | Parts that do not fit or work together | Cross-check CPU socket, RAM type, storage interface |
| Not documenting changes | Untracked deviations from the original request | Record all changes on a change order form |
