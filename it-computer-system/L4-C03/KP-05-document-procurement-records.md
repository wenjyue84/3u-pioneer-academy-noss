## Objektif Pembelajaran / Learning Objectives

Upon completion of this Information Sheet, trainees shall be able to:

1. Compile a complete procurement file containing all mandatory documents from initiation to closure
2. Apply document retention and records management requirements for ICT procurement
3. Maintain a procurement register and asset register in a format suitable for audit
4. Prepare a procurement closure report summarising outcomes against objectives

---

## 1.0 Importance of Procurement Documentation

Procurement records serve multiple purposes:
- **Audit trail** — enables internal and external auditors to verify compliance with regulations
- **Dispute resolution** — provides evidence in the event of vendor disputes or warranty claims
- **Institutional knowledge** — enables future procurement exercises to reference previous specifications and prices
- **Asset management** — links purchased equipment to financial records and physical inventory
- **Governance** — demonstrates that procurement was conducted fairly, transparently, and within authority limits

Poor documentation is one of the most common findings in government ICT audit reports. Missing documents — even when the procurement itself was conducted correctly — can result in negative audit findings.

---

## 2.0 The Procurement File

Every procurement exercise must be supported by a complete procurement file (fail perolehan). The file is organised chronologically and contains:

| Stage | Document | Purpose |
|-------|----------|---------|
| Initiation | Needs Assessment Report | Business justification and requirements |
| Initiation | Budget approval letter / memo | Confirmation of approved funding |
| Specification | Technical Specification Document | What was procured |
| Solicitation | RFQ cover letters / Tender advertisement | Record of how vendors were invited |
| Solicitation | All quotations / tender submissions received | Evidence of market competition |
| Evaluation | Quotation Opening Record / Tender Opening Minutes | Documents when and who opened submissions |
| Evaluation | Compliance Matrix | Technical evaluation results |
| Evaluation | Price Comparison Table | Commercial evaluation results |
| Evaluation | Evaluation Report and Recommendation | Summary and recommendation for award |
| Award | Award Approval memo / Tender Board minutes | Authorised approval of award decision |
| Award | Letter of Award (LOA) / Acceptance of Quotation | Formal notification to successful vendor |
| Delivery | Purchase Order (PO) | Binding commitment to purchase |
| Delivery | Goods Received Note (GRN) | Acknowledgement of physical delivery |
| Delivery | Functional Acceptance Test report | Proof of technical acceptance |
| Delivery | Acceptance Certificate | Formal acceptance triggering payment |
| Payment | Invoice from vendor | Payment claim |
| Payment | Payment Voucher | Internal payment processing record |
| Closure | Warranty registration records | Evidence of warranty activation |
| Closure | Asset registration records | Entry in ICT asset register |
| Closure | Procurement Closure Report | Summary of outcomes vs objectives |

---

## 3.0 Document Retention Requirements

Procurement documents must be retained for the legally required period. For Malaysian government agencies:

| Document Category | Minimum Retention Period |
|------------------|-------------------------|
| Tender documents and evaluations | 7 years from contract completion |
| Purchase orders and GRNs | 7 years |
| Payment records | 7 years |
| Asset register | Life of asset + 7 years |
| Audit correspondence | 7 years |

For private organisations, retention follows the **Companies Act 2016** requirements and internal records management policy. Typical minimum is 7 years for financial-related records.

### 3.1 Physical vs Digital Records

| Format | Considerations |
|--------|---------------|
| Physical (hard copy) | Required for original signatures; store in fireproof cabinet; access controlled |
| Digital (scanned / electronic) | Acceptable for reference copies; must be legible; backup required |
| Electronic Document Management System (EDMS) | Preferred for large organisations; enables search, access control, and retention scheduling |

## 4.0 Procurement Register

The Procurement Register (Daftar Perolehan) is a master log of all procurement exercises:

| Field | Description |
|-------|-------------|
| Reference number | Unique procurement reference (e.g. PRO-2026-001) |
| Description | Brief description of goods/services |
| Procurement method | Direct purchase / quotation / limited tender / open tender |
| Estimated value (RM) | Budget allocation |
| Actual value (RM) | Final award value |
| Vendor awarded | Name and MOF registration number |
| Award date | Date of formal award |
| Delivery date (required) | Contractual delivery deadline |
| Delivery date (actual) | Date goods received and accepted |
| Status | Open / Delivered / Closed / Disputed |
| File reference | Reference to procurement file location |

The Procurement Register is reviewed quarterly by the Procurement Committee and annually during audit.

---

## 5.0 ICT Asset Register

Upon completion of procurement and delivery, each asset must be entered in the ICT Asset Register:

| Field | Entry |
|-------|-------|
| Asset tag | Unique physical label (barcode/QR) affixed to equipment |
| Asset description | Make, model, specification summary |
| Serial number | Manufacturer serial number |
| Procurement reference | PRO number linking to procurement file |
| Purchase date | Date of acceptance certificate |
| Purchase cost (RM) | Unit price as per PO |
| Warranty expiry | Calculated from acceptance date |
| Location | Building, floor, room, workstation |
| Assigned user | Staff name and ID |
| ICT category | Hardware / Network / Peripherals |
| Disposal date | Completed when asset is disposed |
| Disposal method | Written-off / transferred / auctioned / recycled |

## 6.0 Procurement Closure Report

At the end of each procurement exercise, a **Procurement Closure Report** summarises:

### 6.1 Closure Report Contents

| Section | Content |
|---------|---------|
| Executive Summary | One-page summary of procurement outcome |
| Objectives vs Outcomes | Were original requirements met? Any deviations? |
| Financial Summary | Budget vs actual cost; savings or overspend |
| Timeline Summary | Planned vs actual dates for each milestone |
| Vendor Performance | Delivery timeliness, quality of goods, responsiveness |
| Issues Encountered | Discrepancies, delays, specification deviations |
| Lessons Learned | Recommendations for future procurement exercises |
| Attachments | Key documents list (or reference to procurement file) |

### 6.2 Lessons Learned

Recording lessons learned from each procurement improves future exercises:

| Area | Example Lesson |
|------|---------------|
| Specification | "Specify minimum NVMe read speed numerically — two vendors offered SATA SSDs because speed was not stated" |
| Timeline | "Allow 4 weeks from PO to delivery for imported network equipment; 2 weeks was insufficient" |
| Vendor management | "Vendor B required two chaser emails to submit warranty registration — include warranty registration deadline in PO" |

---

## 7.0 Common Errors in Procurement Documentation

| Error | Consequence | Prevention |
|-------|-------------|------------|
| Missing quotation opening record | Cannot prove submissions were opened fairly and on the same date | Always record opening date, time, attendees, and amounts on official form |
| Incomplete procurement file | Audit finding; cannot reconstruct procurement history | Use a file checklist; verify completeness before closing the file |
| Asset not registered after delivery | Equipment untraceable; cannot support warranty claims | Asset registration must be completed within 5 working days of acceptance |
| Payment processed before acceptance certificate signed | Vendor paid for goods not yet verified | Finance must require acceptance certificate before processing payment |
| Procurement records not retained | Cannot comply with audit requirements | Apply document retention schedule; digitise and back up physical records |
