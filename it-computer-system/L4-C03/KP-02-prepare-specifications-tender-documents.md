## Objektif Pembelajaran / Learning Objectives

Upon completion of this Information Sheet, trainees shall be able to:

1. Write clear, measurable, and technology-neutral technical specifications for ICT hardware, software, and network equipment
2. Prepare a complete Request for Quotation (RFQ / Sebut Harga) and Invitation to Tender (ITT / Jemputan Tender) document set
3. Define evaluation criteria and scoring methodology in tender documents
4. Apply Malaysian government procurement document standards and formatting requirements

---

## 1.0 The Importance of Clear Specifications

Technical specifications (spesifikasi teknikal) form the foundation of any procurement exercise. Poorly written specifications cause:
- Vendor misunderstanding leading to non-compliant bids
- Inability to compare quotations fairly
- Legal disputes if a supplied product does not meet unstated expectations
- Audit findings of non-compliance with procurement regulations

Good specifications are:
- **Measurable** — use specific quantities, speeds, capacities, and standards
- **Technology-neutral** (where possible) — describe what is needed, not a brand name, to allow fair competition
- **Complete** — cover hardware, software, services, warranty, and delivery
- **Compliant** — align with government or organisational standards and green procurement requirements

---

## 2.0 Structure of a Technical Specification Document

A technical specification document for ICT procurement contains the following sections:

| Section | Content |
|---------|---------|
| 1. Introduction | Purpose of procurement, background, scope |
| 2. Quantity and item list | Number of units and item descriptions |
| 3. Minimum technical requirements | Detailed specifications per item |
| 4. Compliance standards | Required certifications (Energy Star, CE, SIRIM, FCC) |
| 5. Warranty and support requirements | Minimum warranty period, on-site vs carry-in, SLA |
| 6. Delivery requirements | Delivery address, schedule, packaging |
| 7. Installation and commissioning | Whether included, scope of work |
| 8. Training | Number of users, duration, format |
| 9. Documentation | Manuals, licences, compliance certificates |

## 3.0 Writing Technical Specifications for ICT Equipment

### 3.1 Desktop / Workstation Specifications

| Parameter | Example Specification |
|-----------|----------------------|
| Processor | Intel Core i7 13th Gen or equivalent; minimum 3.4 GHz base clock; 12 cores |
| Memory | Minimum 16 GB DDR5-4800 MHz; 2 DIMM slots; upgradeable to 64 GB |
| Storage | Minimum 512 GB NVMe PCIe Gen 4 SSD; sequential read ≥ 3,000 MB/s |
| Display | 24-inch IPS, Full HD (1920×1080), 60 Hz, anti-glare |
| Operating system | Windows 11 Pro 64-bit, pre-installed, licensed, COA attached |
| Ports | Minimum: 4× USB 3.2, 1× USB-C, HDMI 2.0, RJ-45 Gigabit Ethernet |
| Warranty | Minimum 3 years on-site next-business-day |
| Energy | Energy Star 8.0 certified |

### 3.2 Network Switch Specifications

| Parameter | Example Specification |
|-----------|----------------------|
| Port count | Minimum 24× 10/100/1000 Mbps RJ-45 ports |
| Uplink | 2× SFP+ (10 Gbps) uplink ports |
| Switching capacity | ≥ 56 Gbps |
| Management | Web GUI, CLI (SSH/Telnet), SNMP v3 |
| PoE | PoE+ (802.3at) on all ports; total PoE budget ≥ 370W |
| VLAN | IEEE 802.1Q VLAN support; minimum 256 VLANs |
| Warranty | Lifetime hardware warranty with next-business-day advance replacement |

### 3.3 Software Licensing Specifications

| Parameter | Requirement |
|-----------|------------|
| Licence type | Named user or device licence (specify) |
| Volume | Number of seats required |
| Version | Minimum version number or release year |
| Software Assurance | Whether upgrade rights are required |
| Delivery | Electronic licence key or physical media (specify) |
| Proof of licence | Certificate of Authenticity (COA) or vendor licence agreement |

## 4.0 Request for Quotation (RFQ / Sebut Harga) Document

An RFQ is used for purchases in the quotation threshold (typically RM50,001–RM500,000). The RFQ package includes:

| Document | Purpose |
|----------|---------|
| Cover letter / invitation | Formal invitation to supplier to submit quotation |
| Technical specification | Detailed requirements (as above) |
| Quotation submission form | Template for supplier to fill in prices |
| Terms and conditions | Payment terms, delivery, warranty obligations |
| Compliance checklist | Supplier to declare compliance with each specification |
| Closing date and time | Deadline for submission |

### RFQ Key Requirements:
- Minimum **3 quotations** must be obtained from different suppliers
- All quotations must be in writing (fax, email, or sealed envelope as per policy)
- Quotations must be opened on the same date for fairness
- A quotation evaluation form must document the comparison

---

## 5.0 Invitation to Tender (ITT / Jemputan Tender) Document

For limited or open tender, the document set is more formal and extensive:

| Document | Purpose |
|----------|---------|
| Instruction to tenderers | Rules for submitting, format requirements, evaluation method |
| Technical specification | Detailed technical requirements |
| Bill of Quantities (BQ) | Itemised list with quantities; suppliers price each line item |
| Draft contract / conditions | Legal terms, SLA, liquidated damages, payment milestones |
| Tender submission form | Formal cover sheet with tenderer's declaration |
| Technical compliance schedule | Column-by-column response to every specification |
| Financial proposal | Lump sum or itemised pricing |

### 5.1 Tender Evaluation Methodology

Tenders are evaluated using a defined scoring matrix. A common approach for ICT procurement:

| Criterion | Weightage |
|-----------|-----------|
| Technical compliance (meets specifications) | 60% |
| Price | 30% |
| Vendor experience and support capability | 10% |

Each criterion is scored and multiplied by its weightage. The highest total score (not necessarily lowest price) is recommended for award.

---

## 6.0 Technology-Neutral Specification Principles

To ensure fair competition and avoid claims of specification-writing to favour a specific brand:

- Specify **performance parameters** (e.g. "≥ 3,000 MB/s read speed") rather than brand/model
- Where a standard must be referenced (e.g. Wi-Fi 6E), cite the **IEEE standard** (IEEE 802.11ax) rather than a proprietary name
- If only one product meets the requirement due to genuine technical necessity, document the justification (sole source justification / justifikasi pembekal tunggal)
- For government procurement, the Auditor General's findings frequently cite brand-specific specifications as a non-compliance risk

---

## 7.0 Common Errors in Specification and Document Preparation

| Error | Consequence | Prevention |
|-------|-------------|------------|
| Brand-specific specifications | Legal challenge; audit finding | Use performance-based, technology-neutral language |
| Incomplete compliance checklist | Cannot verify supplier compliance | Include a column-by-column response schedule |
| Missing warranty terms | Disputes on warranty coverage | State warranty period, type (on-site/carry-in), and response SLA |
| Incorrect tender threshold applied | Wrong procurement method used | Verify current AP/Pekeliling threshold before selecting method |
| No closing date stated | Submissions arrive at different times; unfair comparison | Always state a firm closing date and time |
